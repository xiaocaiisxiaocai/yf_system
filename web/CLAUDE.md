# CLAUDE.md (web)

Frontend-specific guidance; loads when working under `web/`. Repo-wide rules, the OpenAPI typed-contract flow and test policy are in the root `CLAUDE.md`.

## Commands

Run from `web/`. Requires Node 22.13+/24+.

```powershell
npm ci
npm run dev      # vite dev server on 127.0.0.1:5173, proxies /api (incl. WebSocket) -> 127.0.0.1:8080
npm run build    # tsc -b && vite build (predev/prebuild also (re)build the Excel/PPTX/Word preview bundles)
npm run lint     # oxlint --deny-warnings (any warning fails)
npm test         # vitest run (jsdom) over src/test/**/*.test.{ts,tsx}; pretest rebuilds the preview bundles
npx vitest run src/test/migrated/previews/pdf-preview.test.tsx   # single test file
npm run test:precompression   # node --test for the postbuild precompression script
```

`npm run dev`/`build` trigger `predev`/`prebuild` hooks that regenerate `.excel-preview-build/`, `.pptx-preview-build/`, `.docx-preview-build/` and `generated/*-viewer.html` — don't hand-edit those. `postbuild` precompresses `dist` assets (`scripts/precompress-assets.mjs`). `generated/` is imported by source (`?raw`), so a bare `tsc -b` fails until the preview build has run once. Unit tests live in `src/test/` (Vitest; `src/test/migrated/` holds cases ported from the old `node --test` suite, mapped in `src/test/migration/`). `test/browser-*.acceptance.txt` are stale historical snippets, not tests — port any scenario you need into `server_dotnet/scripts/browser/*.cjs`.

The dev proxy points at port 8080 (`server_dotnet`). The backend README runs the dev server as `npm run dev -- --host 127.0.0.1 --port 5180 --strictPort` to match `WebBaseUrl=http://127.0.0.1:5180` in the local config (CORS and the WebSocket origin allow-list both derive from `WebBaseUrl`). Never run two backends against the same business DB and storage.

## Architecture

- `src/api/client.ts` — the HTTP client (axios) talking to `/api/v1`; `src/api/types.ts` builds on `src/api/generated/api-types.ts`, generated from the backend OpenAPI contract (see Testing philosophy).
- Auth refresh: `client.ts` single-flights token refresh within a tab and serializes refresh-cookie rotation across tabs with Web Locks (`navigator.locks`), falling back to a localStorage lease on plain-HTTP intranet origins — two tabs rotating the same cookie would trip the backend's replay revocation. Each realm has its own lock names (OEM portal: `src/oem/api/portalAuthLock.ts`). `src/store/authStorageSync.ts` applies other tabs' `yf-auth` changes (logout / reload / new permissions). 409/40903 is detected with `src/api/versionConflict.ts`.
- Refresh outcome is `ok`, `rejected` or `unavailable`; only `rejected` logs out the user. `UploadNavigationGuard` and `uploadLeave.ts` ask for confirmation when navigating within the site during an active upload. OEM downloads use an iframe with an explicit path allowlist. After a 403, permission/profile refresh runs in the background.
- Realtime: `src/services/projectRealtime.ts` owns the SignalR connection; `src/store/collaboration.ts` (zustand) turns push signals into per-project `messageRevisions`/`receiptRevisions`/`activityRevisions` and a `reconnectRevision` counter. Components feed those counters into `src/hooks/useCoalescedRefresh.ts` (300 ms window; a signal during an in-flight request causes exactly one refetch after it) and refetch over REST; `useDisconnectedPoll` polls only while the connection is down.
- OEM UI lives in `src/oem/` (lazy-loaded from `App.tsx`): `/oem` reuses the internal collaboration session, `/oem-portal` is the vendor portal with its own isolated session.
- System mail UI (`src/pages/system/SysConfig.tsx` and `components/MailSettingsPanel.tsx`) has separate `SMTP 配置` and `邮件提醒规则` tabs. The SMTP tab is a bounded two-column workspace: connection settings/direct one-shot test on the left, queue/recent audit-backed mail records on the right; overflow stays inside the card at shorter heights. The rules tab switches between Robot and ODM/OEM policy panels. Preserve each tab's unsaved draft independently and do not make an SMTP test eligible while SMTP fields are dirty. The test endpoint sends immediately once, does not enqueue or retry, and its result is followed by a best-effort log/status refresh.
- Robot and ODM/OEM vendor directory pages own their XLSX actions. Vendor masters, shared login accounts and contacts are separate imports/exports; account forms/sheets have no person's name/email, while contacts are one name/email row each and a vendor may have many. OEM company rows expose `账号管理` and `联络人` drawers, and the top-level directory toolbar imports/exports companies, accounts and contacts so existing vendors can receive either child record type. Do not restore OEM primary-contact or telephone fields.
- Server state for Dashboard, user admin, messages and read receipts uses TanStack Query 5 (`src/api/queryClient.ts`); query keys include account, session generation and permission scope, and logout/permission changes cancel requests and clear the cache. Writes don't auto-retry.
- Unsupported formats are refused when files are picked or dropped (`utils/uploadExtensions.ts`, whitelist from `GET /uploads/allowed-extensions` for Robot and `GET /oem/upload-rules` for ODM/OEMA): nothing is queued, so no draft or upload session is created. An unknown whitelist never blocks; the server still validates on init.
- Uploads (`src/api/uploads.ts`): per-chunk SHA-256 (`X-Chunk-SHA256` header) and whole-file MD5 are computed in Web Workers (`*.worker.ts`); the resume fingerprint is a quick name/size/mtime/head/tail hash, not an integrity check. Protocol details: `docs/开发阶段架构调整-2026-09-23.md`.
- Previews: PDF uses local PDF.js 6.3.289 (`PdfPreview.tsx`/`pdfEngine.ts`), page-by-page, assets emitted by the `pdfAssets()` Vite plugin (`pdf-assets.ts`) into `dist/pdfjs/<version>/`. Excel/PPTX run in a sandboxed iframe: `scripts/build-{excel,pptx}-preview.mjs` bundle `web/vendor/vue-office-{excel,pptx}/viewer.js` (with npm `pptx-preview`/`exceljs`/`xlsx`) as an IIFE and inline it into `generated/{excel,pptx}-viewer.html`, which `ExcelPreview.tsx`/`PptxPreview.tsx` import `?raw`. `xlsx` comes from the SheetJS CDN tarball, not the npm registry.
- Word (`.docx`) runs the same way: `scripts/build-docx-preview.mjs` bundles `web/vendor/vue-office-docx/viewer.js` (the supplied vue-office wrapper + npm `docx-preview` 0.3.7) into `generated/docx-viewer.html` for `DocxPreview.tsx`. Legacy `.doc`/`.ppt` are download-only.
- `ExcelPreview`/`PptxPreview`/`DocxPreview`/`PdfPreview` read `/files/{id}/content` by default and accept a `loadContent(signal)` loader for other sources; the ODM/OEMA preview (`src/oem/components/OemFilePreview.tsx`, formats in `oemPreview.ts`) reuses them through `/oem/files/{id}/content`. The Robot file table (`FileTable.tsx`) offers the same formats; its backend allow-list is `FileService.IsPreviewable`.
- CSP: `web/csp.ts` (Vite plugin, build only) injects a `<meta>` Content-Security-Policy into `dist/index.html` — no `unsafe-eval`/general `unsafe-inline` script. The Excel/PPTX/Word srcdoc iframes inherit it, so each generated viewer must keep **exactly one** inline script, allowed by SHA-256 hash (the build fails otherwise). Browser tests' `waitForFunction` is patched in `scripts/browser/ui-lib.cjs` to poll via `page.evaluate`, because Playwright's native one needs eval.
- Arco styles: `main.tsx` imports `src/styles/arco-components.ts` (generated by `node scripts/generate-arco-styles.mjs`), not the full `dist/css/arco.css`. It lists only the stylesheets the imported components need, in full-bundle order (loading `css.js` per component would reorder the cascade and shift layouts). After importing a new Arco component, rerun the generator — `src/test/migrated/core/style-artifacts.test.ts` fails while it is stale.
- Every data table has resizable columns whose widths persist in the browser per table and user (`yf:table-columns:<tableId>:<userId>` in localStorage). Pages with a column picker use `useAdjustableColumns` with explicit `ColumnLayoutSpec`s; every other table uses `components/ResizableTable.tsx` (a drop-in for Arco `Table` taking a site-unique `tableId`, optional `growKey` for the column that takes spare width). Its specs come from each column's written `width` (120 when unset), and a page's numeric `scroll.x` stays the minimum table width. Use one of the two for any new table instead of a bare `Table`. `src/test/uniformLayout.test.ts` fails on a bare `Table` (or a hand-written `Sider`).
- Second-level navigation in every section (collaboration `AdminLayout`, ODM/OEMA, outsourcing and vendor portal via `SectionShell`) uses `layouts/NavSider.tsx` (desktop, collapsible, one shared `yf:sider-collapsed` preference) and its `NavMenu` (mobile drawer).
- Collaboration page access has one source: `src/layouts/navigation.ts` (`COLLABORATION_PAGES`). Sidebar menus, the business rail, the `/` landing page (`pages/Home.tsx`) and the route guards in `App.tsx` (`pageGuard(code)`, plus `canManageLeaders` for the org page) all read it; register a new collaboration page there instead of writing its menu/permission check again. `src/test/module-navigation.test.tsx` checks that menu visibility and the guard agree.
- Table action columns use `actionSlots(slots, variant)` (`src/components/ActionSlots.tsx`): every slot has a fixed width (`--action-slot-width`, widened per variant in `index.css`) and a hidden action keeps its empty slot, so the same action lines up across rows. Keep the slot order stable when adding an action.
- Password inputs and account-import previews use the shared `src/utils/password.ts` / `password-policy.json` contract: 5–20 Unicode characters plus weak/simple-pattern rejection. Do not reintroduce an eight-character frontend-only minimum.
- `package.json` `overrides` pin `exceljs`' Node-only dependency chain (`uuid`, `glob`, `minimatch`) for `npm audit`; the viewer imports the prebuilt `exceljs/dist/exceljs`, so that chain never ships (see `yfDependencyPolicy`).
- Preview watermark (employee no. + name + open time) is `WatermarkedPreview` in `src/components/FileTable.tsx`, styled by `.preview-watermark` in `src/index.css`.
