# 项目元数据与字典契约

schema v6 在不改变旧项目语义的前提下扩展项目资料。旧记录的新增外键和日期均为 `null`，工令号为 `[]`。

新增与编辑保存时，工令号（至少一项）、机型、Robot 厂商、Robot 型号、负责人、课别、优先级、预计完成日期均为必填。课别由负责人带入，负责人未关联课别时拒绝保存。历史空值不自动填充，但再次编辑保存必须补齐；下文 nullable 描述仅用于历史记录读取和数据库结构，不表示写入可省略。

## 页面入口

项目协作的列表、新建、编辑和详情同步展示工令号、机型、Robot 厂商、Robot 型号、负责人、课别、优先级及预计完成日期。工令号输入后按回车添加，可填写多个；Robot 型号随厂商联动；课别为只读。列表保留所有列，在表格内部横向滚动，窄屏取消固定列以避免遮挡。

侧栏“数据字典”（`/system/dictionaries`）提供 Robot 厂商、Robot 型号和优先级维护，使用系统参数的 `config:manage` 权限。支持新增、编辑、排序、停用和删除；已引用型号的所属厂商不可变更。

## 项目字段

`POST /api/v1/projects` 与 `PUT /api/v1/projects/{id}` 在原 `name`、`description`、`supplierId` 之外接收：

- `workOrderNos: string[]`：至少 1 项、最多 50 项；空白项忽略，逐项 trim，按不区分大小写去重，每项最多 128 个字符。
- `machineModel: string`：trim 后 1–128 个字符。
- `robotVendorId`、`robotModelId`、`responsibleUserId`、`priorityId`: 必填的有效正整数 ID。
- `expectedCompletionDate: string`：必填，严格使用 `yyyy-MM-dd`。

项目列表、详情以及创建、修改、状态流转响应增加：

`workOrderNos`、`machineModel`、`robotVendorId/Code/Name`、`robotModelId/Code/Name`、`responsibleUserId/EmployeeNo/Name`、`sectionId/Name`、`priorityId/Code/Name`、`expectedCompletionDate`。

`sectionId` 不接受客户端输入。后端只在所选负责人的直属组织节点 `kind='SECTION'` 时保存该节点；直属组织是 `DEPARTMENT`、`DIVISION` 或为空时拒绝保存，提示先设置负责人所属课别，不会猜测下级课别。

负责人必须是启用的内部用户，且其有效角色拥有 `project:list`。内部项目可见范围只由当前负责人或 `project:view_all` 决定，仍要求 `project:list`；创建人和旧 `project_members` 记录不再提供访问权。更换负责人后，旧负责人若无全局查看权限便失去访问权。项目详情不再提供成员页签或成员维护接口。

普通内部通知及已读参与者仅包括当前负责人，全局查看者不会自动加入回执或普通邮件收件人；验收者仍需验收权限和项目可见权限。供应商的既有可见范围保留。历史未设置负责人的项目仅由具全局查看权限的内部人员查看并补齐。遗留成员记录仅保留用于历史与清理，不再参与授权。

## 字典接口

字典类型固定为 `ROBOT_VENDOR`、`ROBOT_MODEL`、`PRIORITY`。

- `GET /api/v1/project-dictionaries?type=...&enabledOnly=true|false&parentId=...` 返回数组。管理页省略 `enabledOnly` 以查看全部；项目表单使用 `enabledOnly=true`。`parentId` 仅用于 `ROBOT_MODEL`。
- `POST /api/v1/project-dictionaries` 创建。
- `PUT /api/v1/project-dictionaries/{id}` 修改，`type` 创建后不可修改。
- `DELETE /api/v1/project-dictionaries/{id}` 删除。

读写模型为 `{ id, type, code, name, parentId, parentName, sortNo, enabled, inUse }`；创建和修改请求不含 `id`、`parentName`、`inUse`。`code` 为 1-64 位 ASCII 字母、数字、下划线或短横线，统一保存为大写；`name` 为 1-128 个字符；`sortNo` 为 0-100000。

`ROBOT_MODEL.parentId` 必须指向 `ROBOT_VENDOR`。已被项目引用的型号不能更换所属厂商。项目引用或厂商仍有子型号时拒绝删除；可停用并继续显示历史项目上的名称。字典写操作要求 `config:manage`；读取允许 `config:manage`，或同时具有 `project:list` 与 `project:create`/`project:update`。

`GET /api/v1/project-owner-options` 返回 `{ id, employeeNo, realName, sectionId, sectionName }[]`，权限为 `project:list` 与 `project:create`/`project:update`。

v6 初始只建立 `HIGH/高`、`NORMAL/普通`、`LOW/低` 三个优先级。机器人厂商和型号不预置业务数据，由管理员维护。

## 迁移与运行

升级命令仍为 `dotnet run --project Yf.Api -- --migrate-database`。迁移新增 `project_dictionaries`、`project_work_orders`，并在 `projects` 增加可空元数据字段；启动过程只验证 schema，不自动迁移。源码回退不能撤销 v6 数据结构，回退应用前需使用匹配版本的数据库备份。
