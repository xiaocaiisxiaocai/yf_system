# 项目元数据与字典契约

## 数据层级

- 主项目统一维护供应商、工令号、机型、Robot 厂商、Robot 型号、负责人、课别、优先级、预计完成日期和项目说明。
- 子项目只允许维护名称和说明，并在创建时继承主项目公共资料。
- 修改主项目后，未完成子项目同步业务资料和工令号；已完成子项目保留验收时的业务资料快照。
- 负责人和课别决定访问权，因此所有子项目（包括已完成子项目）始终同步主项目当前负责人和课别。

## 必填字段

创建或编辑主项目时，下列字段均为必填：

- `name`：主项目名称。
- `supplierId`：关联供应商；创建后不可更换。
- `workOrderNos: string[]`：至少 1 项、最多 50 项；逐项 trim、忽略空白、按不区分大小写去重，每项最多 128 个字符。
- `machineModel: string`：trim 后 1–128 个字符。
- `robotVendorId`、`robotModelId`、`responsibleUserId`、`priorityId`：有效正整数 ID。
- `expectedCompletionDate: string`：严格使用 `yyyy-MM-dd`。
- `subprojectNames: string[]`：创建主项目时至少提供一个子项目名称。

`sectionId` 不接受客户端输入。后端从负责人直属组织带入；负责人直属组织不是启用的课别时拒绝保存，不猜测下级组织。

## 接口

- `POST /api/v1/project-groups`：创建主项目及初始子项目，接收完整公共资料和 `subprojectNames`。
- `PUT /api/v1/project-groups/{id}`：修改主项目公共资料。存在待验收子项目、主项目已完成或已终止时拒绝修改。
- `POST /api/v1/project-groups/{id}/projects`：新增子项目，只接收 `name`、`description`。
- `PUT /api/v1/projects/{id}`：修改子项目名称和说明，不接受独立公共元数据。
- `GET /api/v1/project-owner-options`：返回 `{ id, employeeNo, realName, sectionId, sectionName }[]`。

项目列表和详情响应包含 `workOrderNos`、`machineModel`、Robot 厂商/型号、负责人、课别、优先级及 `expectedCompletionDate`。课别只读，Robot 型号随厂商联动。

## 负责人和供应商范围

- 负责人必须是启用的公司内部用户，直属组织为课别，有效角色具有 `project:list`。
- 公司内部访问只由当前负责人或 `project:view_all` 决定；创建人和历史关系不授予访问权。
- 关联供应商下所有启用账号都可访问项目，不维护项目成员名单。
- 普通内部通知和留言回执参与者只包含当前负责人；全局查看者不会自动加入普通通知或回执。
- schema v10 删除旧 `project_members` 表及 `project:member` 权限。

## 数据字典

侧栏“数据字典”（`/system/dictionaries`）维护 Robot 厂商、Robot 型号和优先级，使用 `config:manage` 权限。支持新增、编辑、排序、停用和删除。

字典类型固定为：

- `ROBOT_VENDOR`
- `ROBOT_MODEL`
- `PRIORITY`

接口：

- `GET /api/v1/project-dictionaries?type=...&enabledOnly=true|false&parentId=...`
- `POST /api/v1/project-dictionaries`
- `PUT /api/v1/project-dictionaries/{id}`
- `DELETE /api/v1/project-dictionaries/{id}`

读写模型为 `{ id, type, name, parentId, parentName, sortNo, enabled, inUse }`。数据字典没有编码字段；`name` 为 1–128 个字符，同一类型名称唯一，`sortNo` 为 0–100000。

`ROBOT_MODEL.parentId` 必须指向 `ROBOT_VENDOR`。已被项目引用的型号不能更换厂商；项目仍引用字典项或厂商仍有子型号时不能删除，可停用并继续显示历史名称。

## 迁移与运行

- schema v6 引入项目字典、工令号和公共元数据字段。
- schema v9 引入主项目层级并回填现有项目。
- schema v10 删除旧成员模型，增加负责人和公共元数据的外键与一致性保护。
- 升级命令为 `dotnet run --project Yf.Api -- --migrate-database`。正常启动只验证 schema，不自动迁移。
- v10 迁移发现无效负责人、课别、字典引用或不一致的主子项目数据时会中止并报告，不会静默修补业务数据。

## 验证口径

- 结构测试必须覆盖当前 schema 版本、旧成员表退出、外键、内置供应商撤回权限和迁移可重入性。
- 业务测试必须覆盖主子资料同步、已完成业务快照冻结、负责人转交、供应商企业级访问及内部/供应商验收职责。
- 前端测试必须覆盖主项目表单、字典联动、待验收编辑门禁、负责人/供应商说明及角色文案。
