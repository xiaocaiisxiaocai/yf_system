# 公告图文、文件与排序

公告中心供内部和 ODM/OEMA 账号阅读。内部公告管理使用同一份正文进行编辑、发布预览和管理预览。原有接收范围、本人下架和阅读明细权限继续适用。

## 正文与文件

- 历史公告保留纯文本正文。图文草稿保存 Tiptap 文档；服务端校验段落、标题、列表、表格、链接及图片节点，并从文档生成列表所用的文字。只有图片或只有附件的公告也可以发布。
- 图片在正文中按位置展示，图注和显示宽度随图片节点保存。附件另有排列顺序。列表显示文字摘要、首张缩略图及文件数量。仅附件公告显示首个文件名和附件数。
- 上传属于某一条草稿。相同文件操作重试使用相同上传标识，成功上传的文件经草稿保存后成为正式引用。发布前应完成、重试或移除未成功的文件。复制重发在新公告下保存独立的文件引用。
- 图片支持 JPEG、PNG、GIF 和 WebP，单张上限 10 MiB。附件支持 PDF、Word、Excel、PowerPoint，单件上限 32 MiB；PDF、DOCX、XLS/XLSX、PPTX 使用现有预览器，旧版 DOC 和 PPT 提供下载。单条公告允许最多 100 个已引用的图片和附件。
- 内部读者、厂商读者和内部管理者分别从对应的公告资源接口请求原图、缩略图和附件。服务端按请求中的公告核验文件引用及当前访问资格。下架后读者通过旧链接无法再次获取文件；获授权的管理人员可查看归档。
- 浏览摘要、加载缩略图和管理预览都不写阅读记录。打开全文后沿用账号的首次和最近阅读时间。
- 实际文件存放在协作存储根目录的 `announcement-assets/` 下。备份与恢复时应包含该目录及数据库的文件引用表。删除草稿中的图片后允许在编辑器里撤销；发布时清除未选引用，日常清理会回收超过保留期的暂存及无引用文件。

## 排序与置顶

- 置顶组排在普通组之前。两组分别保存手动顺序。组内已填写顺序号的公告优先，数值小的在前。同号或未填写时，置顶组按置顶时间倒序、普通组按发布时间倒序，最后按公告编号倒序。
- 同一条公告取消置顶后恢复普通组原有的顺序；移入另一组不改原组的顺序号。
- 管理页支持拖动、上移、下移及直接输入顺序号，预览后保存。服务端复用置顶管理权限及管理范围，核验整组预览版本后一次写入。其他管理者已经改变顺序或组成员时返回冲突，操作人刷新并重新确认。
- 读者只在自己可见的公告中看到上述顺序。列表跨页遵循同一顺序。调序保留阅读记录，并写入公告分类的操作日志。
