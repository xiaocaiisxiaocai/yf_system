# 主项目与子项目协作契约

## 数据归属

- 主项目是项目列表的顶层对象，统一维护供应商、工令号、机型、Robot 厂商与型号、负责人、课别、优先级、预计完成日期及主项目说明。
- 子项目必须归属于一个主项目。数据库字段 `projects.project_group_id` 为非空外键，不能产生孤立子项目。
- 新建子项目时复制主项目当前公共资料；主项目资料更新时，在同一事务中同步到全部子项目。
- 子项目仅维护自己的名称和说明。文件、留言、已读回执、动态、复制履历和验收状态均按子项目 ID 隔离。
- 主项目没有文件或留言接口，不能把协作内容写到主项目层级。

## 状态与验收

- 每个子项目沿用独立的草稿、进行中、待内部验收、已完成和已终止流程。
- 主项目状态由全部子项目状态计算，不提供手工修改入口。
- 全部子项目为草稿时，主项目为草稿；任一子项目开始后，主项目进入进行中。
- 全部子项目验收完成时，主项目在最后一次确认的数据库事务内自动变为已完成并记录完成时间。
- 全部子项目均已结束且至少一个已终止时，主项目为已终止；重新开始子项目会自动重开主项目。

## 访问范围

- 供应商账号可访问与自己供应商一致的主项目及其子项目。
- 内部账号按主项目负责人控制访问；拥有 `project:view_all` 的账号可查看全部主项目。
- 更换主项目负责人会同步全部子项目，旧负责人不再因历史成员关系继续获得访问权。

## 主要接口

- `GET/POST /api/v1/project-groups`：查询或创建主项目。创建时必须同时提供至少一个子项目名称。
- `GET/PUT/DELETE /api/v1/project-groups/{id}`：查看、更新或删除空主项目。
- `POST /api/v1/project-groups/{id}/projects`：在主项目下新增子项目并继承公共资料。
- `/api/v1/projects/{id}/...`：只处理子项目详情、文件、留言、动态、复制和验收。

迁移 v9 会先为现有项目建立对应主项目并回填关系，再将 `project_group_id` 收紧为非空。迁移可重复执行，应用启动只校验结构，不自动升级。
