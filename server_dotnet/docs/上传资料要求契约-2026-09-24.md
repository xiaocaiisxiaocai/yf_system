# 上传资料要求契约

## 目标

公司内部发给供应商（C2S）的资料必须能直接用于 Robot 动作评估：上传窗口的每一批都要同时包含动作流程 Excel，以及 STEP 格式 3D 图或压缩文件（STEP 很多时会打包压缩）。动作流程 Excel 不再校验文件名。供应商发给公司（S2C）的资料不做限制，上传窗口只展示资料示例（多视角循环动作视频、调整信息说明）。

方向由上传者身份决定：内部账号上传即 C2S，供应商账号上传即 S2C，与现有文件方向一致。

## C2S 规则（服务端强制）

校验点是 `POST /api/v1/uploads/init` 建立**新**上传会话时（`UploadService.InitAsync`），资料先行规则在合并时（`POST /api/v1/uploads/{id}/merge`）再校验一次；规则实现在 `Yf.Api/Modules/Files/UploadMaterialRules.cs`，前端镜像 `web/src/utils/uploadMaterialRules.ts`。失败返回 `400 / 40001`，提示为中文业务信息。

### 1. 必需资料：Excel + STEP/压缩文件（2026-10-29 起）

- 必需资料分两类：**动作流程 Excel**（`.xls` / `.xlsx` / `.xlsm` / `.xlsb`）与 **3D 资料**（STEP `.step` / `.stp`，或压缩文件 `.zip` / `.rar` / `.7z`），扩展名大小写不敏感。压缩文件不解包检查内容。
- **上传窗口按批强制**（前端，`ChunkUploader`）：C2S 时本批（不含已取消、被拒绝的文件）必须同时有一个 Excel 和一个 STEP 或压缩文件，否则「上传所选文件」不可用并给出提示。只有 Excel、只有 STEP/压缩文件或只有其它文件的批次都会被拦下。
- **服务端按子项目强制**（服务端没有“批”的概念）：必需资料本身（Excel、STEP、压缩文件）初始化与合并都不受此条限制；其它任意文件初始化时，子项目必须同时具备两类资料，每类满足以下任一条件，否则拒绝：
  - 已有状态为 `AVAILABLE` 的 C2S 文件；
  - 存在内部账号发起、未过期、状态为 `UPLOADING` / `MERGING` 的上传会话（支持“同批上传”：必需资料先建立会话，其余文件随后初始化）。
- 检查在新会话事务内完成，读取数据库时钟判断会话是否过期。
- 已取消/过期的会话不计入；续传已有会话不重复检查。
- **合并时再校验**：内部账号合并其它文件时，子项目必须已有 `AVAILABLE`（已合并、未删除）的 C2S Excel 与 STEP/压缩文件；进行中的会话只在**初始化**时放行同批文件，合并时不再计入。不满足时合并返回 `400 / 40001`（同一提示）。先在认领合并前快速检查（会话保持 `UPLOADING`，不做哈希），再在合并写事务内（项目行锁之后）权威复核；复核失败会把合并租约退回 `UPLOADING`，已传分片保留，资料上传完成后可再次合并，也可以取消。
- 之后删除资料文件不受此规则阻止（规则只约束新增资料，不追溯）。
- 上传白名单 `upload.allowed_exts` 必须至少保留一个 Excel 扩展名，以及 `step` / `stp` 或一个压缩文件扩展名，否则保存参数时返回 400。

### 2. 动作流程 Excel

- 2026-10-21 起不再按文件名正则限制 C2S 电子表格。`.xls` / `.xlsx` / `.xlsm` / `.xlsb` 只要在上传白名单内即可，文件名不作格式检查。
- 这些文件属于必需资料（见 §1），本身不受资料先行约束。其它扩展名受资料先行与白名单约束。

### 3. Excel 扩展名的配套支持（2026-10-06）

- 上传白名单 `upload.allowed_exts`：新库种子（`BootstrapSeedCatalog`）包含 `xls,xlsx,xlsm,xlsb`；已有库由数据迁移 `AllowMacroAndBinaryExcelUploads` 在白名单已含 `xlsx` 时补上缺失的 `xlsm` / `xlsb`（可重复执行；管理员已去掉 `xlsx` 的白名单不改动；回滚迁移不回收）。白名单对两个方向同时生效。
- MIME（`FileStorage.MimeType`）：`.xls` `application/vnd.ms-excel`、`.xlsx` `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`、`.xlsm` `application/vnd.ms-excel.sheet.macroEnabled.12`、`.xlsb` `application/vnd.ms-excel.sheet.binary.macroEnabled.12`。
- 在线预览（≤50 MiB，`GET /files/{id}/content`）四种都支持：`.xlsx` / `.xlsm` 由 ExcelJS 直接解析（`.xlsm` 的宏不执行、不展示）；`.xls`（OLE2）与 `.xlsb`（ZIP 内二进制 BIFF12，ExcelJS 会静默解析为空表）先在沙箱预览器内经 SheetJS 转成 xlsx 再渲染，样式保真度低于 `.xlsx`。解析失败时显示“Excel 预览失败”，仍可下载。

## 每账号上传配额（服务端强制，两个方向都适用）

新建上传会话时按账号统计**未过期**且状态为 `UPLOADING` / `MERGING` 的会话：

| 配置 | 默认 | 取值范围 | 超限提示 |
| --- | --- | --- | --- |
| `App:UploadMaxActiveSessionsPerUser` | 20 | 1–1000 | 当前账号未完成的上传任务已达上限（N 个）… |
| `App:UploadMaxPendingBytesPerUser` | 21474836480（20 GiB） | 1 GiB–16 TiB | 当前账号未完成上传的文件总大小超过上限（N GiB）… |

- 字节数按会话声明的 `file_size` 累计（含本次申请）；完成、取消、过期的会话不占配额。
- 超限返回 `409 / 40901`（不是 429：前端分片上传会自动重试 408/429/5xx，而配额需要用户先完成或取消已有上传）。
- 续传已有会话、上传分片、合并都不受配额限制。
- 同一账号的新建会话经 MySQL 命名锁 `upload-quota` 串行化，并发初始化不会越过上限；等待超过 10 秒返回 `409 / 40901`“上传会话正在创建，请稍后重试”。

## 前端行为

- `ChunkUploader` 通过 `direction` 区分方向（`FileTable` 按账号类型传入）。
- C2S：窗口顶部展示资料要求，并附两张示例图（STEP 3D 总装图、动作流程说明 Excel，`web/src/assets/upload-examples/company-*.jpg`，2026-10-08 起）。Excel 文件名不再拦截。本批缺少 Excel 或 STEP/压缩文件时禁用上传并提示（2026-10-29 起，替代原先“本批没有 STEP 时只提醒”的行为；文件表不再预查子项目已有 STEP）。
- 同批包含必需资料与其它文件时，必需资料先建立上传会话，其它文件显示“等待同批 Excel 与 STEP/压缩文件开始上传”，所有必需资料会话建立（或已结束）后再开始分片上传；分片与 MD5 提交完成后显示“等待同批 Excel 与 STEP/压缩文件上传完成”（释放并发名额），同批必需资料全部结束（合并完成或失败）后再请求合并。必需资料失败时也放行，由服务端返回明确提示。
- S2C：展示两张示例图（`web/src/assets/upload-examples/`），不做任何限制。

## 变更记录

- 2026-10-06：C2S 动作流程 Excel 由“只接受 `.xlsx`”改为 `.xls` / `.xlsx` / `.xlsm` / `.xlsb` 同等接受，并受 STEP 先行约束；上传白名单、MIME 与在线预览配套支持（见 §3）。
- 2026-10-21：移除 C2S 动作流程 Excel 的文件名正则。上传窗口不再展示「CSLR-XXX XXX机 210XXX-X 动作流程.xlsx」命名要求。
- 2026-10-22：提交验收、终止和复制所阻挡的“活动上传”改为：`MERGING` 始终阻挡；`UPLOADING` 仅在 `expires_at` 晚于数据库时钟时阻挡。已过期的 `UPLOADING` 不再阻挡。`GET /api/v1/projects/{id}/upload-sessions` 只列出这些阻挡中的会话（最多返回 200 条，`total` 为全部数量），需要项目查看权限；不返回临时目录、指纹或分片摘要。取消仍走 `DELETE /api/v1/uploads/{sessionId}`。上传人可取消自己的未完成会话；内部账号在项目进行中且具备 `file:delete` 或 `project:status` 时可取消他人会话；同供应商的供应商账号在具备 `file:upload` 与 `project:submit` 时只能取消该供应商账号的会话，不能取消内部账号的会话。无权取消返回 403，会话不存在返回 404。配额统计仍只计未过期的 `UPLOADING` / `MERGING`，与上述阻挡条件不是同一规则。
- 2026-10-29：C2S 资料要求由“至少一个 STEP”改为“动作流程 Excel + STEP 或压缩文件（.zip/.rar/.7z）”。上传窗口按批强制（缺任一类时禁用上传）；服务端对 Excel/STEP/压缩文件本身不再设先行限制，其它文件要求子项目同时具备两类资料。上传白名单校验同步调整。
