## 维护脚本行为

- Backup：停止命名站点的专属应用池并等待 worker 退出，成套备份数据库、文件存储、外部配置和旧程序，生成 SHA-256 清单。
- Upgrade：先完成上述备份，核验新包并复制到新空目录；仅指定 `-MigrateDatabase` 时执行迁移，然后切换同一站点的物理目录。
- Restore：校验备份清单及站点归属，只写入另一个空数据库、空存储目录和空程序目录，保留旧数据。目标库存在表、存储过程/函数或事件时拒绝恢复。
- 前置检查拒绝路径重叠、重解析点、篡改/额外清单文件、非标准启动、会覆盖外部 JSON 的环境变量。检查 IIS 有效配置、应用池默认环境、机器及当前进程环境。
- 备份目录和临时 MySQL 配置限制 ACL；密码不进入命令行。客户端临时凭据文件在成功或失败路径清理。
- 失败保持命名池停止，保留现场；数据库迁移后不自动切回旧程序。操作前需确认没有其他实例写同一数据库或存储。

完整参数和目标服务器命令见 [部署维护说明](../deploy/README.md)。脚本针对现有专属 IIS 站点；新机器仍需先完成 Hosting Bundle、MySQL、证书和同名站点安装。

IIS 默认环境变量也会传给应用池 worker，因此不能只检查网站内的 `web.config`。配置读取和 worker 查询使用 [IIS 环境变量说明](https://learn.microsoft.com/en-us/iis/configuration/system.applicationhost/applicationpools/applicationpooldefaults/environmentvariables/) 与 [Microsoft.Web.Administration.ServerManager](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.administration.servermanager?view=iis-dotnet) 对应的管理接口。

## 证据边界

本轮不向外部发送邮件，不运行目标服务器的 IIS 安装、升级或恢复。维护数据操作在本机自有临时 MySQL 库和目录验证；IIS 管理部分做输入守卫、语法和可用管理接口的只读检查。不能将这些结果表述为目标服务器 IIS、证书、网络或正式恢复演练已通过。

维护前置校验拒绝时不停止站点；进入停池维护阶段之后失败才保持命名池停止。维护窗口前应确认配置与实际运行实例一致，配置调整后先按正常部署流程重启并核对目标资源。

前端业务代码未改动；已有前端测试证据只有在源码哈希仍一致时复用。发布包构建和 HTTP 验证针对本轮新的 .NET 二进制。
