# 邮件提醒规则契约

## 目标

系统保留 SMTP 发件配置，并把邮件提醒拆成三个层级：总开关、收件对象开关和消息类型开关。只有内部管理员拥有 `config:manage` 权限时可以维护这些设置。

## 配置项

| 层级 | 参数 | 默认值 | 作用 |
| --- | --- | --- | --- |
| 总开关 | `notify.enabled` | `true` | 关闭所有业务邮件提醒和发送任务 |
| 收件对象 | `notify.internal.enabled` | `true` | 是否发送给公司内部员工 |
| 收件对象 | `notify.supplier.enabled` | `true` | 是否发送给外部企业（供应商）账号 |
| 消息类型 | `notify.event.message_created` | `true` | 新留言 |
| 消息类型 | `notify.event.file_uploaded` | `true` | 新文件 |
| 消息类型 | `notify.event.project_started` | `true` | 开始子项目（`PROJECT_STARTED`），提醒供应商 |
| 消息类型 | `notify.event.project_terminated` | `true` | 终止子项目（`PROJECT_TERMINATED`），提醒供应商 |
| 消息类型 | `notify.event.project_restarted` | `true` | 重新开始子项目（`PROJECT_RESTARTED`），提醒供应商 |
| 消息类型 | `notify.event.project_reopened` | `true` | 重开已完成子项目（`PROJECT_REOPENED`，正文含重开原因），提醒供应商 |
| 消息类型 | `notify.event.project_material_reviewed` | `true` | 资料确认：负责人确认 OK（`PROJECT_MATERIAL_APPROVED`，子项目随之完成）或退回（`PROJECT_MATERIAL_RETURNED`）回传资料时提醒供应商（2026-10-29，迁移 `AddProjectMaterialReview` 以 `INSERT IGNORE` 补齐） |
| 消息类型 | `notify.event.project_due_soon` | `true` | 即将到期（`PROJECT_DUE_SOON`），见下文“到期提醒” |
| 消息类型 | `notify.event.project_overdue` | `true` | 已逾期（`PROJECT_OVERDUE`），见下文“到期提醒” |
| 到期对象 | `notify.due.internal.enabled` | `true` | 到期 / 逾期提醒是否发给子项目负责人 |
| 到期对象 | `notify.due.supplier.enabled` | `true` | 到期 / 逾期提醒是否发给供应商 |
| 到期参数 | `notify.due.remind_days_before` | `3` | 需求完成时间前几天发即将到期提醒，整数 1–30；非法存量值按 3 处理 |

2026-10-31（Robot 仿真协作第 2、3 批，迁移 `AddProjectNotificationsAndDueReminders`）：以 `INSERT IGNORE` 补齐上表新参数，删除已退役的 `notify.event.project_submitted` / `project_confirmed` / `project_rejected` / `project_withdrawn`。状态类邮件（开始、终止、重新开始、重开）只发给供应商一方，不发给操作人。历史遗留的 `PROJECT_SUBMITTED` 待发邮件在领取时取消（`PROJECT_ACCEPTANCE_RETIRED`）；其他已退役事件类型不再受独立开关控制，只受总开关和对象开关约束。

缺少新参数时按开启处理，保证迁移前的测试夹具和正在升级的开发库不会意外停止通知。v11 迁移会用 `INSERT IGNORE` 补齐缺失参数，不覆盖已保存的值。

## 判定与发送

收件地址（2026-10-30）：发给供应商一方的邮件改发给该供应商所有启用的联络人；没有启用联络人时仍发给供应商账号邮箱。详见 [厂商联络人与签名契约](厂商联络人与签名契约-2026-10-30.md)。

业务写入事务创建 outbox 记录前会检查总开关、消息类型和收件对象。收件账号没有邮箱时不创建 outbox，并写入 `EMAIL_SKIPPED_MISSING_EMAIL` 审计。SMTP worker 在领取记录时重新读取同一套规则和收件账号类型：规则在入队后关闭，记录会标记为 `CANCELLED`，并写入 `EMAIL_CANCELLED_STALE` / `NOTIFICATION_POLICY_DISABLED`，不会调用 SMTP。

SMTP 未配置时仍不会发送；规则开启不代表一定能发出邮件。真实发送还需要有效的 SMTP 配置、收件账号处于启用状态、项目访问权限仍然有效，并且对应账号填写了邮箱。

收件人资格（2026-09-27 补充）：入队和 worker 领取时都要求收件账号为 `ACTIVE`、不处于"须修改初始密码"（`must_change_password=1`）状态；供应商账号还要求所属供应商公司为 `ACTIVE`。入队后供应商公司被停用或账号被重置为须改密，领取时记录标记为 `CANCELLED`（`收件人已无项目访问权限，通知已取消`），不会调用 SMTP。

## 到期提醒（2026-10-31）

- 后台服务 `ProjectDueReminderService` 每小时扫描一次（`App:WorkerEnabled=false` 时不运行；单实例），对象为 `IN_PROGRESS` 且填写了需求完成时间的子项目，草稿和终态不提醒。
- 业务日期按中国标准时间（UTC+8）计算“今天”，以数据库时钟为准。
- 需求完成时间在 [今天, 今天 + `remind_days_before`] 内发一次 `PROJECT_DUE_SOON`；早于今天发一次 `PROJECT_OVERDUE`，之后不重复。
- 已发送记录保存在子项目行 `due_soon_notified_for` / `overdue_notified_for`（记录发送时对应的需求完成时间），扫描以条件更新占用后再入队，因此重复扫描、重启都不会重发；修改需求完成时间后按新日期重新提醒。该标记不更新 `updated_at`，不影响 `expectedUpdatedAt` 并发基线。不使用 outbox `dedupe_key` 去重，避免已完成邮件按保留期清理后重复提醒。
- 收件人：子项目负责人（`notify.due.internal.enabled` 且 `notify.internal.enabled`）和供应商一方（`notify.due.supplier.enabled` 且 `notify.supplier.enabled`，按联络人规则展开）。两个到期对象开关都关闭或事件开关关闭时，扫描不占用标记，之后重新开启仍会在条件满足时提醒。
- worker 领取时按同一套规则复核（含到期对象开关），规则关闭则取消。

## 合并、有效期与失败处理（2026-09-27）

- **合并窗口**：`FILE_UPLOADED` 与 `MESSAGE_CREATED` 均按（子项目，收件人）合并。首条事件创建一条 `PENDING` 记录（`dedupe_key` 分别为 `file-summary:*` / `message-summary:{projectId}:{recipientId}`），`next_attempt_at` 为创建时间 + 2 分钟；窗口内的后续事件追加到同一封邮件正文，每条留言保留自己的精确链接 `/projects/{id}?tab=messages&target={messageId}`。记录被 worker 领取、已重试、已发送或正文将超过约 60000 字节时释放合并键，下一条事件开启新窗口。窗口长度为代码常量，不可配置。
- **过期取消**：`PENDING` 记录创建超过 `App:MailPendingTtlDays`（默认 3 天，范围 1–365）仍未发送时，worker 将其标记为 `CANCELLED`，`last_error` 为"待发送邮件超过有效期，已取消"，并写入 `EMAIL_CANCELLED_STALE` 审计（`reason=PENDING_EXPIRED`）。该清理每分钟最多执行一次，SMTP 未配置时同样执行，避免配置 SMTP 后补发多日前的提醒。
- **失败分类**：
  - 连接、TLS、认证失败、超时、发件人（MAIL FROM）被拒或发件地址无效属于 SMTP 服务不可用：停止本批次，当前记录保持 `PENDING` 且不增加 `retry_count`，写入 `EMAIL_RETRY` 审计（`reason=SMTP_UNAVAILABLE`），并打开熔断：首次暂停 1 分钟，连续失败逐次翻倍，最长 30 分钟；任一邮件发送成功或 SMTP 配置变更后立即恢复。熔断状态只保存在单实例进程内存中。
  - 收件人或内容的 5xx 永久拒绝（如 RCPT 550）或收件地址格式无效：只将该邮件标记为 `FAILED`，同批其他邮件继续发送。
  - 4xx 及其他未知错误：沿用原重试策略（`retry_count` 加 1，30 秒起指数退避，累计 3 次后 `FAILED`）。

## 前端行为

“系统参数 → 邮件发送 → 邮件提醒规则”展示对象开关、九类消息开关和“到期提醒”分组（提前天数、负责人、厂商）。修改只保存在草稿中，点击“保存邮件提醒”才通过批量系统参数接口提交；“取消修改”恢复最近一次服务端状态。通用系统参数表隐藏这些专用项，避免同一配置出现两处编辑入口。
