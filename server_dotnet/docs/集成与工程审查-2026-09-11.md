## 范围与判断

逐模块核对了 Identity、Admin、Projects、Files、System 与基础设施，以及 React 的登录/会话恢复、权限菜单、管理列表、项目工作流、留言、文件上传预览、系统配置、审计消费者。对接检查包含 HTTP 方法、路径、请求字段、响应字段、空值、分页、时间、错误码和权限；路由数量本身不作为行为正确的证明。

后端采用的模块化单体、Minimal API 和 Dapper 适合当前协作平台，不需要为了设计模式改成微服务、EF Core 或机械增加 Controller/Repository 层。代码已有真实事务、权限策略、状态转换和故障恢复边界，但本轮又发现了此前通过用例没有覆盖的权限与资源问题，因此不能仅凭路由对齐、构建成功或测试数量判断迁移完成。

## 工程设计评估

|方面|当前代码证据与结论|
|---|---|
|模块与依赖注入|模块注册和端点映射分开；业务服务按 Identity/Admin/Projects/Files/System 定位。单例主要持有配置或线程安全缓存，MySQL 连接按操作取得并释放，不将连接作为单例共享。|
|应用服务与状态规则|端点负责绑定/认证上下文，业务服务协调授权、查询、事务与返回。`ProjectWorkflowRules` 将管理状态转换和成员上限提取成纯规则，避免把状态机散布在页面按钮中。|
|数据一致性|`AppDb.BeginTransactionAsync` 统一 READ COMMITTED；管理门、用户/项目行锁确定写入顺序；业务、审计及通知入队在同一事务。已有锁等待交错回归验证提交不能读取过时文件/上传状态。|
|授权|后端检查身份、操作权限和项目范围，前端权限仅负责呈现。补齐工作台、项目读取、选项接口、预览和供应商角色生命周期边界。供应商不能通过误配管理权限跨越 INTERNAL 硬边界。|
|文件恢复|分片先进入受限临时存储，再在短事务内复核。命名锁和更新栅栏区分在途与中断合并；pending-final 标记处理结果未知，清理前检查数据库引用；路径解析阻止越出存储根。|
|事务 outbox|业务写入与邮件任务入队原子提交，后台领取使用状态/租约比较并更新。SMTP 是独立外部副作用，本轮增加窄的投递接缝，把已接受邮件与连接清理失败区分。|
|错误与诊断|业务异常统一为稳定 HTTP/code/message；日志不输出连接串、密码或令牌。审计与项目动态通过 `IProjectAuditCapture` 在同一数据库事务中关联；补齐资料修改和注销的可见记录。|
|测试接缝|纯规则/安全用例、真实隔离 MySQL、真实 HTTP、生产入口与少量实际浏览器操作各自证明不同层次。验证码观察器仅存在于独立 TestHost，正式 API 没有答案接口。|
|独立维护|.NET 自己初始化/显式迁移和维护版本记录；测试接受独立测试连接；前后端可由 .NET 发布脚本打包。旧第 16/17 版库可接管，更早结构须另行审查有损转换。|

仍值得后续维护的地方：部分 Admin 服务方法把多个步骤挤在一行，阅读成本较高；匿名响应对象缺少编译期消费者约束，继续依靠契约回归保护，适合在实际接口扩展时逐步引入命名 DTO；`SchemaMigrations` 当前校验值是固定版本标识，并非迁移源码内容哈希，修改迁移行为时必须增加版本，不能依赖它识别源码被修改。这些不是要求立即重写架构的理由。

前端另有非阻断性能跟进项：静态检查显示 Excel 预览关闭后没有中止请求，且在检查组件有效状态前执行解析；大型工作簿的取消耗时尚未实测。本轮保留为后续性能验证项，未将它计入已修复缺陷或后端对接验收。

## 本轮缺陷与修复

|编号|级别|真实触发与影响|修复与回归|
|---|---|---|---|
|1|P2|内置供应商角色仍有启用账号时可被禁用；还可创建/启用绑定禁用角色的账号，导致成功创建但无可用权限。|角色禁用检查覆盖所有启用用户；创建/启用供应商账号要求启用的内置供应商角色。HTTP 检查拒绝与重新启用控制组。|
|2|P2|用户页面提示可搜邮箱，后端只匹配工号/姓名，邮箱查询得到空结果。|查询加入邮箱条件，HTTP 同时核对 total 和目标记录 ID。|
|3|P2|资料修改写入 PROFILE_UPDATE，却不属于审计分类，页面也没有对应中文摘要。|归入 AUTH 分类并增加标签、筛选和字段摘要；HTTP 与组件回归覆盖。|
|4|P2|人工退出会撤销会话，但始终不生成页面支持的 LOGOUT 审计。|仅在真实撤销有效会话时记录一次，包含来源 IP，不记录 token/session ID；重复退出无重复记录。|
|5|P2|SMTP SendAsync 已成功，随后 QUIT/关闭连接异常仍被当成发送失败，进入重试而重复投递。|已接受投递与清理分离；清理独立 5 秒，SENT 落库使用独立 15 秒完成窗口。模拟接受后取消+QUIT IOException，真实库断言 SENT 且不重发；发送阶段失败仍正常重试。|
|6|P2|仅有 file:preview 的账号可通过 content 接口取得 ZIP 等不支持预览的完整文件；Excel 缺少后端预览大小限制。|只允许 PDF/XLS/XLSX，统一 50 MiB 上限；预览和下载权限分别检查。HTTP 包含无下载权限控制组、ZIP 拒绝、超限 Excel 拒绝、合法下载。|
|7|P2|撤销工作台菜单后，首页仍加载工作台数据，两个后端接口也不检查 dashboard 权限。|前端无权限不请求数据、不发生首页重定向循环；后端两个入口均拒绝。个人资料入口仍可用。|
|8|P1|认证连接跨越整个 next()，慢上传/下载持续占用连接；并发请求还可能各占一个认证连接，等待第二个业务连接导致池饥饿。|认证查询结束即释放连接，然后调用下游。真实 MySQL 单连接池用例中，下游必须能取得连接并完成查询。|
|9|P2|撤销 project:list 后，既有成员关系或供应商身份仍能直接调用项目与关联资源读取接口。|在统一项目访问边界和项目列表验证 project:list；用仍有项目关系但无菜单权限的账号验证拒绝，并保留正常权限控制组。|
|10|P2|选项接口仅要求内部身份，未获功能权限的账号也能枚举供应商及员工；受限成员的供应商过滤选项还可能包含不可见项目的供应商。|选项要求对应项目/成员权限；供应商列表按创建/全量查看权限或既有项目范围限定。HTTP 覆盖受限与正常选择场景。|
|11|P2|SMTP 状态页与发送 worker 对空白主机判定不同，非法端口/发件地址等也可能到发送时才失败。|统一启用判定并在启动时验证完整配置；空主机仍表示关闭。8 项配置用例覆盖关闭、有效和非法配置。|

P1 表示可能影响系统可用性、需优先修复的问题；P2 表示有具体触发条件的功能或权限缺陷。本轮未发现需要重新选择后端技术栈的问题。

## 结论的边界

本报告证明的是代码审查、局部前端冒烟及当前本地隔离回归，不是生产部署验收。目标服务器 IIS/HTTPS、真实 SMTP、生产业务数据库接管、生产容量和备份恢复尚未在本轮执行。

预览接口向浏览器提供 PDF/Excel 字节，因此预览权限不等于 DRM 式“能看但无法保存”。邮件保持至少一次投递：SMTP 接受后进程立即退出或完成记录丢失时，仍可能需要重试；本轮修复的是已知接受后仅因关闭连接异常造成的错误重试。业务请求在提交响应丢失时也可能结果未知，不应对所有写操作无条件自动重试。

历史发布包 v3 对应基线 `ab95e71`，不包含本轮后续修复；本报告不将旧包或未执行的目标机部署视为更新完成。
