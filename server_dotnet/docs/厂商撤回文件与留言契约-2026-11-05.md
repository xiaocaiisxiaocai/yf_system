# 厂商撤回文件与留言契约（2026-11-05）

适用于 Robot 协作（`/api/v1`）。ODM/OEMA 业务线不提供撤回。

## 配置

系统设置「运行参数」中两项独立配置（`RuntimeSettings`，保存后立即生效，无需迁移；首次启动按 `App:` 配置补行）：

| 参数 | 默认 | 范围 | 含义 |
|---|---|---|---|
| `withdraw.supplier_file_minutes`（厂商文件撤回时限） | 10 | 0–1440 分钟 | 厂商上传文件后可自行撤回的分钟数，0 表示不允许撤回 |
| `withdraw.supplier_message_minutes`（厂商留言撤回时限） | 10 | 0–1440 分钟 | 厂商发表留言后可自行撤回的分钟数，0 表示不允许撤回 |

时限按数据库时钟从文件合并完成 / 留言写入的时间起算，使用撤回发生时的配置值。

## 撤回

- 接口：`POST /files/{id}/withdraw`、`POST /messages/{id}/withdraw`。
- 只有上传 / 发表它的那个厂商账号本人可撤回（同厂商的其他账号、内部账号均不可）；仍须持有 `file:upload` / `message:create`。
- 内部复制带入的文件不提供厂商撤回，包括再次复制的文件；复制时间不能开启新的上传撤回窗口。原始上传文件即使被复制，仍按原上传时间和通常规则判断撤回。
- 子项目必须为进行中。文件只限「供应商 → 公司」方向；负责人已退回（`RETURNED` 且覆盖该文件）的那份资料不能撤回，已确认通过的子项目已完成，自然不可撤回。
- 撤回后状态为 `WITHDRAWN`：内容与 blob 完整保留，不进入任何清理。
  - 文件不再算作本轮资料（审核只认 `AVAILABLE` 的最新厂商文件），厂商不能下载、预览或批量下载；内部账号照常列出（标「已撤回」），可下载、预览。同厂商其他账号看不到它。
  - 留言对厂商显示为「某某撤回了一条留言」占位（无正文、图片）；内部账号仍看到原文和图片，标「厂商已撤回」。撤回的留言不计未读、不可标记已读。
- 仍在两分钟合并窗口内、未被领取的通知摘要会去掉这一条（以条目里该文件 / 留言的唯一链接定位）；去掉后没有条目的摘要改为 `CANCELLED`（原因「通知内容已被撤回」）。已发出或已重试的邮件不变。
- 记 `FILE_WITHDRAW` / `MESSAGE_WITHDRAW` 审计，并形成项目动态「撤回文件 / 撤回留言」；提交后推送实时信号。

## 恢复

- 接口：`POST /files/{id}/restore`、`POST /messages/{id}/restore`。
- 只有撤回它的那个厂商账号本人可恢复，不限时间，只要子项目仍为进行中；仍须持有 `file:upload` / `message:create`。
- 恢复后回到 `AVAILABLE` / `NORMAL`，已读回执保留；文件若属于本轮（编号大于本轮起点）重新计入待审资料。重新开始时的本轮起点包含已撤回文件，所以重新开始之前撤回的文件恢复后仍不算新一轮资料。
- 不发邮件；记 `FILE_RESTORE` / `MESSAGE_RESTORE` 审计与项目动态「恢复文件 / 恢复留言」。
- 历史上已经撤回的复制件仍允许原账号恢复，恢复后不再提供撤回。

## 内部删除

持有 `file:delete` / `message:delete_any` 的内部账号可删除已撤回的文件 / 留言，规则与删除普通内容相同。

## 响应字段

- 文件列表项：`withdrawableUntil`（当前厂商账号可撤回的截止时间，否则 null）、`withdrawn`、`canRestore`。
- 留言：`status`（`NORMAL` / `WITHDRAWN`）、`withdrawableUntil`、`canRestore`。前端只在截止时间前显示「撤回」，到点自动隐藏；以后端判定为准。
