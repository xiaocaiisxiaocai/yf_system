# 厂商联络人与签名契约

> 2026-10-30 起生效。背景：Robot 厂商只开一个登录账号，由多人共用（系统不限制同一账号同时在线）。为了知道每份资料、每条留言由谁提供，并让通知到达每一位实际人员，引入“厂商联络人”。

## 联络人

- 联络人挂在**供应商（厂商）**下，不挂在账号下：表 `supplier_contacts`（姓名 1–32 字、邮箱、排序、启用/停用）。同一供应商下姓名唯一（按数据库排序规则比较，忽略大小写与全半角）。
- 只由公司内部拥有 `supplier:manage` 的账号维护（“供应商管理 → 联络人”）。每个供应商最多 100 位。
- 联络人**不能删除，只能停用**：签名、Robot 负责人选择都引用它。删除供应商时（此时已不允许存在项目）一并删除其联络人。
- 接口：`GET/POST /api/v1/admin/suppliers/{id}/contacts`、`PUT /api/v1/admin/supplier-contacts/{id}`、`PUT /api/v1/admin/supplier-contacts/{id}/status`。审计 `SUPPLIER_CONTACT_CREATE` / `SUPPLIER_CONTACT_UPDATE` / `SUPPLIER_CONTACT_STATUS`（`target_type=supplier`）。
- 项目选择用接口 `GET /api/v1/supplier-contacts?supplierId=`：仅公司内部且具备 `project:list` 的账号可用，返回 `{id,name,enabled}`（含停用的，供表单显示原已选中项）。**供应商账号不能列出联络人**：签名靠手动输入后与名单核对，名单不交给供应商。

## Robot 负责人

- 主项目的 Robot 负责人改为从**该主项目供应商的联络人中多选**（1–10 位），请求字段 `robotOwnerContactIds`，取代原自由文本 `robotOwnerName`（请求中不再接收）。
- 新选中的联络人必须是启用状态；原已选中、后来被停用的联络人可以保留。联络人必须属于主项目的供应商。
- 关联保存在 `project_group_robot_owners`（按选择顺序）；`robot_owner_name`（主项目和子项目，长度放宽到 512）继续保存按顺序用“、”连接的姓名快照，所有列表、详情和复制逻辑照旧读取它。主项目响应新增 `robotOwnerContactIds`。
- 联络人改名时，自动刷新引用它的未完成主项目及其未完成子项目的快照，不改变它们的 `updatedAt`（不会让编辑者遇到版本冲突）；已完成子项目保留验收时的名字。
- 历史主项目没有关联的联络人，`robotOwnerContactIds` 为空；下一次编辑主项目资料时必须选择。
- 本节取代 [Robot 负责人](Robot负责人-2026-10-09.md) 中“自由文本、必填、不超过 64 字”的规定。

## 签名（留言与上传）

- 签名是**手动输入的提供人姓名**，不是手写，也不从下拉选择。服务端去掉首尾空格后与该供应商**启用中**的联络人姓名比对，比对成功才保存，并记录联络人 ID 和登记的姓名写法。
- 规则：
  - 供应商账号留言（`POST /projects/{id}/messages` 的 `signerName`，JSON 或表单字段）和上传（`POST /uploads/init` 的 `signerName`）时，若该供应商至少有一位启用的联络人，签名**必填**；为空返回 400“请填写签名（提供人姓名）”，对不上返回 400“签名「X」不是该供应商登记的联络人，请核对姓名”。
  - 该供应商没有任何启用联络人时，可以不签名（兼容尚未维护联络人的厂商）。
  - 公司内部账号一人一号，不签名；即使传了 `signerName` 也忽略。
- 上传签名在创建上传会话时核对并保存；续传沿用会话创建时的签名；合并时写入文件。复制子项目时，复制出的文件保留原签名快照。
- 留言重放（相同 `clientMessageId`）时签名也参与内容比较，不同则返回 409。
- 留言响应新增 `signerName`，文件列表新增 `signerName`；界面在留言正文下显示“— 姓名”，文件列表“上传人”显示为“姓名（登录账号）”。网页端不记住签名：留言发送成功后清空，上传对话框每次打开都是空的，每次都由实际提供人重新输入。
- 存储：`messages`、`upload_sessions`、`files` 新增 `signer_contact_id`（外键，限制删除）和 `signer_name`（快照）。

## 邮件

- 发给供应商一方的项目邮件（新留言、新文件、验收结果、资料确认等）改为发给**该供应商所有启用的联络人**，不再发到共用账号的邮箱；没有启用联络人时仍发到账号邮箱。
- 每封邮件仍挂在一个有项目访问权的供应商账号下，发信前照旧复核该账号的启用状态和项目访问权；同时复核收件地址仍是该供应商某位启用联络人的邮箱，联络人停用或改邮箱后，尚未发送的邮件取消（“收件账号或地址已失效”）。
- 留言与文件的 2 分钟合并窗口按（子项目，收件账号，联络人）分别合并。

## 共用账号的已知限制

- 审计日志、项目动态、提交验收等记录到的操作人仍是共用账号；签名只说明“由谁提供”，是自报身份，系统无法验证。
- 改密码会让所有共用者下线；无法单独收回某一个人的访问，只能改密码。
- 同一账号最多同时保持 `App:MaxActiveSessionsPerUser`（默认 20）个登录会话，超过时最早的会话被挤下线。
