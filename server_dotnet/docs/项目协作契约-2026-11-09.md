# 项目协作契约

自 2026-11-09 起取代[主项目与子项目协作契约](主项目与子项目协作契约-2026-09-16.md)。设计记录见 `docs/superpowers/specs/2026-11-09-remove-subprojects-design.md`。

## 数据归属

- 项目是唯一层级。主项目 / 子项目两级结构已删除（迁移 `RemoveProjectGroups` 删除 `project_groups` 及其工令号、Robot 负责人、状态历史表和 `projects.project_group_id`）。
- 项目本身维护工令号、机型、Robot 厂商（供应商）、料号与型号、Robot 类型、Robot 负责人（`project_robot_owners`，1–10 位联络人，`robot_owner_name` 为姓名快照）、负责人、课别、优先级、需求完成时间和项目说明。
- 文件、留言、截图、已读回执、动态、复制履历和资料确认结果都按项目 ID 保存。
- 新项目的负责人由服务端绑定为创建人，课别按创建人自动带出，允许为空。负责人只能通过专用接口变更。
- 项目完成时记录 `projects.completed_at`，重开时清空。

## 访问范围

- 公司内部：所有能登录且拥有 `project:list` 的内部账号都能查看全部项目（列表、详情、文件、留言、动态、复制履历）。`project:view_all` 已退役。
- 供应商：以企业为边界。关联供应商下所有启用账号可见该供应商的项目。
- 只有当前负责人（`responsible_user_id`）可以写项目：
  - 编辑资料
  - 终止 / 重新开始
  - 资料确认 OK、退回资料、重开
  - 上传文件、续传或取消上传
  - 发留言
  - 删除文件、留言
- 非负责人的内部账号一律只读。这些写接口返回 `403`“仅项目负责人可以操作该项目”，并且在获取项目行锁之前就会拒绝。删除文件这类按 404 隐藏的接口仍返回 `404`。
- 负责人转交后，原负责人（包括原创建人）失去写权限。
- 项目响应带三个布尔字段，供前端决定显示哪些按钮：
  - `canManage`：调用者是当前负责人。
  - `canTransfer`：调用者是负责人，或是该项目课别 / 上级部门 / 事业部的主管或系统管理员。仍需同时具备 `project:transfer`。
  - `canDelete`：调用者是主管或系统管理员，并且项目已终止。
  - 这三个字段对供应商恒为 `false`。

## 创建即开始

- `POST /api/v1/projects` 一次写入项目、工令号、Robot 负责人和一条 `START` 状态历史（`from` 为空，`to` 为 `IN_PROGRESS`）。审计依次记录 `PROJECT_CREATE` 和 `PROJECT_START`，并发出一封“开始项目”供应商邮件。
- 没有草稿状态。`DRAFT` 已删除；迁移把存量草稿改为 `TERMINATED`。
- 创建时执行与“重新开始”相同的前提校验。任一不满足即整体拒绝，不写入任何数据：
  - 负责人（即创建人）必须是启用且拥有 `project:list` 的内部账号。
  - 供应商必须存在且启用。不存在或已停用在字段校验阶段返回 `400`“供应商已被停用”。
  - 供应商必须至少有一个启用账号。否则返回 `409 / 40901`：“项目所属厂商尚未添加启用的用户，请先添加或启用厂商用户后再开始项目”。
  - 至少一个启用账号实际具备 `file:upload`。否则返回 `409 / 40901`：“项目所属厂商的启用用户都没有上传文件权限……”。
- 网页端“新建项目”的确认按钮为“创建并开始”。创建成功后进入 `/projects/{id}?tab=files`。

## 状态与资料确认

| 当前状态 | 操作 | 下一状态 | 执行方和约束 |
|---|---|---|---|
| `IN_PROGRESS` | 资料确认 OK | `COMPLETED` | 当前负责人；资料状态 `PENDING` 或 `RETURNED`；带 `expectedSupplierFileId`；无厂商活动上传 |
| `IN_PROGRESS` | 退回资料 | `IN_PROGRESS` | 当前负责人；资料状态 `PENDING`；原因 1–500 字；带 `expectedSupplierFileId` |
| `COMPLETED` | 重开 | `IN_PROGRESS` | 当前负责人；原因 1–500 字；带 `expectedUpdatedAt` |
| `IN_PROGRESS` | 终止 | `TERMINATED` | 当前负责人，需 `project:status`；无活动上传 |
| `TERMINATED` | 重新开始 | `IN_PROGRESS` | 当前负责人，需 `project:status`；前提同创建 |

- `PUT /projects/{id}/status` 只接受 `TERMINATED` 和 `IN_PROGRESS`（重新开始）。其他值返回“仅允许终止或重新开始项目”。可选的 `expectedStatus` 不一致时返回 `409 / 40903`。
- 资料轮次、`materialReviewStatus`、`latestSupplierFileId`、退回自动失效等规则与 2026-10-31 单关卡流程一致。主项目汇总已不存在。

## 编辑、转交与删除

- `PUT /api/v1/projects/{id}`：只有负责人可以编辑。
  - 请求必须带 `expectedUpdatedAt`。缺少返回 `400`“expectedUpdatedAt 必须为当前项目的 updatedAt”；不一致返回 `409 / 40903`“项目已被他人修改，请刷新后重试”。
  - 已完成或已终止的项目返回 `409 / 40901`“项目已结束，不能修改资料”。
  - 不能更换供应商，否则返回 `400`“项目创建后不可更换供应商”。
- `PUT /api/v1/projects/{id}/responsible`：需要 `project:transfer`，并且调用者是负责人、所属组织主管或系统管理员。不满足返回 `403`“仅项目负责人、所属组织主管或系统管理员可以变更负责人”。可选的 `expectedResponsibleUserId` 不一致时返回 `409 / 40903`。
- `DELETE /api/v1/projects/{id}`：
  - 只有已终止的项目可以删除，否则返回“仅已终止项目可以删除”。
  - 删除权限属于系统管理员和所属组织主管。显式授予的 `project:delete` 仍是覆盖手段。
  - 以下情况返回 `409 / 40901`：仍有进行中的上传、复制任务未结束、已被复制出副本。
  - 删除时一并清除文件、留言、上传记录、动态和状态履历，与原子项目删除规则相同。

## 复制

- `POST /api/v1/projects/{id}/copy`（202，后台任务）：任何拥有 `project:create` 的内部账号都可以复制任一可见项目，来源状态不限。
  - 副本由复制人负责，课别取复制人的课别。
  - 副本立即为 `IN_PROGRESS`，写入 `START` 状态历史，审计记录 `PROJECT_COPY` 和 `PROJECT_START`，并发出开始邮件。
  - 供应商前提在受理时和提交时各校验一次。
- 复制内容：公共资料、Robot 负责人和当前文件。复制来的 S2C 文件计入 `material_file_floor`，不会成为本轮待确认资料。留言、资料确认结果、已读回执和通知不复制。
- `GET /api/v1/project-copy-jobs` 列出调用者自己的复制任务。`GET /project-copy-jobs/{jobId}` 查询单个任务。响应不再包含 `projectGroupId`。
- 复制履历与文件映射（`/projects/{id}/copy-history`、`/project-copies/{copyId}/files`）在两端项目都可见时返回。内部账号可见全部项目，因此都能读取。

## 列表、工作台与通知

- `GET /api/v1/projects` 支持以下参数：`page`、`pageSize`、`keyword`、`status=IN_PROGRESS|COMPLETED|TERMINATED`、`supplierId`、`materialState=NO_MATERIAL|PENDING|RETURNED`、`overdue=true`、`mine=true`（只看我负责的）。
- 工作台待办、未读计数、协作通知和内部邮件只覆盖调用者负责的项目。供应商仍按企业范围计算。别人的项目可以查看，但不产生提醒。
- 实时推送按项目受众发送：供应商账号、负责人和全部内部可见账号。推送只带变更类型，客户端收到后通过 REST 重新拉取。

## 已删除的接口

- `/api/v1/project-groups` 及其全部子路由：
  - 列表、详情、编辑、删除
  - `/projects`
  - `/responsible`
  - `/copy-jobs`
- 草稿相关行为：草稿禁言、草稿文件对供应商隐藏。

## 迁移

- `RemoveProjectGroups`：
  - 把主项目的 Robot 负责人复制到每个项目。
  - 按状态历史补齐 `completed_at`。
  - 把 `DRAFT` 改为 `TERMINATED`。
  - 删除 `project:view_all` 权限及其授权。
  - 删除主项目相关表和列。
- 开发库直接重建，不保证旧数据兼容。`Down` 为每个项目重建一个同 ID 的主项目，用于迁移回滚验证，不恢复 `project:view_all`。
- 审计日志页仍能显示历史的 `PROJECT_GROUP_*` 动作。对象类型 `project_group` 显示为“主项目（已停用）”。
