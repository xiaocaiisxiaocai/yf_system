# Robot 类型字典

> 2026-10-08 起生效。补充 [Robot 料号与创建人负责制](Robot料号与创建人负责制-2026-09-23.md) 中“`project-dictionaries` 仅支持 `PRIORITY`”的约定。

## 字典

- `project-dictionaries` 支持 `PRIORITY` 和 `ROBOT_TYPE` 两种类型，其他值返回 400（“type 仅支持 PRIORITY 或 ROBOT_TYPE”）。两者都不支持 `parentId`。
- Robot 类型是独立的一组选项，所有 Robot 厂商共用，不按厂商区分。读写模型、名称唯一（同类型内）、排序、停用、权限（`dict:manage`）与优先级完全一致。
- 被任一主项目或子项目引用的 Robot 类型不能删除（409），可停用；停用后历史项目继续显示原名称，新建或改选时不能再选择。
- 迁移 `SeedArmCatalogAndRobotTypes` 预置 5 个 Robot 类型：六轴、三轴、四轴、SCARA四轴、蜘蛛手（见 [Robot 手臂料号目录补充](Robot手臂料号目录补充-2026-10-08.md)），已存在的同名类型保留原状态，不重复插入。缺少启用的 Robot 类型时，新建主项目弹窗提示“暂无启用的 Robot 类型，请在数据字典中维护”。
- 数据字典页（`/system/dictionaries`）的第一个、默认标签为“Robot 类型”，其后为“Robot 料号”“优先级”。

## 项目字段

- 主项目与子项目各有可空列 `robot_type_id`，外键指向 `project_dictionaries`（Restrict）。迁移 `AddProjectRobotType` 只加列、索引和外键，不回填历史数据。
- `POST/PUT /api/v1/project-groups` 请求新增 `robotTypeId`，为必填（缺失返回 400“请选择 Robot 类型”）；必须是 `ROBOT_TYPE` 类型的字典项，新选的值必须为启用状态，保留原值时允许已停用。
- 历史主项目的 `robotTypeId` 为空；下一次编辑主项目资料时必须补选。
- 主项目、子项目和列表响应新增 `robotTypeId`、`robotTypeName`。
- Robot 类型属于主项目公共资料：新建子项目继承；修改主项目时同步到所有未完成子项目，已完成子项目保留验收时的快照；复制子项目时副本继承主项目当前值。
- 复制前的资料完整性检查包含 Robot 类型：主项目或源子项目没有 Robot 类型，或该类型已停用时，复制返回 409，需先补齐主项目资料。
- 主项目更新审计 `PROJECT_GROUP_UPDATE` 的变更列表包含 `robotTypeId`（标签“Robot 类型”）。
