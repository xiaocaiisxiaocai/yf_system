## 核对口径

路由、业务行为、数据库副作用与运行环境分别检查。Rust 中的旧缺陷不作为必须复制的契约；.NET 已明确加强的权限控制和独立数据库迁移流程保留。没有以编译通过或接口数量一致代替业务完整性结论。

静态提取 Rust 注册的 80 个业务 HTTP 方法/路径，与 .NET 独立契约的 80 项逐项一致，另有 `/health`。本轮不把该提取程序加入正式测试依赖；.NET 正式测试继续使用自己的契约文件。[本机路由对照明细](../../.runlogs/backend-completeness-route-map.json)。

## 历次确认的问题与补齐

1. 用户部门的显式 `null` 与字段省略在 .NET 中混淆，导致前端清空部门无效；用户更新审计也缺少前端使用的修改字段和部门变更详情。同步修复显式 `roleId: 0` / `roleIds: [0]` 被当成未修改角色的问题，统一返回参数错误。
2. 上传初始化的 COMMIT 失败后，若查询最终结果也失败，原实现可能把“未知”当成“成功”。只有复核确实存在才可返回成功，未知时保留目录并返回错误。
3. 邮件等待 SMTP 时长期占用连接池。改为短连接读取/认领，释放连接后发送，最后重新取得连接并按租约更新结果。交叉复核还发现租约写入使用应用机时间、到期判断却使用数据库时间；现在租约和失败退避均使用数据库时钟，认领与读取租约在同一短事务内完成。
4. 系统配置按大小写敏感的字符串校验，但 MySQL 按不区分大小写/重音及尾部空格的规则匹配键。名称别名可能绕过内部参数保护、数值范围和重复键检查；现在先规范化 ASCII 参数名再统一校验。
5. 日志查询漏掉 Rust 对粘贴文本首尾空白的处理，导致有记录却搜不到；恢复相关过滤项的 trim 行为，并补齐 category 分类的同类处理，避免带空白时静默扩大查询范围。

6. 项目留言、提交/撤回以及上传文件通知未与 .NET 的项目查看权限对齐。只有 `project:confirm`、没有 `project:list` 的成员仍可能收到项目名/文件名，却不能打开项目；现在普通收件人必须具有查看权限，提交待办另需确认权限。原提交者接收自己提交结果的既有规则保留。

7. 后续结构预检已从表列名称检查扩展为完整列定义、字符集/排序规则、主键/唯一键/索引/外键及迁移历史检查。已有第16版接管也必须在首次写入之前完成检查；异常结构前后快照不变。详见[数据库结构校验说明](../../docs/数据库结构校验及补测合并说明-2026-09-12.md)。

8. 全栈收尾修正匿名未知路径错误进入登录页、留言输入框按 UTF-16 提前截断含表情字符的合法4000字文本、留言发送失败产生未捕获 Promise 异常；不改变后端业务接口。

## 有意保留的差异与边界

- .NET 对 `project:list`、工作台、管理域和预览类型的额外限制是权限修复，不按 Rust 的宽松行为回退。预览是传输可读文件字节，不提供 DRM 式防保存保证。
- 数据库初始化/升级由 .NET 显式命令执行，启动不自动 DDL。支持接管旧第 16/17 版结构；第 15 版及更早的有损工作流转换仍明确拒绝，需另外准备数据转换方案。旧迁移表仅保留来源历史，不调用 Rust 迁移器。
- 邮件保持至少一次投递语义；SMTP 接受后数据库不可用或进程崩溃仍可能需要人工核查，不承诺跨 SMTP/MySQL 的严格一次投递。
- 普通文件下载后端按流传输，但当前前端仍通过 Blob/ArrayBuffer 完整缓冲。PDF/Excel 预览限制 50 MiB、ZIP 输入限制 256 MiB；普通超大文件的浏览器内存容量未在本轮验收，这不是缺失后端接口。
- 本轮核对源码与本机隔离行为，不切换正在运行的业务实例，不操作正式数据、目标 IIS 或真实收件邮箱。源代码功能迁移、已有生产数据接管、服务器发布验收是不同事项。
- 之前的发布验证 ZIP 对应 `65921bb` 基线，不包含本轮后续修复；需要部署时应从本轮最终提交重新生成发布包。
