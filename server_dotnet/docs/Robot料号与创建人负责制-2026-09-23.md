# Robot 料号与创建人负责制

本契约取代旧版独立 Robot 厂商/型号字典及手动选择主项目负责人的约定。

## 数据层级

- Robot 厂商直接使用供应商 `supplierId`，不再建立第二套厂商字典，也不再提供重复的“关联供应商”选择器。创建后不得更换，以免改变已有文件和留言的供应商访问范围。
- 主项目统一维护工令号、机型、Robot 厂商、料号、型号、负责人、课别、优先级、需求完成时间及说明。
- 新主项目的负责人由服务端设置为通过事务内校验的创建人。客户端不能指定负责人；编辑主项目不更换负责人。旧项目保持原有负责人，不因升级或编辑而转交；只能由拥有 `project:transfer` 的账号显式变更，见[项目负责人转交与数据字典权限](项目负责人转交与数据字典权限-2026-09-23.md)。
- 课别由创建人的有效直属课别带出；没有课别时允许创建并显示“未设置”。不猜测组织，不允许客户端指定课别。
- 新建或复制子项目继承主项目负责人及公共资料。子项目创建人与主项目负责人可能不同，创建子项目不会接管主项目。
- 主项目更新时，未完成子项目同步业务资料和工令号；已完成子项目保留原有业务资料。现有状态、访问权限及验收门禁继续生效。

## 请求和响应

`POST /api/v1/project-groups` 创建主项目及初始子项目：

- `name`：主项目名称。
- `supplierId`：启用的 Robot 厂商（供应商）ID。
- `workOrderNos`：至少 1 项、最多 50 项；逐项 trim、忽略空白、按不区分大小写去重，每项最多 128 个字符。
- `machineModel`：trim 后 1–128 个字符。
- `robotPartId`：所选厂商下启用的料号 ID。
- `priorityId`：有效优先级 ID。
- `expectedCompletionDate`：严格的 `yyyy-MM-dd`，界面统一称为“需求完成时间”。保留原接口字段名及数据库日期列，原日期值不变。
- `subprojectNames`：至少一个子项目名称。
- `description`：可选说明。

不再接受 `robotVendorId`、`robotModelId`、`responsibleUserId` 作为元数据输入。型号由服务端根据 `robotPartId` 读取，不能通过客户端提交型号覆盖目录。

响应使用 `supplierId/supplierName` 表示 Robot 厂商，提供 `robotPartId`、`robotPartNumber`、`robotModelName`，并保留负责人、课别及日期字段。

`PUT /api/v1/project-groups/{id}` 保留供应商和负责人。旧项目没有对应料号时可继续保留旧型号；选择新料号后采用新目录的型号。跨厂商料号必须拒绝，即使请求绕过界面。禁用项不能用于新建，编辑原项目可保留已有禁用项。

`POST /api/v1/project-groups/{id}/projects` 与 `PUT /api/v1/projects/{id}` 仅接受子项目名称及说明。存在待验收子项目、主项目已完成或已终止时，继续拒绝修改主项目公共资料。

## 料号目录和优先级

“数据字典”保留优先级，并提供 Robot 料号目录管理。Robot 厂商在“供应商管理”维护。

- `GET /api/v1/robot-parts?supplierId=...&enabledOnly=true|false`
- `POST /api/v1/robot-parts`
- `PUT /api/v1/robot-parts/{id}`
- `DELETE /api/v1/robot-parts/{id}`
- `GET /api/v1/robot-part-supplier-options`：供目录维护返回 `{id,name,status}[]`，包含禁用供应商，仅向有 `dict:manage` 的内部用户开放；不要求额外的供应商管理权限。

料号写入字段为 `{supplierId,partNumber,model,sortNo,enabled}`；响应补充 `{id,supplierName,inUse}`。同一厂商的料号唯一。已引用的料号不能更换厂商、修改料号/型号或删除，可修改排序、停用。停用不会擦除历史项目显示，也不能通过修改目录重写已验收项目的型号。

目录管理使用 `dict:manage` 权限（原为 `config:manage`，见[项目负责人转交与数据字典权限](项目负责人转交与数据字典权限-2026-09-23.md)）；项目表单读取选项使用原有内部项目元数据权限，不向供应商账号开放全局目录。供应商项目访问仍按 `supplierId` 隔离，不因厂商字典退出而放宽。

`project-dictionaries` 仅支持 `PRIORITY`，不再支持 `ROBOT_VENDOR` 和 `ROBOT_MODEL`。（2026-10-08 起另支持 `ROBOT_TYPE`，见 [Robot 类型字典](Robot类型字典-2026-10-08.md)。）

## Excel 初始化和升级

初始化来源为 `SAC常用六軸手臂料號規格-2026-9-23.xlsx` 的“六軸”工作表：品牌 → 供应商，料號 → 料号，SAP品名規格（最新） → 型号。合并单元格中的品牌只在原合并区域内展开，空白分隔行跳过；B11 料号末尾制表符清除。完整 SAP 名称保留，不从中猜测或提取短型号。

版本化数据在 `Yf.Api/Data/robot-parts-20260923.json`，包含来源文件 SHA-256、工作表、列映射及逐条 Excel 行号。

迁移按准确名称复用供应商，保留已有供应商状态；名称不匹配时新增。**“络石”不会自动并入“珞石”**，以免改变旧项目及供应商账号的归属。业务上确需合并时，应另行确认准确目标及账号/项目迁移范围。

升级先保存旧项目的型号文本，再移除旧厂商/型号外键及字典记录。原项目供应商、负责人、日期、文件、留言及验收记录不改变。旧型号不会被猜测成某个 SAP 料号；未匹配时 `robotPartId/robotPartNumber` 为 null，型号显示保留文本。

空库初始化通过 EF Core 迁移载入目录；已有数据库须显式执行 `--migrate-database`。正常启动不自动升级非空数据库。升级前备份指定数据库，禁止对没有 EF 历史的旧库强制补历史或重建。

旧厂商/型号字典退出后，回退旧版本需要同时恢复升级前数据库备份及旧程序，不能仅切换程序文件或伪造旧字典 ID。

显式的开发数据重置会在清理业务数据后重新初始化这 7 个厂商、27 个料号；检查计划会列出目录数量及重建说明。正常升级不执行开发重置。

## 验证要求

覆盖创建人绑定、管理员无课别、编辑不接管项目、跨厂商/禁用料号拒绝、切换厂商后清除旧料号和型号、迟到响应不污染新厂商、旧型号保留、完成子项目快照、fresh/upgrade 迁移、重复迁移不重复导入和供应商访问隔离。
