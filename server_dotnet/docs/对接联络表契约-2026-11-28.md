# 对接联络总表设计契约（Code-First）

**状态**：交互原型与核心边界已确认（单表合一 + 零内置列全动态配置 + 严格按权限控编辑 + 自动合并 + 逐行/批量设置外包可见 + 电话全局联动），正式作为本模块研发与验收基线。

**依据**：与需求方围绕原型及权限/初始化细节逐项确认的业务规则，并严格对齐仓库现有规范（`CLAUDE.md`、`server_dotnet/docs/外协清单契约-2026-11-09.md`、`YfDbContext.cs`、`BootstrapSeedCatalog.cs`）。

## 1. 定位与边界

- **归属业务线**：仅归属 **「ODM/OEM工令协作」**。
  - 公司内部入口：挂载在左侧业务菜单（`WorkOrderLayout.tsx`）下，新增菜单项 **「对接联络表」**（路由 `/outsource/contacts`）。
  - 外包门户入口：挂载在门户菜单（`OemLayouts.tsx`）下，新增菜单项 **「对接联络表」**（路由 `/oem-portal/contacts`），与「外发工令」「文件传递单」并列。
  - **完全独立于 Robot 仿真协作**：不接触 `suppliers` / `supplier_contacts` 表，不向 Robot 供应商展示。
- **业务边界**：
  - **不匹配工令**（独立于 `outsource_items` 与 IPMS 同步）、**没有班次/排班日历**。
  - **零内置表格结构**：系统**不预置任何内置列定义或内置默认行**，所有列布局完全由拥有配置权限的管理员自由创建、命名、调整与删除，单张总表按配置动态承载研发端、生管端、采购端、其他内部部门端以及外包厂商端。
  - **严格按权限编辑**：无相应编辑/配置权限的内部账号只可只读查看、筛选搜索与导出，前端隐藏一切编辑入口、后端全部写接口严格返回 `403`；全部行内容、列布局及内部/外包联系人档案均由**我司内部授权人员统一录入维护**，外包门户端**纯只读**。
  - **厂商主数据唯一来源**：复用 ODM/OEMA 厂商主表 `oem_companies`（外协管理设定 → 厂商与账号）。严禁以自由文本厂商名作为门户隔离与权限判断依据。

## 2. 权限与菜单

沿用系统 Identity 与 `BootstrapSeedCatalog` 中已有的 `outsource` 菜单组（`id = 217`），新增 **2 个动作权限**（内置 `系统管理员` 角色默认全部拥有；新库由 `BootstrapSeedCatalog` 预置，存量库由 EF Migration 按 `code` 幂等写入并授予 `系统管理员`）：

| 权限点 | 说明与涵盖范围 | 典型授权对象 |
|---|---|---|
| （无写权限的启用内部账号） | **仅只读浏览**：进入 `/outsource/contacts` 查看总表、按分组/关键词筛选、只读查看「人员电话库」与引用位置、导出总表 `.xlsx`；前端不展示编辑交互，所有写请求后端直接拒绝（`403`） | 普通内部查询人员 |
| `outsource:contact_manage`（ID `240`，管理对接联络表） | **仅持有该权限才可编辑内容**：新增/复制/移动/删除行、直接编辑单元格（含同步修改合并块）、单行或批量设置「给谁看（可见范围）」、维护人员电话主档（新建/改电话联动/停启用/离职一键交接替换）、下载导入模板及 Excel 预览与导入 | 研发文员、采购、生管或各部门授权维护人 |
| `outsource:contact_settings`（ID `241`，管理联络表列布局） | **仅持有该权限才可改表结构**：在 `outsource_contact_columns` 中新增/删除/重排总表列、改列名与数据类型、切换人员合列/拆列、切换「设为分组列」「相同内容自动合并」与「外包门户可见」开关 | 系统管理员、外协规则配置员 |

- **外包门户权限**：仅启用状态的 ODM/OEMA 厂商账号（`OemAccountActor`，经 `OemAuthorizer.RecheckAsync` 二次核验）可调用 `/api/v1/oem/contacts*`；门户接口只认登录态解析出的 `CompanyId`，不接受前端传参切换或查询其他厂商。

## 3. 核心业务规则

### 3.1 零内置列定义与自动合并单元格规则

1. **零内置列（全动态自由配置）**：
   - 数据库迁移初始化后总表列数与行数为 **0**，不内置任何固定 `col_key` 或表头字段。
   - **空状态交互**：当尚未配置任何列时，无 `outsource:contact_settings` 权限的内部人员看到友好的「管理员尚未配置联络表结构」提示；持有 `outsource:contact_settings` 的管理员直接看到「管理列配置」引导按钮，可逐列自由创建。
   - 管理员自由创建列时可选类型：`TEXT`（单行文本）、`MULTILINE`（多行文本）、`PERSON`（人员与电话，支持合为一列或拆为姓名+电话两列），并独立开关 `auto_merge`（相同内容自动合并）与 `vendor_visible`（对外包可见）。

   > **配置示例（非系统内置，仅说明常见用法）**：管理员可根据需要自行新建诸如 `归属端`（TEXT + 设为分组列 + 自动合并）、`对应课别/岗位`（TEXT + 自动合并）、`当值/对接人`（PERSON 合列）、`对应主管`（PERSON 拆列 + 自动合并）、`职责与要求`（MULTILINE + 自动合并）、`总负责人`（PERSON + 自动合并）、`内部备注`（TEXT + 关掉外包可见）等列，所有列均可随时重命名、调顺序或删除。

2. **可选分组列 (`is_group_column`)**：
   - 任意列均可由管理员按需设为 **分组列**（`is_group_column = true`，全表至多 1 列，也可全表不设，任意列均可随时取消或删除）。
   - **设了 1 个分组列时**：页面顶部自动根据该列去重生成快捷筛选标签、不同分组值切换行之间显示分组分隔线、其余列的自动合并**禁止跨越不同的分组值**，且 Excel 导入支持「按分组值覆盖」。
   - **未设分组列时**：所有启用 `auto_merge = true` 的列纯粹按连续相同非空值合并，顶部不显示分组筛选标签，Excel 导入支持「追加」与「整表替换」。

3. **自动合并计算规则（前后端及 Excel 导出统一口径）**：
   - **空值永不合并**：文本为空白、或人员列表在当前视角下有效人数为 0 时（如未填人员、或外包视角下停用人员被过滤后为空），合并 Key 为 `null`，逐行独立显示 `—`。
   - **合并条件**：仅当列启用 `auto_merge = true` 且相邻行的规范化 Key 完全一致（`TEXT`/`MULTILINE` 为去首尾空白文本；`PERSON` 为顺序一致的 `(personId, prefixLabel)` 序列），且满足分组列边界约束时向下合并 `rowSpan`。
4. **合并格点击编辑语义**：
   - 具备 `outsource:contact_manage` 权限的内部人员点击跨越 N 行（N > 1）的合并格时，编辑器默认勾选 **「同步更新当前合并块的全部 N 行」**；取消勾选时仅更新首行，保存后首行自然从原合并块拆分独立。
   - 不具备 `outsource:contact_manage` 权限的内部账号点击单元格不会打开编辑弹窗。

### 3.2 「不做即隐藏」与外包数据隔离（4 条硬防线）

1. **行级三态可见策略**：
   - `INTERNAL_ONLY`（仅内部可见）：默认新建空白行的兜底状态，对所有外包隐藏。
   - `ALL_VENDORS`（全部外包可见）：所有已启用外包厂商均可见该行。
   - `SPECIFIC_VENDORS`（仅指定外包可见）：仅 `outsource_contact_row_vendors` 白名单内的外包厂商可见；外包接口过滤掉不匹配的行后，若某类业务无匹配行，该块自动消失。
2. **列级可见过滤**：`vendor_visible = false` 的列及「给谁看 / 行操作」管理列在外包门户接口与门户导出中彻底省略。
3. **防泄密强校验（服务端写事务内强制执行）**：
   - 只要某行任一 `PERSON` 列引用了 `scope_type = VENDOR`（归属 `oem_companies.id = X`）的人员档案，则该行的可见范围**必须**满足：
     - `visibility = INTERNAL_ONLY`，或
     - `visibility = SPECIFIC_VENDORS` 且白名单非空、全部成员均等于 `X`。
   - 违反时（包括在行编辑、批量改可见范围、或 Excel 导入时企图将归属厂商 `X` 的人员放入 `ALL_VENDORS` 或含厂商 `Y` 的行），服务端事务拒绝写入并返回 `400` 明确拦截原因。
4. **零敏感信息泄漏**：
   - 外包门户接口 `/api/v1/oem/contacts` 严禁返回 `employeeNo`（内部工号）、内部 `userId`、行级 `vendorIds` 名单或 `INTERNAL_ONLY` 行。

### 3.3 人员电话主档与全局联动

1. **唯一电话数据源**：人员单元格仅存 `outsource_contact_people.id` 引用与可选局部前缀 `prefix_label`；修改人员主档的姓名或电话，总表所有引用该人员的格位即时同步生效。
2. **账号弱关联**：`INTERNAL` 人员支持可选绑定 `users.id`（不强制要求必须有登录账号）；`VENDOR` 人员强制绑定 `oem_companies.id`。
3. **防重与一键交接**：
   - 新建人员时若同归属下已存在同手机号或同名人员，提示优先复用以保证联动生效。
   - 人员库支持反查「当前被引用在总表第几行及对应列名」，并提供**一键离职/调岗交接替换**（支持勾选全部或部分引用行，将 A 替换为同归属且启用状态的接替人 B）。
4. **停用语义**：
   - 停用人员前前端展示当前引用数并建议先一键交接；强行停用后，该人员在内部总表保留显示并标灰警示，在外包门户及门户导出中自动隐藏。
5. **ODM/OEMA 厂商删除保护**：
   - 在现有 `OemDirectoryService.DeleteCompanyAsync` 中增加校验：凡被 `outsource_contact_people` 或 `outsource_contact_row_vendors` 引用的 `oem_companies` 记录，禁止物理删除，仅允许停用。

## 4. EF Core 9 Code-First 数据模型与迁移规范

严格遵循仓库 **Code-First** 约定：
- 实体及 `IEntityTypeConfiguration<T>` 定义放在 `server_dotnet/Yf.Api/Infrastructure/Entities/OutsourceContactEntities.cs`，并在 `YfDbContext.cs` 注册 `DbSet<T>`。
- 单列主键统一使用 C# 属性 `ulong Id`（由 `YfDbContext.OnModelCreating` 自动映射列名 `id`）；时间字段统一 `datetime(3)`（UTC，由 `UtcDatabaseSession` 驱动）；字符集排序规则统一 `utf8mb4_unicode_ci`。
- **严禁手写 DDL 或修改 `__EFMigrationsHistory`**：通过 `YF_EF_DESIGN_CONNECTION` 指向临时空库执行 `dotnet ef migrations add AddOutsourceContacts --project .\Yf.Api` 生成迁移。

### 4.1 实体与表结构（共 6 张表）

1. `OutsourceContactPerson` → `outsource_contact_people`
   - `Id`, `ScopeType (varchar(16))`, `VendorId (ulong? FK oem_companies Restrict)`, `UserId (ulong? FK users SetNull)`, `Name (varchar(64))`, `Phone (varchar(32))`, `Email (varchar(128)?)`, `TitleHint (varchar(128)?)`, `Status (varchar(16))`, `UpdatedBy (ulong?)`, `CreatedAt`, `UpdatedAt`
   - 索引：`uk_ocp_user_id (user_id)`、`idx_ocp_scope_vendor_status (scope_type, vendor_id, status)`、`idx_ocp_phone (phone)`。
2. `OutsourceContactColumn` → `outsource_contact_columns`
   - `Id`, `ColKey (varchar(64))`, `Title (varchar(64))`, `DataType (varchar(16))`, `PersonDisplay (varchar(16))`, `PhoneTitle (varchar(64)?)`, `AutoMerge (bool)`, `VendorVisible (bool)`, `IsGroupColumn (bool)`, `SortNo (int)`, `WidthHint (double)`, `Status (varchar(16))`, `CreatedAt`, `UpdatedAt`
   - 索引：`uk_occ_col_key (col_key)`、`idx_occ_sort (sort_no, id)`。
3. `OutsourceContactRow` → `outsource_contact_rows`
   - `Id`, `SortNo (int)`, `Visibility (varchar(24))`, `Version (uint)`, `CreatedBy (ulong?)`, `UpdatedBy (ulong?)`, `CreatedAt`, `UpdatedAt`
   - 索引：`idx_ocr_sort (sort_no, id)`、`idx_ocr_visibility (visibility)`。
4. `OutsourceContactRowVendor` → `outsource_contact_row_vendors`
   - 复合主键 `(RowId, VendorId)`，FK `RowId -> outsource_contact_rows` `Cascade`，FK `VendorId -> oem_companies` `Restrict`，索引 `idx_ocrv_vendor (vendor_id)`。
5. `OutsourceContactRowValue` → `outsource_contact_row_values`
   - 复合主键 `(RowId, ColumnId)`，`TextValue (varchar(2000))`，FK `RowId -> outsource_contact_rows` `Cascade`，FK `ColumnId -> outsource_contact_columns` `Cascade`。
6. `OutsourceContactRowPerson` → `outsource_contact_row_people`
   - `Id`, `RowId (FK Cascade)`, `ColumnId (FK Cascade)`, `PersonId (FK outsource_contact_people Restrict)`, `PrefixLabel (varchar(32)?)`, `SortNo (int)`
   - 索引：`uk_ocrp_row_col_person (row_id, column_id, person_id)`、`idx_ocrp_person (person_id)`。

### 4.2 迁移与配套门禁更新清单

1. **Migration (`AddOutsourceContacts`)**：
   - `Up()` 建 6 张表；按 `code` 幂等插入权限 `outsource:contact_manage` / `outsource:contact_settings` 并自动授权给内置 `系统管理员` 角色；**不向 `outsource_contact_columns`、`outsource_contact_rows` 或 `outsource_contact_people` 预置任何数据（零内置表格定义）**。
   - `Down()` 删除上述 6 张表，保证往返迁移零残留。
2. **同步更新仓库门禁文件**：
   - `BootstrapSeedCatalog.cs`、`SchemaShapeTests.cs`、`MigrationRoundTripTests.cs`、`tests/Contracts/api-v1.json`、`OpenApiContractTests.cs` 及前端 `npm run generate:api-types`。

## 5. REST API 接口契约与并发/审计

- 内部端端点（`/api/v1/outsource/contacts`）：
  - 只读：`GET /`、`GET /export`、`GET /people`、`GET /people/{id}/references`（任意启用内部账号）
  - 内容管理（`outsource:contact_manage`）：`GET /template`、`POST /rows`、`POST /rows/{id}/duplicate`、`PUT /rows/order`、`DELETE /rows/{id}`、`PUT /cells`、`PUT /rows/visibility`、`POST /people`、`PUT /people/{id}`、`PUT /people/{id}/status`、`POST /people/{id}/handover`、`POST /import/preview`、`POST /import`

- 外包门户端点（`/api/v1/oem/contacts`，`OemUnitOfWork` + `OemAuthorizer.RecheckAsync`）：`GET /`、`GET /export`。
- 审计事件：`OUTSOURCE_CONTACT_ROW_EDIT`、`OUTSOURCE_CONTACT_VISIBILITY`、`OUTSOURCE_CONTACT_COLUMN`、`OUTSOURCE_CONTACT_PERSON`、`OUTSOURCE_CONTACT_HANDOVER`、`OUTSOURCE_CONTACT_IMPORT`。

## 6. Excel 导入导出规范

- **导出（扩展 `SimpleXlsx`）**：支持可选 `XlsxMerge` 输出 OpenXML `<mergeCells>`，自动合并连续相同非空值（不跨分组列合并），`SPLIT` 列拆成相邻两列，保持纯 `t="inlineStr"` 防公式注入。
- **导入（上传 → 预览 → 确认）**：浏览器端基于 `xlsx` 展开 `!merges`、拒收公式与错误值、忽略范例行；按动态表头与 `可见范围` 列映射；支持 `APPEND`、`REPLACE_ALL` 与（有分组列时）`REPLACE_GROUPS`；同名不同号标黄要求显式确认更新电话；事务内强制执行防泄密校验。
- 预览返回待覆盖行数 `replaceCount` 和 `previewVersion`。确认时提交原文件行、匹配选项、模式及该版本。影响导入的列、人员匹配或待覆盖行发生变化后，确认返回 409，界面保留文件与选项，需重新预览并确认电话变更。
- 同一批次按人员最终归属归并同名同号人员。该人员在不同厂商可见行里的引用共用一份电话主档。
