# 账号与厂商 Excel 导入导出契约（2026-11-01）

本功能在公司账号管理、Robot 供应商总表和 ODM/OEM 厂商总表中提供 `.xlsx` 导入与导出。账号和联络人批量操作入口位于对应厂商总表页；供应商/ODM/OEM 厂商必须先存在，数据行通过厂商名称关联，因此可以只给已有厂商补导账号或联络人。OEM 目录沿用现有统一厂商表，当前数据模型没有 ODM/OEM 类型区分。

## 工作簿与列

导入使用模板的 `数据` 工作表；列名与顺序固定，其他工作表可用于模板说明和选项参考。仅接受 `.xlsx`，拒绝公式、重复/未知表头、错误单元格、空文件以及超出上限的工作簿。导入在浏览器解析工作簿，服务端只接收经过业务验证的 JSON 行；服务端仍重新校验每个字段和业务约束。

| 数据范围 | 导入列（按模板顺序） | 导出额外字段 |
|---|---|---|
| 公司内部账号 | 账号、姓名、邮箱（可空）、所属组织、角色、初始密码 | 状态、是否需改密、最近登录 |
| Robot 供应商账号 | 厂商名称、账号、角色、初始密码 | 状态、最近登录 |
| Robot 供应商联络人 | 厂商名称、联络人姓名、邮箱、排序 | 状态 |
| OEM/ODM 厂商资料 | 厂商名称、备注 | 状态、账号数、启用账号数、联络人数 |
| OEM/ODM 厂商账号 | 厂商名称、账号、初始密码 | 状态、最近登录 |
| OEM/ODM 联络人 | 厂商名称、联络人姓名、邮箱、排序 | 状态 |

Robot 和 ODM/OEM 账号都是厂商共用登录凭据，不收集账号个人的姓名或邮箱；联系人姓名和邮箱只在联络人资料维护。通知邮件发送给所有启用联络人邮箱；没有联系人邮箱时不发给该厂商。

每个导入模板的数据表只包含创建记录必须填写的字段；状态、需改密、最近登录、账号数等只读列仅出现在导出表。每个账号或联络人工作表都按“一行一个人”组织；同一厂商有多个账号或联络人时，多行重复填写厂商名称，模板说明页会注明这一关系。导入时厂商名称必须匹配系统中的已有厂商。内部账号模板的“所属组织”填事业部、部门或课别的名称（2026-11-03 起；部门或事业部主管可以只属于该层级），不填层级路径；选项工作表列出全部启用组织及其层级和角色名称。若组织名称在任意层级间重名，导入预览会提示先区分名称。旧模板第 4 列名为“课别”，仍按“所属组织”读取。内部账号邮箱可留空，未填邮箱的账号不会收到邮件通知；新增/编辑表单同样可不填邮箱。Robot 账号模板附当前可授予的供应商角色。账号列按文本处理，避免 Excel 去除前导零。

## 冲突与写入

- 先在浏览器显示行预览，再由用户明确确认；预览不写业务数据。
- 以账号作为账号唯一键，以厂商名称作为厂商唯一键。重复源行整组跳过；已有同键记录跳过且不覆盖。服务端提交时重新查重，因此预览后被其他操作创建的记录也会跳过。
- 新账号必须在导入表填写初始密码。批量导入（内部、Robot 供应商、ODM/OEM 账号）的初始密码只校验 5–20 个字符（2026-11-03 起，如 123456 可用）；手工新增和重置密码仍拒绝常见弱密码或简单重复序列。成功创建后 `must_change_password=true`，首次登录必须修改，新密码按完整密码规则校验。导出不含密码、密码哈希或登录令牌；预览表不显示初始密码。
- 导入厂商账号或联络人只会向匹配的已有厂商追加记录，不会要求重传或重建厂商资料。联络人必须填写邮箱。OEM 厂商主档的旧主联系人、电话、邮箱字段及联络人电话列由 `RemoveOemCompanyPrimaryContact` 迁移直接删除，不转换为联络人记录。
- 新账号创建和新厂商创建复用现有单条服务与事务，每行独立提交，批次可能部分成功。响应逐行返回 `CREATED`、`SKIPPED` 或 `FAILED`；重复提交会将已创建行识别为重复并跳过，不产生第二条记录。
- 导入上限为账号/联系人每批 100 行、厂商资料每批 500 行，单个供应商或 OEM 厂商最多 100 位额外联络人，工作簿最大 5 MiB。联系人、邮箱、密码、账号、组织、角色等规则最终以既有服务端验证为准；权限在每行写入时重验。

## 权限

- 公司内部账号：`user:manage`。
- Robot 供应商账号：`supplier:account`，并受现有供应商角色委派边界约束；联络人：`supplier:manage`。
- OEM/ODM 厂商资料和其他联络人：`oem:company_manage`；厂商账号：`oem:account_manage`。账号与联系人导入均按当前选中的厂商进行。
