## 本轮确认并修复的问题

| 问题 | 修复及验证方式 |
|---|---|
| 同一项目的旧后台 GET 可覆盖操作后的新状态，操作后刷新还可能被吞掉 | 请求序号保证只采用最新结果；同 ID 乱序回归；403/404 清除旧内容，临时错误保留可重试快照 |
| 留言首次挂载的延迟 effect 会清空用户立即输入的草稿，Ctrl+Enter 因而不发送 | 只在用户或项目真正变化时清空草稿；新增回归取得修复前失败、修复后通过的证据 |
| 仍担任组织主管的账号可删除，留下无效主管 ID | 删除前检查主管关联；保留、补齐 OEM 历史引用保护；真实数据库管理回归 |
| 内部账号误获权限后可以代供应商撤回验收 | 方法入口及事务内都校验供应商身份；仅当前提交者撤回；测试状态、历史、审计及 outbox 不发生副作用 |
| 复制项目未检查关联组织、负责人权限与字典是否仍启用 | 复制前验证有效关联，失效返回 409；真实数据库回归 |
| 复制履历的限制外键导致软删文件物理清理后无法删除元数据，任务反复失败 | 清理实体后，被引用记录转为 PURGED 保留履历，未引用记录仍删除；验证两份物理文件消失、履历保留、下载返回 404 |
| 存储位置比较仅解析最后存在的目录，父级链接可以绕过应用目录与 OEM 备份隔离 | 逐级解析现存链接及目标；3 个失败复现修复后通过，连同文件系统安全测试共 6 项通过 |
| SignalR、审计独立脚本的测试库名过长，超过 MySQL 迁移锁名限制 | 使用短随机库名；初始化失败保留脱敏诊断；真实运行通过 |
| 浏览器/制品验证继承了部分外部 App 配置；宿主早退日志路径错误 | 统一清除两种 App 配置前缀及配置文件/引导密码，修正日志路径；脚本单元测试 |

| 部分测试错误依赖内部代撤；新增 GC 测试占着单连接池调用另一服务 | 改用真正提交供应商并增加内部拒绝断言；在独立服务调用前释放测试连接，保持单连接池限制 |
