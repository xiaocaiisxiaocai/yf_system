# 存储路径页面配置与在线迁移方案

> 状态：**已实施**（2026-10-31，三批一起完成）。确认后本文取代 [OEM 当前集成与部署](OEM当前集成与部署-2026-10-05.md) 与 `deploy/README.md` 中“存储路径由外部配置文件决定”的规定。

## 1. 需求与已确认的决定

| # | 问题 | 决定 |
|---|---|---|
| 1 | 哪些路径改为页面配置 | 协作文件存储 `StorageRoot`、OEM 文件存储 `OemStorageRoot`、日志目录 `LogDirectory` 三项全部 |
| 2 | 迁移方式 | 在线迁移，不停服 |
| 3 | 迁移成功后的旧文件 | 校验后自动删除 |

## 2. 必须留在配置文件中的项

数据库连接串、`JwtSecret` 等启动前就要用的项仍放在外部配置文件中：程序要先连上数据库，才能读到页面配置的路径。

配置文件里的三个路径改为**仅首次初始化使用的初始值**：
- 数据库中还没有路径记录时（新库首次启动、或升级到本版本的第一次启动），用配置文件的值写入数据库。
- 之后一律以数据库为准；配置文件的值与数据库不一致时，启动日志给出警告，但不覆盖数据库。

## 3. 页面

“系统参数”新增“存储位置”页签，仅限新权限点 `storage:manage`（默认授予系统管理员角色），所有操作写审计。

- 显示三项当前路径、已用空间、目标磁盘剩余空间、迁移状态与进度（文件数 / 字节数、当前阶段、错误信息）。
- “更换路径”：输入新路径 → 后端校验（见 §4）→ 确认对话框写明“迁移期间系统照常使用；完成并校验后将删除旧路径下由系统迁移的文件” → 开始迁移。
- 迁移进行中可“取消”：回到旧路径，删除已复制到新路径的文件。
- 同一时间只允许一项迁移进行。

## 4. 新路径校验（服务端）

页面可以写服务器文件系统，所以校验必须严格；任一项不满足即拒绝，不开始迁移：

1. 绝对路径，本机磁盘（不接受 UNC 网络路径、相对路径、`..`、盘符根目录）。
2. 不在网站目录、`wwwroot`、系统目录（Windows、Program Files、ProgramData 等）之下。
3. 与其他两项路径及当前路径互不包含（不能是彼此的父目录或子目录）。
4. 目录不存在则创建；已存在则必须为空。
5. 以网站运行账号实际写入、读取、删除探测文件成功。程序不能给自己授权：**新目录的 NTFS 权限需管理员事先授予 IIS 应用池账号**，校验失败时页面提示原因。
6. 目标磁盘剩余空间 ≥ 当前已用空间 × 1.1 + 1 GiB。

## 5. 在线迁移设计（协作存储与 OEM 存储）

协作文件内容按 SHA-256 存放、写入后不再修改（`blobs/sha256/`），适合在线复制。迁移分四个阶段，状态持久化在数据库，进程重启后从断点继续：

1. **双根阶段**：开始迁移即生效。
   - 新写入（上传分片、合并后的 blob、留言图片、复制任务等）一律写到新路径。
   - 读取先找新路径，找不到再找旧路径。
   - 垃圾回收删除时两边都删。
   - 为此后端所有直接拼接存储根目录的代码（约 75 处）统一改走一个路径解析服务。
2. **复制**：后台按清单逐个把旧路径文件复制到新路径（先写临时文件，校验后改名），已存在且校验一致的跳过。
3. **校验**：
   - blob 按文件名中的 SHA-256 重新计算比对；其他文件（上传分片、元数据旁文件、OEM 文件）按大小 + SHA-256 比对。
   - 全部通过后再扫描一次旧路径，补齐复制期间新增的文件。
4. **切换与删除**：
   - 切换：数据库路径改为新路径，结束双根阶段。
   - 删除：只删除**复制清单中、且新路径已校验一致的文件**，不对旧目录整体递归删除；旧目录里的非系统文件保留并在页面列出。
   - 删除完成后写审计 `STORAGE_MIGRATION_COMPLETE`。

OEM 存储沿用同一流程，并保持现有约束：OEM 文件只放 OEM 存储；完整性 / 格式校验状态不变；恢复后对账标记（`--oem-mark-restored`）照常工作。

## 6. 日志目录

日志不需要校验内容：
- 切换后新日志立即写到新目录（运行中重建日志写入器，无需重启）。
- 旧日志文件移动到新目录。
- 当前正在写的文件在切换后关闭再移动。

## 7. 对部署与运维脚本的影响

- `install-iis.ps1`：首次安装仍从配置文件取路径并授予 NTFS 权限。
- `maintain-iis.ps1` 备份 / 恢复：改为从数据库读取当前有效路径，配置文件的值只作首次初始化。
- 备份恢复到另一台服务器、路径不存在时，启动会因存储检查失败而拒绝运行。为此新增命令行 `--set-storage-path <kind> <path>`：只改数据库记录，不迁移文件，用于站点停止时的恢复场景。
- `restart-dev.ps1` 的 `-StorageRoot` 参数改为写入开发库的路径记录。
- `verify-release.py`、`test-deploy-security.ps1` 与相关测试同步调整。

## 8. 风险与对应措施

| 风险 | 措施 |
|---|---|
| 自动删除不可回退 | 只删清单内且新路径已逐个校验一致的文件；删除前再全量校验一次；不递归删目录；每个删除批次写审计 |
| 在线迁移期间并发写入 | 开始即写新路径，读取新旧兼容；复制结束后补扫旧路径 |
| 迁移中途进程重启或断电 | 状态与清单持久化，重启后从断点继续，临时文件改名前不计为完成 |
| 管理员通过页面把路径指向敏感目录 | §4 校验，加专用权限点与审计 |
| 新目录缺少权限 | 写入探测失败即拒绝，提示需先授予应用池账号权限 |
| 单实例约束 | 迁移进度只由当前唯一进程驱动，沿用现有单实例部署约束 |
| 迁移期间性能 | 后台复制限速（默认 50 MiB/s，单线程），不影响在线上传下载；实测吞吐与 CPU 写入验收报告 |

## 10. 实施记录（2026-10-31）

- 表 `storage_locations`（迁移 `AddStorageLocations`，同时新增 `storage:manage` 并授予内置系统管理员）。启动时 `StorageLocationBootstrap` 补齐缺失行并把生效路径写入运行时选项；`--check-development-readiness` 与开发数据重置也按数据库路径执行。
- 运行时：迁移中协作存储的旧根为 `AppOptions.StorageFallbackRoot`，OEM 为 `OemStorageFallbackRoot`。读取经 `FileStorage.ResolveStoredFile` / `FileBlobStore.RootHolding` / `OemStorage.Absolute` 先新后旧；上传会话按目录所在根继续（`FileStorage.SessionRoot`）；用户触发的删除对两个根都执行。
- **与 §5 的差异**：
  - 不另建复制清单。删除阶段对旧目录逐个文件重新比对新目录同路径文件的大小与 SHA-256，一致才删；新目录缺失则先复制校验再删；不一致或被占用的保留并计数。该做法可重复执行，进程重启后不依赖清单完整性。
  - 删除阶段两遍（间隔 30 秒）以捕获切换瞬间在旧根内完成的改名；之后才清除旧根。
  - 迁移期间暂停文件垃圾回收、孤儿扫描、blob 校验、复制任务暂存清理、上传会话保留期清理与 OEM 核对，避免与复制竞争或把仍在旧根的文件判为缺失。
  - “取消”实现为反向迁移：交换新旧路径，把迁移期间写入新目录的内容复制回原目录并校验后删除；删除阶段开始后不可取消。日志目录迁移不可取消（立即切换，随后移动旧文件）。
  - 首次设置 OEM 存储（原为空）记为“待重启生效”，因 OEM 后台任务随进程启动。
- 页面：系统参数新增“存储位置”页签（仅 `storage:manage` 可见），迁移中每 3 秒刷新进度。
- 运维脚本：`maintain-iis.ps1` 读取数据库生效路径，迁移未完成时拒绝维护；Restore 导入后把 `storage_locations` 指向恢复配置的目录；`restart-dev.ps1 -StorageRoot` 通过 `--set-storage-path` 改写开发库路径。
