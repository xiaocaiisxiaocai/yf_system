# 外协清单契约

**状态**：业务规则已与需求方确认。第一至四阶段（设定维护、权限、IPMS 接口预留、汇入、清单、编辑、删除、导出、IPMS 同步、变更履历、发送邮件）已实现；真正的 IPMS 接口待定。IPMS 接口未定，相关条目标注「待 IPMS」。

来源：采购提供的《外协清单模板及系统功能要求简述.xlsx》，以及 2026-11-09 开发与需求方的逐条讨论。

## 定位与边界

- 外发工令用于登记工令级的外发台账，并按厂商分组发送外发邮件。2026-11-26 起与 ODM/OEMA 合并为「ODM/OEM工令协作」，菜单项「外协清单」更名为「外发工令」。
- 不与 Robot 仿真协作、ODM/OEMA 文件传递共用数据：
  - 外发类型字典、类型与厂商对照、默认抄送名单是本模块自有数据。
  - 厂商与联络人（负责人、邮箱）直接使用 ODM/OEMA 厂商目录（`oem_companies`、`oem_company_contacts`），在「外协管理设定」的「厂商与账号」分页维护，外发工令只读（2026-11-17 统一；原外协厂商与联络人表删除，模块尚未上线，迁移时清空了外协记录、发送记录和类型与厂商对照）。
  - ODM/OEMA 厂商被外协记录、类型与厂商对照或发送记录用到时不能删除，只能停用。
- 厂商不登录系统，只通过邮件接收信息。
- 内部账号沿用全系统的 Identity。模块只新增自己的权限点。

## 权限

2026-11-19 起只保留三个权限（见「权限简化」），2026-11-20 新增「导入BOM时间与发图」：

| 权限 | 能力 | 典型角色 |
|---|---|---|
| （不需要权限） | 每个启用的内部账号都能进入模块：查看清单、筛选、导出、看变更履历；填写栏位设定里指定给自己（角色或人员）的栏位 | 全厂 |
| 管理外协清单 `outsource:manage` | 汇入、删除、标记完成与重新开启、立即同步；填写「有管理外协清单权限的人员」可填的栏位 | 采购、生管 |
| 发送外协清单邮件 `outsource:send` | 预览与发送厂商邮件、重新发送、发送记录、待发送数量、无需通知 | 采购 |
| 外协清单设定 `outsource:settings` | 外发类型字典、类型与厂商对照、客户简称、默认抄送名单、IPMS 同步与 IPMS 资料、栏位设定（外发类型及其厂商对照在「外协管理设定」的「外发类型」分页维护，厂商与联络人在「厂商与账号」分页维护） | 采购 |
| 导入BOM时间与发图 `outsource:date_import` | 用 Excel 按工令导入 BOM时间、发图（见「BOM时间与发图导入」）；与上面三个权限互相独立 | 设计 |

- 厂商账号（Robot 供应商、ODM/OEMA 厂商）看不到内部的外协模块；ODM/OEMA 厂商只在厂商门户看自己公司的记录。
- 迁移时，把全部外协权限授予内置「系统管理员」角色，做法与其他模块一致。其他角色由系统管理员在角色管理中分配。
- 外协邮件记录和审计记录沿用现有的业务线范围规则显示。

## 数据与字段归属

一个工令只能有一笔记录（工令唯一）。

| 字段 | 来源 | 可修改者 |
|---|---|---|
| 序号 | 系统：汇入时按文件顺序接着最大序号自动编号（2026-11-16），不重用、不重排，删除后留空号 | 不可修改 |
| 工令 | 生管汇入 | 不可修改 |
| 外发日期 | 生管汇入 | 编辑画面不再修改（2026-11-17） |
| 外发厂商 | 生管汇入 | 采购（必须通过类型与厂商防呆） |
| 外发类型 | 生管汇入时填写（2026-11-13 起不再来自 IPMS） | 采购（必须通过类型与厂商防呆） |
| 客户、机型、机构执行人、工令下发、数量 | IPMS（见下表），由同步维护 | 只读 |
| BOM 时间、发图 | Excel 导入（2026-11-17 起不再来自 IPMS；2026-11-20 起不在编辑画面出现，只能导入） | 有 `outsource:date_import` 的人员，变动进变更履历并使已发送的记录转为「有变更待通知」 |
| 机构课别 | 值为机构执行人所属组织的有效主管：按机构执行人姓名匹配启用的内部账号，兼容简繁体。从所属组织向上查找有效主管，人员本人为主管时显示其上级。机构执行人为空、未匹配到人员、人员有歧义或没有有效主管时留空。 | 只读，清单与导出按当前组织架构显示。同步未结案工令时，若厂商可见的主管与上次通知不一致，已发送的工令转为「有变更待通知」。 |
| 电控执行人 | IPMS 没有，恒为空（2026-11-16） | 只读 |
| 原始交期 | 汇入时 IPMS 取得的原交期 | 一经写入即锁定，之后不再改变 |
| 最新交期 | 汇入时等于原始交期；之后由采购维护，IPMS 同步不会改动（2026-11-16） | 编辑画面不再修改（2026-11-17）；接口仍接受，变动进变更履历并使已发送的记录转为「有变更待通知」 |
| 备注 | 汇入时为空 | 采购 |
| 状态：正常 / 暂停 / 取消 | 默认正常 | 采购（单笔或批量；三种状态之间可任意切换） |
| 转迅得研发电控设计 | 默认否 | 当前外发厂商在厂商门户签名操作 |
| 发送状态：未发送 / 已发送 / 有变更待通知 | 系统维护 | 不可手动修改 |
| 已完成（结案） | IPMS 不提供结案状态，由采购手动标记（2026-11-13） | 采购（单笔或批量；可重新开启） |
| 导入人、导入时间 | 系统：汇入该笔记录的账号与时间（2026-11-17） | 不可修改 |
| 修改人、修改时间 | 系统：最后一次手动编辑或标记完成／重新开启的账号与时间；IPMS 同步与发信不算（2026-11-17）。既有记录按变更履历里最后一笔手动编辑回填 | 不可修改 |

IPMS 字段对应（MES 监控列 → 外协清单列，2026-11-16）：

| 外协清单 | MES 监控 |
|---|---|
| 客户 | 客户名称（`customerName`） |
| 机型 | 机型（`deviceModels`） |

## 外发类型字典与防呆

- 外发类型字典包含代码（如 `OEMA`）、中文名称（如「进料+制造」）、排序和启用状态。界面显示为「代码【中文】」。
- 类型与厂商对照为多对多，由采购在页面上维护，变更不需要修改代码。
- 外发类型只能停用，不能删除；厂商的停用与删除规则见「外协管理设定」的「厂商与账号」分页；类型与厂商对照可以随时调整，已有记录不受影响。
- 初始数据（附件二）：

  | 类型 | 可用厂商 |
  |---|---|
  | ODM-12345【含售前售后】 | 元控 |
  | ODM-2345【不含售前含售后】 | 元控 |
  | ODM-234【含设计】 | 鼎亚、力顺源、华昇智创、多普、合科 |
  | OEMA【进料+制造】 | 鼎亚、力顺源、华昇智创、多普 |

- 防呆规则（2026-11-13 起，外发类型由人工填写）：
  - 汇入时，生管在表格里填写外发类型：必填；接受 `OEMA` 或 `OEMA【进料+制造】`，不区分大小写；必须是启用的字典类型，且该厂商在该类型的可用厂商内。不符则该行报错，不能汇入。
  - 汇入之后，采购可以修改外发类型（单笔与批量）。只要类型或厂商有变化，就按修改后的组合重新校验；不符则拒绝保存。两者都没有变化时不校验（类型已被停用的记录仍可改备注、日期、状态）。
  - IPMS 同步不再读取或改写类型。类型被停用后，该行标记「类型不在字典中」并禁止发送，直到采购改成启用的类型。
  - 类型与厂商对照被调整后，已有记录不受影响，但对不上的行会被标记并禁止发送。

## 汇入

- 模板列（黄色，生管填写）：外发日期、工令、外发类型、外发厂商（外发类型由生管填写，不来自 IPMS）；序号自动编。列按表头名称识别，顺序不限。
- 外协清单、BOM时间与发图、外协邮箱的导入模板均在数据表的表头下放一行范例。导入时自动忽略与范例完全相同的行，并提示「已忽略范例行」。
- 流程沿用现有 XLSX 汇入惯例：上传 → 预览 → 确认写入。
- 预览时按工令批量查询 IPMS，带出只读字段，并执行防呆校验。
- 行级错误（该行不汇入，其余行照常汇入）：
  - 工令已存在
  - IPMS 查无此工令
  - 厂商名不在 ODM/OEMA 厂商目录中（不自动建立厂商）
  - 外发类型未填、不在字典中、或与厂商不符
- IPMS 无法连接：整批拒绝汇入，提示「IPMS 暂时无法连接，请稍后再试」。
- 汇入成功后：所有 IPMS 字段都已完整，原始交期已锁定，发送状态为「未发送」。

## IPMS 同步

- 每天定时同步一次，默认 03:30，可在设定中调整。采购可以对选中的记录或全部记录执行「立即同步」。
- 只同步未结案的记录，按批次查询。外部调用不放在用户请求或业务事务中执行。
- 比较基准是系统中的上一次数据：任一字段变动，该行就标记为「有变更待通知」。即使之后改回原值，也保持待通知，直到采购发送。
- 同步不会自动发信。
- 同步失败（IPMS 无法连接或超时）：保留现有数据，记录失败原因和时间，等下一次定时同步或手动「立即同步」再试。页面显示最后一次成功同步的时间。
- IPMS 不提供结案状态，由采购手动「标记完成」（见下文「手动标记已完成」）。
- 已完成后的行为：
  - 不再同步，也不产生变更通知。
  - 清单默认隐藏，勾选「显示已完成」后才显示。
  - 数据不删除，也不通知厂商。
- 待 IPMS：接口类型、认证方式、从 IIS 服务器能否访问、字段清单、结案状态、调用频率限制、测试环境。连接凭证放在外部配置文件中，不以明文存入数据库。
- 上线前要实测并记录每轮同步的耗时和处理笔数。

## IPMS 资料 Excel 导入（2026-11-23）

- 在 IPMS 资料页的导入对话框内下载模板。模板在表头下包含一行范例，工单号为「示例工单」。导入时自动忽略该工单号的行，并提示「已忽略范例行」。
- `outsource:settings` 人员可在 IPMS 资料页选择 `.xlsx` 文件。浏览器只读取首张工作表，限制 10 MiB、5000 条数据行、256 列。先展开合并单元格，再找出前 6 行中最后一行带有已知叶子标题的行作为表头末行。每列最下方的非空标题是叶子，上方最近的非空标题是分组。唯一叶子直接匹配 MES 字段，重复叶子优先按分组匹配，没有可识别分组时按该标题出现次序匹配。忽略序号，预览可展开查看无法识别的表头。
- 工单号栏必填。空工单号跳过，去掉首尾空白后超出 1–64 字符的工单号按行号和原因显示。识别到的栏位去掉首尾空白，空白格省略，日期按 `yyyy-MM-dd` 或 `yyyy-MM-dd HH:mm:ss` 写入，数字转为无千分位的字符串。工单状态、是否超期、出机状态等已知文字反查成 MES 代码，未知值保持原样。 数字格式的工单号保留 Excel 显示的文字（例如补零格式显示的 `00123`），常规格式的整数按原数字写入，避免出现科学计数法。含 Excel 错误值（如 `#N/A`）的行列为无效行。
- `POST /api/v1/outsource/mes-mirror/import/preview` 接收行号、工单号与 MES 字段和值。预览只读，不占抓取租约，返回新增、无变化、无效、已存在且有差异的工单及 Excel 内重复组。差异针对 Excel 提交的字段，预览显示现有与导入后的客户名称、机型、计划交期和差异字段数。重复组每个工单必须单选一行，选定后才计入新增、无变化或覆盖候选。覆盖候选默认全不选，可逐笔勾选、全选和全不选。
- `POST /api/v1/outsource/mes-mirror/import` 提交原行、覆盖工单号清单和每个重复组选择的行号。两个 POST 的请求体上限为 64 MiB（与站点整体上限相同；前端在 JSON 超过 60 MiB 时直接提示拆分文件），各自复核 1–5000 行、1–64 字符工单号、允许的 MES 字段与每个值 1000 字符上限。预览和确认均返回无效行明细，确认时跳过无效行。缺少重复工单的选择或行号不属于该工单时整次确认返回 400。
- 确认在一个事务内复查权限并锁定 `mes_mirror_state` 的 `id=1`。抓取中或有待确认结果且租约有效时返回 409/40901「IPMS 资料抓取进行中或有待确认的结果，请稍后再导入」。依当前镜像按工单合并，新增缺少的工单，只覆盖明确勾选且仍有差异的工单。未勾选的工单和预览后才出现的冲突保留现有值，完全相同的行计为无变化。
- 空白格保留原值。服务端把 `values` 中的 `null`、空字符串和全空白字符串视为未提供，预览时只比对有值的字段。覆盖时未提供的字段保留原有 JSON 值与类型，客户名称和机型索引列也保留原值。新增只写有值的字段并补 `workOrder`。同步客户名称和机型索引列时沿用 256 字符截断规则。写入批次为 36 字符 `excel-` 加 GUID 的十六进制部分，抓取时间用数据库 UTC 时间，计划交期排序列由数据库计算。确认返回新增、覆盖、跳过、无变化计数，跳过包括无效行、重复组中未选的行及未勾选覆盖的差异工单。审计 `OUTSOURCE_MES_MIRROR` 记录 `trigger="EXCEL"` 及新增、覆盖、跳过计数。
- 导入保留现有行及完整抓取基准 `last_count`、`last_success_at` 等抓取状态。每日默认 03:00（UTC+8）完整抓取成功后仍以 IPMS 资料整表替换，包括 Excel 导入的资料。

## 采购编辑与删除

- 可编辑字段：外发厂商、外发类型、备注、状态，支持单笔编辑和批量修改（BOM 时间、发图自 2026-11-20 起改为导入，见「BOM时间与发图导入」）。外发日期和最新交期自 2026-11-17 起不在编辑画面出现；接口的这两个字段改为选填，缺省保留原值（最新交期不能清空）。
- 编辑带版本检查：数据已被他人修改时，返回 `409 / 40903`「数据已被他人修改，请刷新后重试」，不覆盖。
- 修改已发送的记录后，该行转为「有变更待通知」。
- 编辑或批量修改保存后，弹出「是否批量发送邮件」，进入下文的发送流程。
- 只有采购（编辑与发送权限）可以删除（2026-11-16 起，已发送的记录也可以删除）：
  - 删除后只保留审计记录（含删除时的发送状态），变更履历一并删除；发送记录里仍保留工令号。
  - 删除已发送的记录不会通知厂商，界面会提示且无法恢复；要让厂商知道取消，请改为状态「取消」再发送变更通知。

## 发送

### 分组与收件人

- 采购可在清单中选取记录（包括全选）。服务端按每行的外发厂商分组，每个厂商一封信，每封信只包含该厂商自己的工令。
- 收件地址由服务端根据记录的厂商确定，前端只提交要发送的记录，不能指定收件地址。
- 每封信的组成：
  - To：该厂商的全部外协邮箱（2026-11-20 起，见「外协邮箱」；不再使用 ODM/OEMA 联络人）。
  - CC：默认抄送名单中选了「外发邮件」模块、启用且有邮箱的内部账号，加上这封信的临时抄送。
  - 所有人在同一封信中一起发送，不拆成多封。
- 默认抄送名单：
  - 从启用且有邮箱的内部账号中选择，由采购维护。每人至少选择一个模块，可同时选择「外发邮件」（`OUTSOURCE_NOTICE`）和「转迅得电控」（`ELECTRICAL_HANDOFF`）。
  - 外发通知与换厂商产生的撤回通知自动抄送「外发邮件」模块成员，发送时不能移除。转迅得电控的邮件将该模块成员用作收件人。
  - `GET /api/v1/outsource/settings/default-cc` 的每个账号返回 `modules`。保存用 `PUT`，请求 `{ entries: [{ userId, modules }] }`，传空数组可清空名单。
  - 迁移将现有名单全部设为仅适用「外发邮件」，保留原有抄送行为。
- 临时抄送：
  - 只加在单封信上，不会作用于整批信。
  - 内部人员从账号中选择；客户等外部人员直接填写邮箱。
  - 如果一封信含多个客户的工令，又填了外部地址，提醒一次后才能继续。
- 任何厂商都不得看到其他厂商的存在：邮件内容不含其他厂商的工令，抄送中也不含其他厂商的联络人。
- 不设置 Reply-To；回复由收件人自行处理，与系统无关。

### 二次确认

- 确认窗口逐封列出：厂商名、收件人、抄送、笔数，每封可以展开预览正文。采购确认后才入队。
- 预览后如果数据有变动，确认时要求重新预览。
- 同一次确认只发送一次，重复点击不会重复发送。

### 更换厂商

- 已发送的记录改了厂商后，下一次发送会同时产生两封信：
  - 给新厂商的外发通知。
  - 给原厂商的撤回通知：只说明该工令已取消外发给贵司，不透露新厂商。
- 两封信绑定在一起确认和入队，不能只发其中一封。

### 邮件内容

- 正文为专门生成的 HTML 表格，使用行内样式以兼容 Outlook 等客户端，另附纯文字版本。
- 正文表格列：工令、客户、机型、外发类型、数量、最新交期、状态、备注。
- Excel 附件包含全部字段，只含本封信的工令：
  - 文件名示例：`外发清单_鼎亚_20261109.xlsx`。
  - 附件在确认时生成并固定保存。失败重试使用同一份文件，发送记录中也可以下载。
- 撤回通知只有正文，不附 Excel。
- 颜色规则（系统画面、邮件正文、Excel 附件三处一致）：
  - 整行底色按状态（浅色，2026-11-17）：正常为绿色，暂停为红色，取消为黄色。
  - 变动的单元格另加黄色底色，只显示新值，不显示旧值，不加「变更字段」列。
  - 标黄范围是与上次寄给该厂商的内容相比确实不同的单元格。

### 投递结果

- 邮件在后台排队发送，共用全系统的 SMTP 配置和重试机制。
- 每封信有多个收件人和抄送，需要扩充邮件队列以支持多收件人、CC 和附件。这项扩充只供本模块使用，不改变 Robot 和 ODM/OEMA 现有的邮件规则。
- 部分地址被拒收：跳过被拒的地址，照常发给其他人，标记为「部分送达」并列出被拒地址。
- 厂商收件人全部被拒：整封标记为失败。
- 确认发送时记录就转为「已发送」；外发通知最终失败（含重试用尽、发送中断）时，其中仍为「已发送」的记录回到「有变更待通知」，重新发送该邮件时再恢复为「已发送」（2026-11-16）。
- 发送中断（进程在寄出过程中结束）无法确定厂商是否已收到，邮件不会自动重发，而是标记失败并提示「发送中断，不确定厂商是否已收到」，由采购确认后手动重新发送。
- 同一 `requestKey` 的确认在等待记录锁期间被先到的请求完成时，返回先到请求的结果，而不是要求重新预览。
- 模块内的发送记录显示每封信的状态：排队中、已寄出、部分送达、失败。失败的信可以重新发送。

### MES 数据镜像（2026-11-12）

IPMS 的数据来源确定为「迅得二期」的 MES 监控页。外协清单不再实时查询，而是读取每天抓取到本库的镜像。设计见 `docs/superpowers/specs/2026-11-12-ipms-mes-mirror-design.md`。

- 迁移 `AddMesMirror`：`mes_work_orders`（镜像，工令为主键，保存客户、机型和 MES 返回的整行 JSON）、`mes_work_orders_staging`（抓取暂存）、`mes_mirror_state`（单行状态：租约、最近一次结果、笔数）。
- 配置（外部配置文件 `App:Ipms`，均为可选的默认值，设定页保存的值优先）：`MesBaseUrl`（含端口，如 `http://主机:6001`）、`MesAccount`、`MesPassword`、`MesSyncTime`（默认 `03:00`，业务时间 UTC+8）、`MesPageSize`（默认 100，最大 200）、`MesPageDelaySeconds`（默认 2）、`MesPageTimeoutSeconds`（默认 180）、`MesMinRatioPercent`（默认 50）。
- 流程：每天 `MesSyncTime` 登入 MES，按页顺序抓取，先写暂存表；去重后的工令数等于 MES 的 `total`，且不低于上次成功笔数的 `MesMinRatioPercent`%，才在一个事务内整表替换镜像。每页失败重试 2 次，过期自动重新登入一次；任何失败都保留旧镜像并记录原因。每轮写一条 `OUTSOURCE_MES_MIRROR` 审计。
- `MesMirrorIpmsClient` 读镜像：客户、机型、数量（MES「数量」列，字段 `deviceNum`）、交期（`customerEndDate`，**待确认**）。外发类型不由 MES 提供，改为人工填写；其余 IPMS 字段暂为空。MES 只列出未出机的工令，因此镜像里没有结案信息。
- 外协每日同步默认时间改为 `03:30`，排在 03:00 的镜像之后。
- **手动抓取**（「外发工令设定」→「IPMS 同步」→「MES 数据镜像」，需要 `outsource:settings`）：
  - 可指定每页条数（1 到 200，默认取配置）；「抓取全部」不中断地抓完并通过校验时与定时抓取一样整表替换；运行中可「停止」；「抓取指定页」只抓一页。
  - 停止之后、或抓指定页之后，结果先留在暂存表，由人二次确认：「放弃」（镜像不变）或「合并已抓部分」（按工令更新或新增，不删除任何行；不改「最近成功时间」，更新笔数基准）。等待确认的结果占用抓取租约，60 分钟未处理视为放弃。
  - 同一时间只有一个抓取任务；路由 `GET /api/v1/outsource/mes-mirror/status`、`POST …/run`、`POST …/stop`、`POST …/confirm`；每次手动抓取与确认写审计 `OUTSOURCE_MES_MIRROR`（`trigger=MANUAL`）。
- **MES 地址可在页面更换**（迁移 `AddMesMirrorBaseUrl`，`mes_mirror_state.base_url`）：页面保存的地址优先，留空则用配置 `App:Ipms:MesBaseUrl`；`GET/PUT /api/v1/outsource/mes-mirror/settings`，保存写审计 `OUTSOURCE_MES_MIRROR_SETTINGS`（只记新旧地址）。地址必须是 http 或 https 的完整地址，不含账号密码、查询、片段；抓取运行或等待确认时不允许更改。（账号与密码自 2026-11-13 起也在页面设定，见下文。）
- **测试连接**（`POST /api/v1/outsource/mes-mirror/test`，可带待保存的地址）：用该地址全新登入并抓 1 条，不写任何数据、不保存地址、不替换正在使用的登入状态，只返回成功与否、总笔数、耗时和不含凭证的提示。token 由程序自动登入获取，无需手动取得。
- 安全提示：拥有 `outsource:settings` 权限的人能让服务器向任意 http 或 https 地址发送登入请求（带 IPMS 账号密码），请只授予可信的采购人员。
- 部署注意：MES 是明文 HTTP，专用账号只授予只读权限；抓取一轮预计十几分钟，应避开白天高峰。

### IPMS 连接设定（2026-11-13）

这里的 IPMS 就是「迅得二期」IPMS 系统里的 MES 监控模块，不是另一套系统。界面统一称为 IPMS。

- 设定页「IPMS 同步」分三块：「IPMS 连接」（地址、账号、密码、每日抓取时间，保存、测试连接，显示已设定/未设定）、「抓取资料」（手动抓取全部或指定页、停止、资料笔数与最近结果）、「更新外发工令」（每日同步时间与最近结果）。
- 迁移 `AddIpmsConnectionSettings`：`mes_mirror_state` 增加 `account`、`protected_password`（AES-GCM 加密，密钥由 `App:JwtSecret` 派生，用途 `yf.ipms.mes.v1`，与 SMTP 授权码同一做法 `SecretBox`）、`sync_time`。升级或还原必须沿用原站点的 JWT 密钥，否则已存的 IPMS 密码无法解密（视为未设定，需重新输入）。
- `PUT /api/v1/outsource/mes-mirror/settings` 请求 `{ baseUrl, account, password, syncTime }`：地址或账号留空即清除页面值（改用配置值；清除账号同时清除已存密码）；`password` 为空表示不修改；有密码必须有账号；`syncTime` 为 `HH:mm`，留空不修改。回应 `{ baseUrl, configBaseUrl, saved, account, passwordSet, accountConfigured, syncTime }`，从不返回密码。地址、账号或密码变更时，抓取运行或等待确认中会被拒绝（409）。
- 审计 `OUTSOURCE_MES_MIRROR_SETTINGS` 记录地址、账号、每日抓取时间的新旧值，密码只记「已更改」或「已清除」。
- 测试连接 `POST …/test` 请求 `{ baseUrl, account, password }`：留空的栏位用当前生效的值；输入了其他账号时不会借用已存密码。
- 不再需要 `App:Ipms:Mode=MesMirror`：地址、账号、密码齐备后，每日抓取与外协同步自动生效；未齐备时定时任务跳过，外协同步状态显示未设定。从未成功抓取过资料时，外协清单查询 IPMS 会提示「尚未从 IPMS 抓取资料，请先在设定页抓取」，而不是把所有工令标为查无。
- 登入：地址必须是 IPMS 的接口地址（如 `http://183.238.37.108:6001`），不是网页地址（`6008` 是网页的 nginx，登入接口在那里回 404）。登入回应的 token 在 `data.token.token`（与 IPMS 网页一致，也接受 `data.token` 为字符串）；接口回 HTML 时提示检查地址，IPMS 拒绝登入时显示 IPMS 自己的原因（如「账号或密码错误」）。

### 定时任务的开始与停止（2026-11-13）

- 「抓取资料」与「更新外发工令」各有一个开关（定时抓取、定时同步），切换立即生效；停止后不再在每日时间自动执行，手动抓取与手动同步不受影响；正在执行的那一次会跑完。
- 迁移 `AddIpmsScheduleSwitches`：`mes_mirror_state.schedule_enabled`、`outsource_sync_state.schedule_enabled`（默认开启）。
- 路由：`PUT /api/v1/outsource/mes-mirror/schedule`、`PUT /api/v1/outsource/settings/sync-schedule`，请求 `{ enabled }`，需要 `outsource:settings`；设定与状态回应增加 `scheduleEnabled`。状态有变化时写审计 `OUTSOURCE_MES_MIRROR_SCHEDULE` / `OUTSOURCE_SYNC_SCHEDULE`。
- 确认框按 MES 回传的顺序列出抓到的工令（迁移 `AddMesStagingOrder`：`mes_work_orders_staging.seq` = (页码 - 1) × 每页条数 + 行序），最多显示 200 笔（一页的上限）。
- 后端启动时释放上一个进程留下的抓取租约并清空暂存（等待确认的结果只存在于进程内存，进程重启后无法再确认），避免新的抓取被挡 60 分钟。

### 手动标记已完成（2026-11-13）

- IPMS（MES 监控）只列未出机的工令，不提供结案状态，因此结案改由采购手动标记「已完成」。没有迁移，沿用 `outsource_items.closed_at`。
- `PUT /api/v1/outsource/items/completion`，请求 `{ items: [{ id, expectedUpdatedAt }], completed }`（`outsource:manage`，每次最多 500 条，版本不一致 `409 / 40903`）：`true` 标记已完成，`false` 重新开启；状态没变的记录跳过。
- 已完成的记录：清单默认隐藏（勾选「显示已完成」才显示，整行文字变淡并带「已完成」标签）；不再同步 IPMS；不能编辑、批量修改或发送（`409`「已完成的记录不能修改，请先重新开启」）；不通知厂商；发送状态保持原样。
- 重新开启后恢复同步、编辑与发送。每次变化写变更履历（字段 `completed`「完成状态」，未完成 ↔ 已完成，来源 EDIT）与审计 `OUTSOURCE_ITEM_COMPLETE` / `OUTSOURCE_ITEM_REOPEN`。
- 前端：勾选未完成的记录时工具栏多一个「标记完成」（需确认）；所选包含已完成的记录时显示「重新开启」，只作用于其中的已完成记录。混选时（2026-11-17 起）「标记完成」「发送邮件」「批量修改」「同步所选」只作用于其中未完成的记录，按钮上的数字是实际作用的条数；「删除」作用于全部所选（含已完成，确认框会注明已完成与已发送的条数）。

- 迁移 `AddOutsourceVendorEmails`：建表，并把每家厂商现有启用、有邮箱的联络人邮箱复制一份作为初始外协邮箱，上线后行为不变，再由采购按需修改。
- 权限：读取和写入都需要 `outsource:settings`（与设定页其他分页一致，不再需要 ODM/OEMA 的 `oem:company_manage`）；ODM/OEMA 厂商管理页不再有外协邮箱的入口。
- Excel：分页上的「导入」「导出」，两列：厂商名称、邮箱（同一厂商有多个邮箱时重复填写厂商名称）。导入只新增：厂商必须已存在且启用；文件内重复、厂商已有的邮箱跳过，格式不对的行报错，超过每家 50 个的行报错；最多 500 行。导入弹窗先预览，确认后服务端按锁定的厂商重新核对，所有待导入的行在一个事务里保存。导出文件含全部厂商的外协邮箱。
- 接口（都在 `/api/v1/outsource/settings` 下）：`GET /vendor-emails`、`POST /vendor-emails`（`{ vendorId, email }`）、`PUT /vendor-emails/{id}`（`{ email }`）、`DELETE /vendor-emails/{id}`、`POST /vendor-emails/import`（`{ rows: [{ rowNumber, vendorName, email }] }`）。审计 `OUTSOURCE_VENDOR_EMAIL_CREATE` / `UPDATE` / `DELETE` / `IMPORT`。

### 客户简称（2026-11-17）

MES 监控列表只有客户全称（`customerName`）；「业务中心 → 工单查询」才有客户简称。外协清单因此维护一份「客户全称 → 简称」对照表，清单上的「客户」列、关键字搜索、导出的 Excel 和给厂商的邮件都显示简称，查不到简称时显示全称；清单上鼠标停在简称上可看全称。

- 迁移 `AddOutsourceCustomerAliases`：`outsource_customer_aliases`（全称唯一，简称最多 64 字符，`manual` 标记手动设定）。
- 同步只在设定页「客户简称」分页手动触发（「从 IPMS 同步」，需要 `outsource:settings`），没有定时任务。用 IPMS 连接设定里的同一个账号登入，分页（每页 500 笔）读取工单查询 `POST /xyj-twxd-mes/r/xdSalesOrderItem/querySalesOrderItems`（不带筛选条件，只取 `customerName`、`customerShortName`）。抓取期间不占用数据库连接。
- 规则：同一个全称在不同工单上填的简称可能不同，部分工单的简称栏填的就是全称。每个全称取出现次数最多、且不等于全称本身的简称（次数相同取 IPMS 先列出的）；一个都没有就不建对照。全称超过 128 或简称超过 64 字符的跳过。比较全称时按数据库的排序规则处理：全角与半角（IPMS 同一客户有「（淮安）」和「（淮安)」两种写法）、大小写和多余空格不算不同客户，对照表存 IPMS 先列出的写法；清单按同样的规则匹配简称。
- 同步只新增或更新对照，不删除；手动设定过的简称保留不覆盖。在设定页可逐笔修改简称（标为「手动」），清空则恢复由下次同步决定。
- IPMS 没给简称的客户（简称栏填的就是全称，例如深圳市泰雪科技有限公司）：设定页「缺少简称」列出 IPMS 资料（MES 镜像）与外协清单里出现、对照表中还没有的客户全称及各自的工单数，可直接「设置简称」；也可用「新增」手动加一笔全称和简称。手动新增或编辑过的对照标为「手动」，可以删除；IPMS 同步来的不能删除（下次同步会再出现）。同一客户的另一种写法（全角半角、大小写）已有简称时不能重复新增。
- 路由：`GET /api/v1/outsource/settings/customers`、`GET …/customers/missing`（任一外协权限可读）；`POST …/customers/sync`、`POST …/customers`、`PUT …/customers/{id}`、`DELETE …/customers/{id}`（`outsource:settings`）。审计 `OUTSOURCE_CUSTOMER_SYNC`（笔数、客户数、新增、更新、保留的手动设定）与 `OUTSOURCE_CUSTOMER_ALIAS`。
- 实测（2026-11-17）：工单查询共 8806 笔、139 个客户全称，MES 镜像中的 29 个客户全称都能在其中找到。

### 栏位设定（2026-11-19）

每个栏位由谁填写、厂商能看到哪些栏位，都在设定页的「栏位设定」分页里设定，需要 `outsource:settings`（2026-11-19 起，原来单独的 `outsource:field_settings` 并入此权限）。设定页不能新增栏位（2026-11-19 起）：新栏位随版本由迁移加入，设定页只能编辑、排序和停用已有栏位。

- 栏位按来源分类，每类能设定的内容不同：
  - 固定：工令、转迅得研发电控设计。内部不能编辑，固定对厂商显示。
  - IPMS：客户、机型、机构课别、机构执行人、电控执行人、工令下发、原始交期、数量。机构课别由组织架构匹配，其余由 IPMS 带出；这些栏位不能人工填写，只能设定厂商是否看得到。
  - 流程：外发日期、状态、外发类型、外发厂商、最新交期。只能由内部人员填写，因为它们决定邮件发给哪家厂商、每行显示什么颜色。状态固定对厂商显示。
  - 人工：备注。
  - 导入：BOM时间、发图。
  - 自定义：随版本加入的非系统栏位（如「是否有RobotV」）。类型可以是文字、是/否、日期、数字、下拉选项，名称、类型和选项都可以修改。自定义栏位只能停用，不能删除，已填的值会保留；已经有人填写过的栏位不能再改类型，已经被选用的下拉选项不能删掉。
- 外发日期、状态、转迅得研发电控设计、工令固定排在左侧，其余栏位可以上下调整顺序。外发通知附件使用同样顺序，并排除转迅得研发电控设计。
- 内部填写有四种范围：「有管理外协清单权限的人员」（默认，也就是有 `outsource:manage` 的人）、「指定角色」（只有勾选的角色可以填）、「指定人员」（可以多选，只有选中的人员可以填）、「内部不填写」。系统管理员可以填写前三种范围的栏位；「内部不填写」对系统管理员同样生效（2026-11-20 起，迁移 `StopInternalRobotVEditing` 同时把「是否有RobotV」设为内部不填写，需要时在栏位设定中改回）。这是编辑栏位的唯一关卡：被指定的角色或人员不需要任何外协权限就能填写该栏，也只能填写该栏，不会因此获得汇入、删除、标记完成或同步。「指定人员」的候选列出所有启用中的内部账号；删除账号时，该账号会自动从所有栏位的指定人员里移除。保存时服务端逐个栏位核对：改动了没有权限的栏位，整笔拒绝，提示「无权修改栏位「X」」；没有改动的栏位不检查。编辑框和批量修改框只显示当前账号能填写的栏位；一个能填写的栏位都没有时，编辑按钮停用，也不显示批量修改。
- 厂商可见设定决定厂商门户及其导出的栏位。外发通知的正文、附件和「上次寄出」快照按厂商可见设定取栏位，并排除「转迅得研发电控设计」。已发送记录只有通知字段变化时才转为「有变更待通知」。
- 栏位设定中的通用「厂商填写」仍为预留功能。转迅得电控通过专用操作写入，沿用履历里的 `VENDOR`、`actor_oem_account_id`、`signer_name`。
- 迁移 `AddOutsourceFieldEditorUsers` 新增 `outsource_field_editor_users`，用来保存「指定人员」。迁移 `AddOutsourceFieldSettings` 新增三张表：`outsource_fields`（栏位，`field_key` 唯一）、`outsource_field_editor_roles`（可以填写的角色；删除角色时随之删除）、`outsource_item_values`（自定义栏位的值；没有记录表示空；删除外协记录时随之删除）。迁移按 2026-11-17 的列顺序写入 17 个系统栏位，全部对厂商显示；再在「机型」之后加入第一个自定义栏位「是否有RobotV」，类型是是/否，默认不对厂商显示，由所有有编辑权限的人员填写。所以迁移完成后，大家能编辑的内容和以前完全相同。
- 接口：
  - `GET /api/v1/outsource/fields`（任一内部账号）：清单当前启用的栏位及顺序，每个栏位带 `canEdit`，表示当前账号能否填写。
  - `GET /api/v1/outsource/settings/fields`、`PUT …/fields/{id}`、`PUT …/fields/{id}/status`、`PUT …/fields/order`（都需要 `outsource:settings`）：维护栏位设定。每项修改都写审计：`OUTSOURCE_FIELD_UPDATE`、`STATUS`、`ORDER`。新增栏位的接口 `POST …/fields` 已于 2026-11-19 移除。
  - 单笔编辑 `PUT /outsource/items/{id}` 和批量编辑 `PUT /outsource/items/batch` 新增 `values` 参数，按栏位 key 传自定义栏位的值：不传的 key 保持原值，传空文字表示清空；是/否类型存成 `true`/`false`。清单返回的每条记录都带 `customValues`。
  - 自定义栏位的变更按栏位 key 写入变更履历，显示时用栏位名称。

### 编辑与发送分开（2026-11-19）

- 原来的「编辑与发送外协清单」（`outsource:manage`）改名为「编辑外协清单」，负责编辑、批量修改、标记完成或重新开启、删除和立即同步。
- 新增「发送外协清单邮件」（`outsource:send`），负责预览和发送厂商邮件，以及在发送记录里重新发送失败的邮件。查看发送记录在 2026-11-19 起也需要 `outsource:send`（见「权限简化」）。
- 迁移 `SplitOutsourceSendPermission` 按代码新增权限，并给所有已有 `outsource:manage` 的角色补上 `outsource:send`，所以升级后大家能做的事和以前一样；之后管理员可以把只该编辑的角色上的发送权限去掉。全新安装时，权限由 `BootstrapSeedCatalog` 写入（ID 232）。
- 前端：有 `outsource:manage` 或 `outsource:send` 任一权限都可以勾选记录。「发送邮件」按钮、保存后询问是否发送邮件，以及「重新发送」只对有发送权限的人显示；编辑类按钮只对有编辑权限的人显示。

### 待发送提醒与无需通知（2026-11-19）

- 有 `outsource:send` 权限的人，在业务切换栏的「ODM/OEM工令协作」入口和二级菜单的「外发工令」上会看到一个数字。这个数字是未完成记录中「未发送」和「有变更待通知」的条数，由 `GET /api/v1/outsource/send-queue` 返回，需要 `outsource:send`。数字每分钟刷新一次，浏览器窗口重新获得焦点时也会刷新。数字不为 0 时，点击二级菜单「外发工令」会打开 `/outsource/items?sendQueue=1`，清单自动筛出这些记录。清单工具栏的「待发送」勾选框对应同一个筛选，查询参数是 `sendQueue=true`。
- 发送人可以选择不发：`PUT /api/v1/outsource/items/skip-notice`，需要 `outsource:send`，每笔记录要带版本。只能用在未完成、而且状态是「未发送」或「有变更待通知」的记录上，其他记录会整批拒绝（409）。不会发出任何邮件。
  - 「有变更待通知」改回「已发送」，并把当前厂商可见栏位的内容记成新的「上次寄出」快照，黄色标记清除。
  - 「未发送」改为新的发送状态「无需发送」（`NOT_NEEDED`），不计入待发送数量。黄色标记也清除，因为之前的人工编辑不再标示，只标示之后的编辑。之后再编辑，状态仍然是「无需发送」；之后仍然可以照常发送邮件。
  - 每笔都会写入变更履历（字段「发送状态」，新值「无需通知」）和审计 `OUTSOURCE_ITEM_SKIP_NOTICE`。
- 已经寄出过的记录，只有在厂商可见的栏位又发生变化时，才会再次转为「有变更待通知」。

### 转迅得电控（2026-11-24）

- 「转迅得研发电控设计」是固定栏位，排在「状态」之后。采购清单中，「是」以蓝底深蓝字高亮整格，「否」沿用行底色，撤回后恢复。既有记录、新记录与汇入记录都默认为「否」，汇入模板及流程只处理原有汇入字段。单笔编辑、批量修改及栏位设定对包括系统管理员在内的所有内部账号均不可写，内部填写范围固定为 `NONE`，厂商可见固定开启。
- 内部清单和厂商门户均显示「是／否」，内部清单在「是」上悬停可查看签名与时间。内部和厂商门户导出包含该栏。内部清单响应增加 `electricalHandoff`、`electricalHandoffAt`、`electricalHandoffSigner`，时间与签名保存最近一次转交或撤回。
- 仅当前外发厂商的 ODM/OEMA 账号可对自己公司的记录操作。厂商门户按 `canElectricalHandoff` 在「操作」列显示「转迅得电控」或「撤回」。已完成记录隐藏操作按钮。正常、暂停、取消均可按外发类型的设定操作。确认需输入自由文字签名，去首尾空白后为 1–32 个 Unicode 字符，签名无需匹配联络人。
- `POST /api/v1/oem/outsource-items/{id}/electrical-handoff` 接受 `{ handoff, expected, signerName }`，返回最新厂商视图行。OEM 工作单元内重查账号、公司、会话并锁定记录。内部账号返回 403，其他厂商的记录返回 404，已完成返回 400「已完成的记录不能操作」，当前值与 `expected` 不同返回 409/40903。门户提示并刷新清单，由厂商重新确认操作。
- 每次切换写入履历，字段 `electricalHandoff`，原值与新值为「否／是」，来源 `VENDOR` 并保存 OEM 账号及签名。同时写 `OUTSOURCE_ELECTRICAL_HANDOFF` 或 `OUTSOURCE_ELECTRICAL_HANDOFF_WITHDRAW` 审计。`ModifiedBy/ModifiedAt`、发送状态与上次发送快照保持原值。外发邮件正文、附件及后续发送快照排除该栏。
- 同一事务将 `ELECTRICAL_HANDOFF` 或 `ELECTRICAL_HANDOFF_WITHDRAW` 邮件入队，提交后由 `OutsourceMailWorker` 共用系统 SMTP 投递。TO 为「转迅得电控」模块中启用且有邮箱的内部账号（来源 `MODULE`），CC 为该厂商的外协邮箱（来源 `VENDOR`）。没有有效 TO 时仍保存变更，审计记录 `mailQueued=false`，邮件队列不新增记录。
- 主旨为「【转迅得电控】{厂商名} 工令 {工令}」或「【撤回转迅得电控】{厂商名} 工令 {工令}」。两种邮件正文沿用采购外发通知版式：向迅得电控同仁问好，说明厂商已签名转交或撤回，以横向单行清单列出工令、客户简称（或清单显示的全称）、机型、外发类型、外发厂商、签名人和操作时间（UTC+8），HTML 末尾显示系统落款，无附件。厂商签名提交后自动投递，无需采购确认。发送记录显示「{厂商名}（签名：xxx）」，失败邮件可按原内容重新发送。
- 迁移 `AddOutsourceElectricalHandoff` 增加记录栏位、外协邮件的 OEM 创建人和签名、内置栏位设定及默认抄送模块关系。回滚时旧版只保留适用「外发邮件」的默认名单，队列删除旧版无法处理的厂商发起邮件及其批次。

#### 按外发类型设定转交

- 在「ODM/OEM工令协作 → 外协管理设定 → 外发类型」的新增和编辑对话框可设定「允许转迅得电控」。既有类型迁移后默认开启，新建时省略 `allowElectricalHandoff` 或传 `null` 也默认开启。编辑时省略或传 `null` 保留原设定，开关变更写入审计。
- 工令按类型代码匹配启用的字典类型，并使用该类型的设定。空值、未知类型和已停用类型沿用默认允许。未完成的工令在类型允许或当前已转交时，`canElectricalHandoff` 为 `true`。
- 类型不允许且当前未转交时，厂商门户的对应栏位显示「—」。发起转交返回 HTTP 400「该外发类型不支持转迅得电控」。已转交的未完成工令仍可签名撤回。内部外协清单继续显示工令的实际转交状态。

### 权限简化（2026-11-19）

外协清单全厂可看，编辑由栏位设定决定，所以权限从六个减为三个：

- 去掉「查看外协清单」（`outsource:view`）：每个启用的内部账号都能进入模块、查看清单、导出和看变更履历。没有其他业务权限的内部账号，首页直接进入「外发工令」。读取接口（清单、栏位、变更履历、同步状态、设定页的下拉资料）只要求内部账号。
- 「汇入外协清单」（`outsource:import`）并入「管理外协清单」（`outsource:manage`，原名「编辑外协清单」）：汇入、删除、标记完成与重新开启、立即同步。编辑栏位不再先检查这个权限，只看栏位设定：「有管理外协清单权限的人员」可填的栏位需要它，「指定角色」「指定人员」的栏位不需要。编辑接口在当前账号一个能填的栏位都没有时返回 403。
- 「外协栏位设定」（`outsource:field_settings`）并入「外协清单设定」（`outsource:settings`，原名「外协清单设定维护」）。
- 发送记录（`GET /outsource/mails` 与附件下载）改为需要 `outsource:send`：记录里有厂商邮箱与邮件内容，不再对全厂开放。
- 设定页不能新增栏位，`POST /outsource/settings/fields` 移除。
- 迁移 `SimplifyOutsourcePermissions`：有 `outsource:import` 的角色补上 `outsource:manage`；有 `outsource:field_settings` 的角色补上 `outsource:settings`；只有 `outsource:view` 的角色不补任何权限（查看已不需要权限，避免把只读角色升级成能删除）。之后删除三个旧权限及其授权，并改名。Down 不恢复旧权限。全新安装时由 `BootstrapSeedCatalog` 写入三个权限（ID 220、221、232）。
- 前端：内部账号通过「ODM/OEM工令协作」菜单中的「外发工令」查看清单；「发送记录」只对有发送权限的人显示；编辑按钮与「批量修改」按当前账号能否填写任一栏位显示；「汇入」「删除」「标记完成」「重新开启」「立即同步」只对有管理权限的人显示。

### 原始交期改取客户交期（2026-11-24）

- 需求方确认：原始交期（及汇入时的最新交期初值）对应 IPMS MES 监控的「客户交期」（`customerEndDate`），不是「原交期」（`deliveryDate`）。`MesMirrorIpmsClient` 改为读取 `customerEndDate`。
- 迁移 `CorrectOutsourceDueDatesFromCustomerDate`（只改数据）：按 IPMS 资料（MES 镜像）一次性更正现有记录——原始交期改为客户交期；最新交期仍等于旧原始交期（采购没改过）时一并改，采购改过的保留。镜像里没有该工令或客户交期为空、格式不对的记录不动。不写变更履历，也不改变发送状态。`Down` 不还原。

### 档案栏与传递单绑定工令（2026-11-24）

- 传递单新增可空的 `outsource_item_id`（外键，删除受限）。内部发送与厂商回传**都必须绑定一个未完成的工令**，一次一个；内部发送的厂商由工令的厂商决定，不再选「目标 ODM/OEMA 厂商」，两者不一致返回 400。厂商只能发送本公司的工令。`GET /oem/sendable-items` 按输入的工令号查询（`workOrderNo`，不区分大小写的包含匹配，完全匹配排最前，其余按工令号排序，最多 20 条，空输入返回空数组）。内部查询遇厂商无可接收账号时带 `disabledReason`，厂商查询只返回本公司的工令。旧传递单没有工令，不补绑，也不出现在档案栏。
- 外协清单新增内置栏位「档案」（`files`，默认排在工令之后，不置顶，对厂商可见，只读不可停用）。列表带 `fileCount`（可用文件数）与 `purgedFileCount`（已清除含待清除）。只统计 `RELEASED` 传递单；处理中的文件列出但不计数；校验失败、存储丢失的文件不列。栏位不进导出、导入模板、厂商邮件、已发送快照和变更标记。
- `GET /outsource/items/{id}/files`（内部，所有启用账号）与 `GET /oem/outsource-items/{id}/files`（厂商，只含本公司，他公司 404）返回 `{ canOpen, files[] }`。已清除的文件仍列出并标「已清除」。灯：有可用文件为绿色，否则灰色。
- 权限 `outsource:file_view`（外协档案）：仅内置管理员预设拥有，其他角色（含采购）由管理员在角色管理勾选。持有者可通过既有 `/oem/files/{id}/content|download-sessions` 读取绑定工令的已送出传递单文件（`TransferAccess` 的 `Reference` 访问），但**不因此看见该传递单**；没有权限者只能看到灯和文件名。这种访问**不算收件**：不写 `FirstRecipientDownloadAt`，不触发收件后清除；下载用途记 `REFERENCE`。
- 已有传递单绑定的工令不能删除（409，「工令 {no} 已有往来文件，不能删除」）。
- 迁移 `AddOutsourceTransferLink`（列、索引、外键、权限）与 `AddOutsourceFilesField`（栏位设定行）。当时的业务切换栏将外协清单排在 ODM/OEMA 之前。发送对话框用文本框手动输入工令号，工令号完全匹配且可发送时才可提交；传递单列表与详情显示工令。
