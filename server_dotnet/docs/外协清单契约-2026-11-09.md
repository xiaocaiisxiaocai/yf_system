# 外协清单契约

**状态**：业务规则已与需求方确认。第一至四阶段（设定维护、权限、IPMS 接口预留、汇入、清单、编辑、删除、导出、IPMS 同步、变更履历、发送邮件）已实现；真正的 IPMS 接口待定。IPMS 接口未定，相关条目标注「待 IPMS」。

来源：采购提供的《外协清单模板及系统功能要求简述.xlsx》，以及 2026-11-09 开发与需求方的逐条讨论。

## 定位与边界

- 外协清单是独立业务模块，用于登记工令级的外发台账，并按厂商分组发送外发邮件。
- 不与 Robot 仿真协作、ODM/OEMA 文件传递共用数据：
  - 厂商、厂商联络人、外发类型字典、类型与厂商对照、默认抄送名单都是本模块自有数据。
  - 即使同一家公司也出现在 ODM/OEMA 厂商目录中，两边的记录也互不关联、不同步。
- 厂商不登录系统，只通过邮件接收信息。
- 内部账号沿用全系统的 Identity。模块只新增自己的权限点。

## 权限

| 权限 | 能力 | 典型角色 |
|---|---|---|
| 查看 | 进入模块；查看总表和厂商分页；筛选、导出；查看发送记录 | 生管、采购、主管 |
| 汇入 | 上传清单 | 生管 |
| 编辑与发送 | 修改可编辑字段（单笔或批量）、删除、发送邮件、立即同步 | 采购 |
| 设定维护 | 维护厂商与联络人、外发类型字典、类型与厂商对照、默认抄送名单 | 采购 |

- 没有任何外协权限的账号看不到模块入口。
- 迁移时，把全部外协权限授予内置「系统管理员」角色，做法与其他模块一致。其他角色由系统管理员在角色管理中分配。
- 外协邮件记录和审计记录沿用现有的业务线范围规则显示。

## 数据与字段归属

一个工令只能有一笔记录（工令唯一）。

| 字段 | 来源 | 可修改者 |
|---|---|---|
| 工令 | 生管汇入 | 不可修改 |
| 外发日期 | 生管汇入 | 采购 |
| 外发厂商 | 生管汇入 | 采购（必须通过类型与厂商防呆） |
| 外发类型 | 生管汇入时填写（2026-11-13 起不再来自 IPMS） | 采购（必须通过类型与厂商防呆） |
| 客户、机型、机构课别、机构执行人、电控执行人、工令下发、BOM 时间、发图、数量、最新交期 | IPMS | 只读，由同步维护 |
| 原始交期 | 汇入时 IPMS 取得的交期 | 一经写入即锁定，之后不再改变 |
| 备注 | 汇入时为空 | 采购 |
| 状态：正常 / 暂停 / 取消 | 默认正常 | 采购（单笔或批量；三种状态之间可任意切换） |
| 发送状态：未发送 / 已发送 / 有变更待通知 | 系统维护 | 不可手动修改 |
| 已完成（结案） | IPMS 不提供结案状态，由采购手动标记（2026-11-13） | 采购（单笔或批量；可重新开启） |

## 外发类型字典与防呆

- 外发类型字典包含代码（如 `OEMA`）、中文名称（如「进料+制造」）、排序和启用状态。界面显示为「代码【中文】」。
- 类型与厂商对照为多对多，由采购在页面上维护，变更不需要修改代码。
- 外发类型和厂商只能停用，不能删除；类型与厂商对照可以随时调整，已有记录不受影响。
- 初始数据（附件二）：

  | 类型 | 可用厂商 |
  |---|---|
  | ODM-12345【含售前售后】 | 元控 |
  | ODM-2345【不含售前含售后】 | 元控 |
  | ODM-234【含设计】 | 鼎亚、力顺源、华昇智创、多普、合科 |
  | OEMA【进料+制造】 | 鼎亚、力顺源、华昇智创、多普 |

- 防呆规则（2026-11-13 起，外发类型由人工填写）：
  - 汇入时，生管在表格里填写外发类型：必填；接受 `OEMA` 或 `OEMA【进料+制造】`，不区分大小写；必须是启用的字典类型，且该厂商在该类型的可用厂商内。不符则该行报错，不能汇入。
  - 汇入之后，采购可以修改外发类型（单笔与批量）。只要类型或厂商有变化，就按修改后的组合重新校验；不符则拒绝保存。两者都没有变化时不校验（类型已被停用的记录仍可改备注、日期、状态）。
  - IPMS 同步不再读取或改写类型。类型被停用后，该行标记「类型不在字典中」并禁止发送，直到采购改成启用的类型。
  - 类型与厂商对照被调整后，已有记录不受影响，但对不上的行会被标记并禁止发送。

## 汇入

- 模板列：外发日期、工令、外发厂商、外发类型（外发类型由生管填写，不来自 IPMS）。
- 流程沿用现有 XLSX 汇入惯例：上传 → 预览 → 确认写入。
- 预览时按工令批量查询 IPMS，带出只读字段，并执行防呆校验。
- 行级错误（该行不汇入，其余行照常汇入）：
  - 工令已存在
  - IPMS 查无此工令
  - 厂商名不在本模块厂商目录中（不自动建立厂商）
  - 外发类型未填、不在字典中、或与厂商不符
- IPMS 无法连接：整批拒绝汇入，提示「IPMS 暂时无法连接，请稍后再试」。
- 汇入成功后：所有 IPMS 字段都已完整，原始交期已锁定，发送状态为「未发送」。

## IPMS 同步

- 每天定时同步一次，默认 03:30，可在设定中调整。采购可以对选中的记录或全部记录执行「立即同步」。
- 只同步未结案的记录，按批次查询。外部调用不放在用户请求或业务事务中执行。
- 比较基准是系统中的上一次数据：任一字段变动，该行就标记为「有变更待通知」。即使之后改回原值，也保持待通知，直到采购发送。
- 同步不会自动发信。
- 同步失败（IPMS 无法连接或超时）：保留现有数据，记录失败原因和时间，等下一次定时同步或手动「立即同步」再试。页面显示最后一次成功同步的时间。
- IPMS 不提供结案状态，由采购手动「标记完成」（见下文「手动标记已完成」）。
- 已完成后的行为：
  - 不再同步，也不产生变更通知。
  - 总表默认隐藏，勾选「显示已完成」后才显示。
  - 数据不删除，也不通知厂商。
- 待 IPMS：接口类型、认证方式、从 IIS 服务器能否访问、字段清单、结案状态、调用频率限制、测试环境。连接凭证放在外部配置文件中，不以明文存入数据库。
- 上线前要实测并记录每轮同步的耗时和处理笔数。

## 采购编辑与删除

- 可编辑字段：外发日期、外发厂商、外发类型、备注、状态。支持单笔编辑和批量修改。
- 编辑带版本检查：数据已被他人修改时，返回 `409 / 40903`「数据已被他人修改，请刷新后重试」，不覆盖。
- 修改已发送的记录后，该行转为「有变更待通知」。
- 编辑或批量修改保存后，弹出「是否批量发送邮件」，进入下文的发送流程。
- 只有采购（编辑与发送权限）可以删除：
  - 未发送的记录可以删除，删除后只保留审计记录。
  - 已发送的记录不能删除，只能把状态改为「取消」，再走变更通知。

## 发送

### 分组与收件人

- 采购可在总表或厂商分页中选取记录（包括全选）。服务端按每行的外发厂商分组，每个厂商一封信，每封信只包含该厂商自己的工令。
- 收件地址由服务端根据记录的厂商确定，前端只提交要发送的记录，不能指定收件地址。
- 每封信的组成：
  - To：该厂商的全部启用联络人。
  - CC：默认抄送名单，加上这封信的临时抄送。
  - 所有人在同一封信中一起发送，不拆成多封。
- 默认抄送名单：
  - 从内部账号中选择，由采购维护。
  - 每封信自动带上，发送时不能移除。
- 临时抄送：
  - 只加在单封信上，不会作用于整批信。
  - 内部人员从账号中选择；客户等外部人员直接填写邮箱。
  - 如果一封信含多个客户的工令，又填了外部地址，提醒一次后才能继续。
- 任何厂商都不得看到其他厂商的存在：邮件内容不含其他厂商的工令，抄送中也不含其他厂商的联络人。
- 不设置 Reply-To；回复由收件人自行处理，与系统无关。

### 二次确认

- 确认窗口逐封列出：厂商名、收件人、抄送、笔数，每封可以展开预览正文。采购确认后才入队。
- 预览后如果数据有变动，确认时要求重新预览。
- 同一次确认只发送一次，重复点击不会重复发送。

### 更换厂商

- 已发送的记录改了厂商后，下一次发送会同时产生两封信：
  - 给新厂商的外发通知。
  - 给原厂商的撤回通知：只说明该工令已取消外发给贵司，不透露新厂商。
- 两封信绑定在一起确认和入队，不能只发其中一封。

### 邮件内容

- 正文为专门生成的 HTML 表格，使用行内样式以兼容 Outlook 等客户端，另附纯文字版本。
- 正文表格列：工令、客户、机型、外发类型、数量、最新交期、状态、备注。
- Excel 附件包含全部字段，只含本封信的工令：
  - 文件名示例：`外发清单_鼎亚_20261109.xlsx`。
  - 附件在确认时生成并固定保存。失败重试使用同一份文件，发送记录中也可以下载。
- 撤回通知只有正文，不附 Excel。
- 颜色规则（系统画面、邮件正文、Excel 附件三处一致）：
  - 整行底色按状态：正常为白色，暂停为红色，取消为灰色。
  - 变动的单元格另加黄色底色，只显示新值，不显示旧值，不加「变更字段」列。
  - 标黄范围是与上次寄给该厂商的内容相比确实不同的单元格。

### 投递结果

- 邮件在后台排队发送，共用全系统的 SMTP 配置和重试机制。
- 每封信有多个收件人和抄送，需要扩充邮件队列以支持多收件人、CC 和附件。这项扩充只供本模块使用，不改变 Robot 和 ODM/OEMA 现有的邮件规则。
- 部分地址被拒收：跳过被拒的地址，照常发给其他人，标记为「部分送达」并列出被拒地址。
- 厂商收件人全部被拒：整封标记为失败。
- 模块内的发送记录显示每封信的状态：排队中、已寄出、部分送达、失败。失败的信可以重新发送。

## 页面

- 第一个分页是总表，后面每家厂商一个分页。分页依厂商目录自动生成，并显示笔数。
- 筛选条件：外发类型、状态、发送状态、外发日期范围、工令搜索、显示已完成。
- 导出：导出当前分页和筛选条件下的数据为 XLSX，颜色规则与邮件附件一致。

## 实现进度

### 第一阶段（2026-11-10）

- 迁移 `AddOutsourceSettings`：新增 `outsource_vendors`、`outsource_vendor_contacts`、`outsource_types`、`outsource_type_vendors`、`outsource_default_cc`，以及权限 `outsource`（菜单）与 `outsource:view` / `outsource:import` / `outsource:manage` / `outsource:settings`，授予内置系统管理员。
- 厂商联络邮箱必填、姓名可选，同一厂商内邮箱不可重复。默认抄送只接受启用、填写了邮箱的内部账号；删除账号时自动移出默认抄送。选人下拉一次列出全部启用的内部账号（不截断，本地搜索姓名、账号或邮箱），未填邮箱的显示为「未填写邮箱」且不可选。
- 设定接口位于 `/api/v1/outsource/settings/*`。读取需要任一外协权限（清单页面也要读取厂商、类型与默认抄送），写入需要 `outsource:settings`。
- IPMS 通过 `IIpmsClient` 接入（2026-11-13 起）：
  - `App:Ipms:Mode` 留空（或旧值 `MesMirror`）：读取从 IPMS 的 MES 模块抓取到本库的资料，连接在设定页设定（见下文「IPMS 连接设定」）；地址、账号、密码未设好时视为未设定。
  - `Fake`：开发与测试用，从 `App:Ipms:FakeDataPath` 指定的 JSON 文件读取工令；文件中 `"unavailable": true` 可模拟 IPMS 无法连接。
- 前端入口：业务切换栏的「外协清单」，路由 `/outsource`，第一阶段只有「设定」页（外协厂商、外发类型、默认抄送）。

### 第二阶段（2026-11-10）

- 迁移 `AddOutsourceItems`：新增 `outsource_items`，工令唯一。`type_code` 保存 IPMS 原值，读取时再与字典比对，因此修改字典或对照后，已有记录的防呆结果立即更新。
- 只有启用的外发类型参与比对；停用的类型视同不在字典中。IPMS 返回 `OEMA` 或 `OEMA【进料+制造】` 都按代码比对，不区分大小写。
- 汇入：`POST /outsource/items/import/preview` 预览，`POST /outsource/items/import` 确认。确认时重新查询 IPMS 与数据库，只写入可汇入的行；IPMS 无法连接时返回 `503 / 50301`，整批不汇入。IPMS 已显示结案的工令不汇入。每批最多 500 行。
- 清单：`GET /outsource/items`（分页与筛选）、`GET /outsource/items/summary`（总表与各厂商笔数）、`GET /outsource/items/export`（按当前筛选导出 XLSX，最多 10000 条）。
- 编辑：`PUT /outsource/items/{id}`、`PUT /outsource/items/batch`、`POST /outsource/items/batch-delete`，都需要 `outsource:manage` 并逐条带 `expectedUpdatedAt`，版本不一致返回 `409 / 40903`。已结案的记录不能修改。
- 导出由服务端生成（`SimpleXlsx`，不新增依赖），暂停整行红色、取消整行灰色；第四阶段的邮件附件沿用同一个生成器。

### 第三阶段（2026-11-10）

- 迁移 `AddOutsourceSyncState`：单行表 `outsource_sync_state`（`id=1`，首次使用时自动建立），保存每日同步时间（默认 `03:30`；数据库列默认值仍为 `02:00`（迁移不可改），实际写入由程序指定，2026-11-12 起默认 `03:30`，业务时间 UTC+8）、数据库时钟租约和最近一次结果。
- 后台服务 `OutsourceIpmsSyncService` 每分钟检查一次，到点后每个业务日只运行一次；`App:WorkerEnabled=false` 或 IPMS 未设定时不运行。
- 只同步未结案的记录，每批 200 条查询 IPMS。逐条以 `updated_at` 做比较后写入：同步期间采购刚改过的记录本轮跳过，下一轮再更新。
  - 有字段变化：更新 IPMS 字段并刷新 `updated_at`；已发送的记录转为「有变更待通知」，未发送的保持未发送。
  - 没有变化：只记录同步时间，不改变 `updated_at`。
  - IPMS 显示已结案：标记结案。IPMS 查无此工令：保留原资料，计入「IPMS 查无」。
  - 原始交期为空时以本次交期补上，之后不再改变。
- 立即同步：`POST /outsource/items/sync`（`outsource:manage`），可指定最多 500 条，不指定时同步全部未结案记录。另一轮正在进行时返回 `409`；IPMS 无法连接时记录失败原因并返回 `503`，资料不变。
- 状态：`GET /outsource/sync-status`（任一外协权限）；同步时间：`PUT /outsource/settings/sync-time`（`outsource:settings`）。每轮写一条 `OUTSOURCE_IPMS_SYNC` 审计。
- 前端：清单工具栏显示最近一次同步（失败时显示红色并可查看原因）和「立即同步」（勾选时只同步所选）；设定页新增「IPMS 同步」分页，可修改每日同步时间。

### 变更履历（2026-11-10）

- 迁移 `AddOutsourceItemChanges`：新增 `outsource_item_changes`，记录每条外协记录每个字段的变动：字段、原值、新值、来源（`EDIT` 编辑、`IPMS_SCHEDULED` 定时同步、`IPMS_MANUAL` 手动同步）、操作人和时间。汇入时的初始值不记录；删除未发送的记录时履历一起删除。
- 采购编辑记录外发日期、外发厂商、备注、状态；IPMS 同步记录全部 IPMS 字段（含最新交期）。
- `GET /outsource/items/{id}/changes`（`outsource:view`）按时间倒序返回履历。
- 前端：最新交期与原始交期不同时以橙色显示，悬停可看到从原始交期起的每次变化；每行的「变更履历」按钮打开完整履历。
- 第四阶段标示「与上次发送相比有变动的单元格」时，可以沿用这份履历。

### 第四阶段：发送邮件（2026-11-10）

- 迁移 `AddOutsourceMails`：新增 `outsource_mail_batches`（确认请求，防止重复提交）、`outsource_mails`（每封邮件的主旨、HTML 与纯文字正文、附件、状态、尝试次数）、`outsource_mail_recipients`（每个收件人与抄送、来源和是否被拒收）、`outsource_mail_items`（邮件包含的工令）；`outsource_items` 新增 `notified_vendor_id`、`last_sent_snapshot`、`last_sent_at`。
- 预览 `POST /outsource/mails/preview`：按记录当前的厂商每家一封外发通知；记录上次寄给的厂商与当前不同时，另给原厂商一封撤回通知。收件人是厂商的全部启用联络邮箱，抄送是默认抄送中启用且有邮箱的内部账号，都由服务端决定。已完成、类型不在字典中、类型与厂商不符、厂商已停用或没有启用联络邮箱时，整批拒绝并列出原因。返回内容指纹。
- 确认 `POST /outsource/mails/send`：带上预览的指纹和一次性的 `requestKey`。服务端锁定记录后重算，指纹不同返回 `409 / 40903`，前端自动重新预览。相同 `requestKey` 重复提交只返回第一次的结果。另加抄送按每封邮件提交（内部账号或任意邮箱，每封最多 20 个）；一封含多个客户的工令又加外部邮箱时，前端再确认一次。
- 确认时冻结内容：主旨、HTML 正文（行内样式；暂停红、取消灰，与上次寄出相比有变动的格子标黄，只显示新值）、纯文字正文，以及外发通知的 Excel 附件（全部字段，只含本封工令）。撤回通知不写新厂商，不附 Excel。外发通知中的记录转为「已发送」，并记下厂商与当时的字段快照，作为下次标黄的依据。
- 投递：`OutsourceMailWorker` 使用系统的 SMTP 设定（与 Robot、ODM/OEMA 共用设定，但使用自己的队列），每封邮件一次发给全部收件人与抄送，不设定 Reply-To。
  - 有地址被拒收：其余照常送达，状态「部分送达」，被拒地址标记在记录上。
  - 厂商收件地址全部被拒收，或邮件本身被拒：状态「失败」。
  - 连接、加密、登录、超时：保持排队，按 1、2、4…最长 30 分钟后重试，共 8 次后转为失败。SMTP 未设定时保持排队并提示。
  - `App:WorkerEnabled=false` 时不投递。
- 记录：`GET /outsource/mails`（`outsource:view`）；失败的邮件可以 `POST /outsource/mails/{id}/retry` 原样重新发送（`outsource:manage`）；`GET /outsource/mails/{id}/attachment` 下载当时寄出的附件。
- 前端：清单勾选后「发送邮件」；编辑或批量修改保存后询问是否发送；确认视窗逐封列出收件人、默认抄送（不可移除）、另加抄送和正文预览。新增「发送记录」页面，排队中的邮件每 5 秒刷新一次。

### MES 数据镜像（2026-11-12）

IPMS 的数据来源确定为「迅得二期」的 MES 监控页。外协清单不再实时查询，而是读取每天抓取到本库的镜像。设计见 `docs/superpowers/specs/2026-11-12-ipms-mes-mirror-design.md`。

- 迁移 `AddMesMirror`：`mes_work_orders`（镜像，工令为主键，保存客户、机型和 MES 返回的整行 JSON）、`mes_work_orders_staging`（抓取暂存）、`mes_mirror_state`（单行状态：租约、最近一次结果、笔数）。
- 配置（外部配置文件 `App:Ipms`，均为可选的默认值，设定页保存的值优先）：`MesBaseUrl`（含端口，如 `http://主机:6001`）、`MesAccount`、`MesPassword`、`MesSyncTime`（默认 `03:00`，业务时间 UTC+8）、`MesPageSize`（默认 100，最大 200）、`MesPageDelaySeconds`（默认 2）、`MesPageTimeoutSeconds`（默认 180）、`MesMinRatioPercent`（默认 50）。
- 流程：每天 `MesSyncTime` 登入 MES，按页顺序抓取，先写暂存表；去重后的工令数等于 MES 的 `total`，且不低于上次成功笔数的 `MesMinRatioPercent`%，才在一个事务内整表替换镜像。每页失败重试 2 次，过期自动重新登入一次；任何失败都保留旧镜像并记录原因。每轮写一条 `OUTSOURCE_MES_MIRROR` 审计。
- `MesMirrorIpmsClient` 读镜像：客户、机型、数量（MES「数量」列，字段 `deviceNum`）、交期（`customerEndDate`，**待确认**）。外发类型不由 MES 提供，改为人工填写；其余 IPMS 字段暂为空。MES 只列出未出机的工令，因此镜像里没有结案信息。
- 外协每日同步默认时间改为 `03:30`，排在 03:00 的镜像之后。
- **手动抓取**（外协设定页 →「IPMS 同步」→「MES 数据镜像」，需要 `outsource:settings`）：
  - 可指定每页条数（1 到 200，默认取配置）；「抓取全部」不中断地抓完并通过校验时与定时抓取一样整表替换；运行中可「停止」；「抓取指定页」只抓一页。
  - 停止之后、或抓指定页之后，结果先留在暂存表，由人二次确认：「放弃」（镜像不变）或「合并已抓部分」（按工令更新或新增，不删除任何行；不改「最近成功时间」，更新笔数基准）。等待确认的结果占用抓取租约，60 分钟未处理视为放弃。
  - 同一时间只有一个抓取任务；路由 `GET /api/v1/outsource/mes-mirror/status`、`POST …/run`、`POST …/stop`、`POST …/confirm`；每次手动抓取与确认写审计 `OUTSOURCE_MES_MIRROR`（`trigger=MANUAL`）。
- **MES 地址可在页面更换**（迁移 `AddMesMirrorBaseUrl`，`mes_mirror_state.base_url`）：页面保存的地址优先，留空则用配置 `App:Ipms:MesBaseUrl`；`GET/PUT /api/v1/outsource/mes-mirror/settings`，保存写审计 `OUTSOURCE_MES_MIRROR_SETTINGS`（只记新旧地址）。地址必须是 http 或 https 的完整地址，不含账号密码、查询、片段；抓取运行或等待确认时不允许更改。（账号与密码自 2026-11-13 起也在页面设定，见下文。）
- **测试连接**（`POST /api/v1/outsource/mes-mirror/test`，可带待保存的地址）：用该地址全新登入并抓 1 条，不写任何数据、不保存地址、不替换正在使用的登入状态，只返回成功与否、总笔数、耗时和不含凭证的提示。token 由程序自动登入获取，无需手动取得。
- 安全提示：拥有 `outsource:settings` 权限的人能让服务器向任意 http 或 https 地址发送登入请求（带 IPMS 账号密码），请只授予可信的采购人员。
- 部署注意：MES 是明文 HTTP，专用账号只授予只读权限；抓取一轮预计十几分钟，应避开白天高峰。

### 外发类型改为人工填写（2026-11-13）

- 外发类型不再来自 IPMS：`IpmsWorkOrder` 不含类型，`FakeIpmsClient`、MES 镜像和每日同步都不读取或改写 `outsource_items.type_code`；无迁移。
- 汇入请求每行增加 `typeName`；规范代码写入 `type_code`；预览里 READY 行显示类型标签。
- 单笔 `PUT /outsource/items/{id}` 与批量 `PUT /outsource/items/batch` 增加可选的 `typeId`（空表示不改）；校验与错误文案见上；类型变化写变更履历（字段 `typeCode`，标签「外发类型」，来源 EDIT）和审计，已发送的记录转为「有变更待通知」。
- 前端：汇入模板增加「外发类型」列；编辑对话框增加外发类型，厂商下拉随所选类型过滤，原厂商不适用时清空并要求重新选择；批量对话框增加「不修改」的外发类型。记录的类型不在字典中时，编辑要先选择外发类型。

### IPMS 连接设定（2026-11-13）

这里的 IPMS 就是「迅得二期」IPMS 系统里的 MES 监控模块，不是另一套系统。界面统一称为 IPMS。

- 设定页「IPMS 同步」分三块：「IPMS 连接」（地址、账号、密码、每日抓取时间，保存、测试连接，显示已设定/未设定）、「抓取资料」（手动抓取全部或指定页、停止、资料笔数与最近结果）、「更新外协清单」（每日同步时间与最近结果）。
- 迁移 `AddIpmsConnectionSettings`：`mes_mirror_state` 增加 `account`、`protected_password`（AES-GCM 加密，密钥由 `App:JwtSecret` 派生，用途 `yf.ipms.mes.v1`，与 SMTP 授权码同一做法 `SecretBox`）、`sync_time`。升级或还原必须沿用原站点的 JWT 密钥，否则已存的 IPMS 密码无法解密（视为未设定，需重新输入）。
- `PUT /api/v1/outsource/mes-mirror/settings` 请求 `{ baseUrl, account, password, syncTime }`：地址或账号留空即清除页面值（改用配置值；清除账号同时清除已存密码）；`password` 为空表示不修改；有密码必须有账号；`syncTime` 为 `HH:mm`，留空不修改。回应 `{ baseUrl, configBaseUrl, saved, account, passwordSet, accountConfigured, syncTime }`，从不返回密码。地址、账号或密码变更时，抓取运行或等待确认中会被拒绝（409）。
- 审计 `OUTSOURCE_MES_MIRROR_SETTINGS` 记录地址、账号、每日抓取时间的新旧值，密码只记「已更改」或「已清除」。
- 测试连接 `POST …/test` 请求 `{ baseUrl, account, password }`：留空的栏位用当前生效的值；输入了其他账号时不会借用已存密码。
- 不再需要 `App:Ipms:Mode=MesMirror`：地址、账号、密码齐备后，每日抓取与外协同步自动生效；未齐备时定时任务跳过，外协同步状态显示未设定。从未成功抓取过资料时，外协清单查询 IPMS 会提示「尚未从 IPMS 抓取资料，请先在设定页抓取」，而不是把所有工令标为查无。
- 登入：地址必须是 IPMS 的接口地址（如 `http://183.238.37.108:6001`），不是网页地址（`6008` 是网页的 nginx，登入接口在那里回 404）。登入回应的 token 在 `data.token.token`（与 IPMS 网页一致，也接受 `data.token` 为字符串）；接口回 HTML 时提示检查地址，IPMS 拒绝登入时显示 IPMS 自己的原因（如「账号或密码错误」）。

### 定时任务的开始与停止（2026-11-13）

- 「抓取资料」与「更新外协清单」各有一个开关（定时抓取、定时同步），切换立即生效；停止后不再在每日时间自动执行，手动抓取与手动同步不受影响；正在执行的那一次会跑完。
- 迁移 `AddIpmsScheduleSwitches`：`mes_mirror_state.schedule_enabled`、`outsource_sync_state.schedule_enabled`（默认开启）。
- 路由：`PUT /api/v1/outsource/mes-mirror/schedule`、`PUT /api/v1/outsource/settings/sync-schedule`，请求 `{ enabled }`，需要 `outsource:settings`；设定与状态回应增加 `scheduleEnabled`。状态有变化时写审计 `OUTSOURCE_MES_MIRROR_SCHEDULE` / `OUTSOURCE_SYNC_SCHEDULE`。
- 确认框按 MES 回传的顺序列出抓到的工令（迁移 `AddMesStagingOrder`：`mes_work_orders_staging.seq` = (页码 - 1) × 每页条数 + 行序），最多显示 200 笔（一页的上限）。
- 后端启动时释放上一个进程留下的抓取租约并清空暂存（等待确认的结果只存在于进程内存，进程重启后无法再确认），避免新的抓取被挡 60 分钟。

### 手动标记已完成（2026-11-13）

- IPMS（MES 监控）只列未出机的工令，不提供结案状态，因此结案改由采购手动标记「已完成」。没有迁移，沿用 `outsource_items.closed_at`。
- `PUT /api/v1/outsource/items/completion`，请求 `{ items: [{ id, expectedUpdatedAt }], completed }`（`outsource:manage`，每次最多 500 条，版本不一致 `409 / 40903`）：`true` 标记已完成，`false` 重新开启；状态没变的记录跳过。
- 已完成的记录：总表默认隐藏（勾选「显示已完成」才显示，整行文字变淡并带「已完成」标签）；不再同步 IPMS；不能编辑、批量修改或发送（`409`「已完成的记录不能修改，请先重新开启」）；不通知厂商；发送状态保持原样。
- 重新开启后恢复同步、编辑与发送。每次变化写变更履历（字段 `completed`「完成状态」，未完成 ↔ 已完成，来源 EDIT）与审计 `OUTSOURCE_ITEM_COMPLETE` / `OUTSOURCE_ITEM_REOPEN`。
- 前端：勾选未完成的记录时工具栏多一个「标记完成」（需确认）；所选包含已完成的记录时只显示「重新开启」。
