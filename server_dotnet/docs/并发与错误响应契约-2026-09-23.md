# 并发与错误响应契约

## 事务门控与查询

项目创建、编辑、状态变更、复制等业务写事务先持有 `security.management_lock` 的共享锁（`LockBusinessAsync`），再锁定所需主项目/子项目等业务行。账号、角色、权限、组织、供应商、系统设置和字典管理使用排他锁（`LockManagementAsync`），等待正在进行的业务事务结束后修改授权状态。同一事务中的权限代码查询可复用共享锁期间的缓存；缓存不跨事务，也不用于排他管理事务。

项目详情和摘要的只读鉴权不获取排他项目行锁。`ProjectQueries.Rows` 用 LEFT JOIN 读取主项目、供应商、创建人、负责人、课别与字典名称；缺失可选关联不应使项目消失，课别仍限定 `Kind=SECTION`。最新提交版本及复制履历标志保留原有计算语义。调用者必须在执行查询前施加授权范围。

路由数据库连接由统一助手管理，DTO、状态码和 OpenAPI 保持既有契约。留言图片读取在流式响应前释放数据库连接，路径校验后至打开文件期间的文件/目录消失返回 404。

工作台的留言分页和摘要采用两次查询时，详情查询必须再次应用正常留言状态与项目访问范围；“仅未读”列表还必须再次应用当前回执过滤。并发删除、转交负责人或标记已读后，已失效的候选不再返回。分页总数仍取统计查询时刻的值，并发变化可能使当前页条数减少。

## 已读审计与通知

留言已读按当前用户去重，使用参数化批量 `INSERT IGNORE` 写入回执；单次请求最多 500 个 ID。每个有新增回执的项目写一条 `MESSAGE_READ`：`targetType=project`、`targetId=projectId`、详情 `{projectId,messageIds,count}`。旧审计记录仍可读取；前端新记录显示“标记 N 条留言为已读”。重复读取不写重复审计；`MESSAGE_READ` 不再新增 `project_activities` 动态，成功提交后仍通知该项目更新回执。

协作通知的已查看记录也采用参数化批量幂等写入，时间取数据库时钟；通知未读计数只覆盖最近 30 天。用户已于 2026-09-23 确认：未读统计只需近 30 天，审计日志也仅需保留 30 天；保持现有窗口和默认保留配置。超过窗口的留言不会因此删除，也不会补写实际阅读回执。工作台与通知面板明确提示统计范围。

## 错误响应

统一 JSON 为 `{code,message}`，未预料到的服务器异常另含 `requestId`。不得向客户端输出数据库异常详情或凭据。

| HTTP | code | 含义及处理 |
| --- | --- | --- |
| 409 | 40901 | 数据已存在、状态或版本冲突等业务冲突；刷新当前状态后处理 |
| 409 | 40902 | MySQL 1205 锁等待超时或 1213 死锁；本次事务失败，可刷新状态并重试，不自动把非幂等写入无限重放 |
| 429 | 42901 | 修改密码的原密码校验触发按用户限流；等待后再尝试 |
| 429 | 42902 | 登录、下载等请求触发服务端速率限制；等待后再尝试，前端显示服务端消息 |

字典 `DELETE /api/v1/project-dictionaries/{id}` 成功返回 HTTP 200 与空对象 `EmptyResponse`，不是 204。

## 刷新令牌约束

后端不设置轮换宽限期：刷新成功后，旧刷新令牌立即失效；重放旧令牌吊销整个会话族，包括刚轮换出的刷新令牌及该会话的访问令牌。多标签页竞争只在前端通过 Web Locks 或不支持 Web Locks 时的 localStorage 租约协调；不得以宽限期绕过安全契约。`scripts/test_identity_contracts.py` 保留真实重放回归。
