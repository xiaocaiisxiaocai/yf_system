# 部署单实例与内存状态约束

## 结论

当前版本的正确部署拓扑是一个业务环境只运行一个 Yf.Api 进程。IIS 专属应用池必须设置 `processModel.maxProcesses=1`，且同一数据库、存储和站点来源不得同时由第二个 IIS 站点、Windows 服务、容器或服务器副本承载。`maxProcesses=1` 只限制一个应用池的 worker 数量，不能阻止另一应用池或另一服务器启动副本，因此部署清单还必须核对全局副本数。

负载均衡粘性会话不构成多副本支持。它只能尽量把同一浏览器的后续请求送回原实例，不能把一个实例产生的项目事件转发给连接在另一实例上的客户端，也不能为后台任务、故障切换或应用池回收提供共享状态。

## 进程内状态及重启行为

以下状态当前只存在于单个 API 进程：

| 能力 | 进程内状态 | 回收、重启或切换实例后的结果 |
|---|---|---|
| 实时协作 | SignalR 连接注册表、待派发 Channel、事件合并/去重字典 | 现有连接断开；客户端重连并通过 REST/轮询收敛。重启前尚未派发的内存事件不会转移到新进程 |
| 原生下载 | 未兑换 download grant、已兑换的短时 download session 及其单次使用状态 | 全部立即失效；这是安全失败关闭，用户需从已认证页面重新申请下载 |
| 审计到项目动态通知 | HTTP 响应完成后在本进程安排的 realtime publish | 数据库内审计和项目动态仍随业务事务持久化；进程在响应完成回调前终止时，客户端依靠后续 REST/轮询读取持久化结果 |

下载 grant 的 URL 只携带公开 handle，真正的随机 secret 位于受保护 Cookie；服务端仅保存 secret 哈希。进程内状态消失不会放宽授权，只会让旧 grant 返回未授权。不得通过延长 Cookie、共享机器密钥或粘性会话来掩盖状态不共享。

`FILE_PREVIEW` 是审计事件，但在 `ProjectActivityService.KnownIgnoredAuditActions` 中被明确标记为非业务动态。预览和下载不会新增项目动态，也不会触发 activity 类型的实时通知；未知的 project/file/message 审计动作若既未映射也未显式忽略，会直接失败，避免新增或改名后静默丢失活动合同。

## IIS 安装和维护守卫

正式安装脚本创建应用池时显式设置 `processModel.maxProcesses=1`，随后从 IIS provider 回读 identity、profile 和 maxProcesses，再创建站点。共享维护前置检查读取现有应用池的有效 `ProcessModel.MaxProcesses`；Backup、Upgrade 和 Restore 在停止应用池或写入目录、数据库前拒绝任何不等于 1 的配置。

目标服务器可在管理员 PowerShell 中只读核对：

```powershell
Import-Module WebAdministration
$pool = Get-Item 'IIS:\AppPools\YfSystemDotNet'
[pscustomobject]@{
  Name = $pool.Name
  MaxProcesses = [int]$pool.processModel.maxProcesses
  IdentityType = $pool.processModel.identityType.ToString()
  LoadUserProfile = [bool]$pool.processModel.loadUserProfile
}
```

期望 `MaxProcesses=1`、`IdentityType=ApplicationPoolIdentity`、`LoadUserProfile=False`。还需从部署编排、服务清单和负载均衡目标组核对没有第二副本；单看应用池属性不能证明全局单实例。

应用池回收、服务器重启和版本升级都属于状态边界。维护窗口应停止专属应用池并等待旧 worker 退出，再切换程序目录；恢复服务后检查 `/health`、SignalR 重连，并重新发起一笔下载 grant 到 GET/Range 的完整流程。旧 grant 失效是预期行为，不应在维护后尝试恢复。

## 水平扩容前提

增加 IIS worker、应用副本或服务器前，至少需要同时完成：

1. 为 SignalR 配置受支持的共享 backplane，并验证跨实例连接定向发送、断线重连和身份撤销。
2. 将业务事件从本地 Channel 提升为跨实例可靠传播，定义持久化、去重、重放和失败恢复；仅加 SignalR backplane不能传递当前进程尚未发布的业务事件。
3. 将 download grant/session 放入共享、带 TTL 的原子存储，保留单次兑换、Range/重试兼容、跨认证 session 隔离、撤销和容量上限语义。
4. 验证项目授权在发送瞬间仍重新读取数据库，角色、负责人、供应商状态和会话撤销不会因副本缓存而失效。
5. 完成至少双实例下的连接分布、跨实例事件、下载签发/消费、滚动升级、实例故障和重放测试，再修改 `maxProcesses` 或副本数。

在这些条件全部落地并验收前，部署系统必须把多 worker 或多副本视为不受支持配置；sticky session 不能作为例外。
