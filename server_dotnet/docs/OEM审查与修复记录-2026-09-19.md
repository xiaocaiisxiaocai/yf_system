# OEM 审查与修复记录

审查基线：`46b7a6f`，覆盖近期 OEM 实现及 OfficeScan 接入。修复分支：`codex/fix-oem-review`。

## 已确认问题与修复

| 问题 | 修复 |
|---|---|
| 扫描探针创建失败被当成杀毒软件拦截，权限错误可导致返回 CLEAN | 普通 I/O、目录及权限失败不再建立自检成功证据；无法确认时继续隔离。等待后再次核对文件哈希 |
| 嵌套加密 ZIP 改成 `.bin`、伪装成目录或嵌入 PDF 标记后跳过检查 | 按真实结构识别嵌套压缩包，拒绝携带内容的目录条目，结构签名优先于内嵌 PDF 文本，共享递归预算 |
| RAR/7z 只检查部分文件头，没有落实完整的展开及递归限制 | 经用户授权引入 SharpCompress 0.50.4，真实解析并限制条目、层级、声明和实际展开量、压缩比；保留 RAR/7z 支持 |
| 正式区目标与原文件大小相同、内容不同仍可能发布并删除源文件 | Promotion 同时验证大小与 SHA-256；错误目标不替代源文件 |
| Promotion 耗尽重试后卡住，文件不能自动清理且占用配额 | 终态阻断并安排清理；失败移动记录的源、目标均纳入清理，全部成功才释放配额 |
| 下载完成记账与到期清理锁顺序相反，可能死锁并丢失收件证据 | 统一 transfer → file → session → lease 锁顺序 |
| 过期草稿在候选查询后被编辑，仍会被废弃 | 获锁后重新检查更新时间及当前 TTL |
| 审批健康检查只取前 500 条，后续实例可能长期不检查 | 按 transferId 分批遍历 |
| 审批恢复后仍发送排队中的“审批阻断”邮件 | 发送前复核阻断状态和发送人／异常处置管理员资格 |
| 用户删除检查遗漏 OEM 审批与历史关联 | 增加 OEM 传递、附件、模板、审批、下载关联保护 |
| 网页分三次保存审批模板，失败后可能部分生效 | 增加单事务 definition 接口，整体成功或整体回滚 |
| 账号管理员页面为空、部分角色默认进入无权页面、窄屏无导航 | 按实际权限加载厂商与选择首页，内部端和门户增加移动菜单 |
| 病毒库新鲜度配置可以保存，但运行时不生效 | 不支持的配置标明原因；禁止新启用，历史开启值保持隔离并提供关闭恢复路径 |
