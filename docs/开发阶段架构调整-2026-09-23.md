# 开发阶段架构调整

本次直接切换新协议，不保留旧客户端兼容入口。前后端及数据库必须一起升级；审计仍保留 30 天，刷新令牌重放仍立即吊销整个会话。

## 鉴权缓存

身份投影按数据库修订号、用户、会话缓存。每次请求仍用短连接读取数据库时间和 `security.identity_revision`，不使用会延迟撤销的 TTL 缓存。用户、供应商、刷新令牌表的九个触发器在修改事务中递增修订号；回滚不会使修订生效。启动检查修订行和触发器完整性，缺失即拒绝启动。

权限查询保持实时。HTTP 身份携带会话 ID，业务写事务在管理门禁内复核用户、供应商及会话。注销、改密、刷新重放撤销与业务写入采用一致锁序。缓存减少身份投影查询，不消除每次请求的数据库访问；多 API 实例部署仍不受支持。

## 上传协议

`POST /uploads/init` 接受 `projectId/fileName/fileSize/fileLastModified/fileFingerprint`，不再接受初始化 MD5。

快速指纹为 UTF-8 JSON 数组 `['yf-upload-fingerprint-v2', name, size, lastModified, firstSha256, lastSha256]` 的 SHA-256；首尾摘要分别覆盖 1 MiB，小文件允许重叠。它仅用于发现续传会话，不作为完整性凭证。

初始化和会话查询的 `uploadedChunks` 均为 `{index, sha256}[]`。PUT 分片必须携带 `X-Chunk-SHA256`，服务端实算请求体摘要；浏览器仅跳过与当前文件摘要一致的分片。摘要 sidecar 记录 `sha256 长度 最后写入时间`，与服务端实算时的分片文件状态绑定：长度和写入时间都一致时直接采用记录的摘要，不重读分片；旧格式或状态不一致（包括同长度篡改）时重新计算并比对。合并时整文件 MD5/SHA-256 仍做端到端校验。浏览器端逐片 SHA-256 在独立 Worker 中计算，HTTP 部署缺少 SubtleCrypto 时纯 JS 计算也不占用页面主线程。

完整 MD5 在 Worker 中增量计算，与分片上传并行；完成后调用 `POST /uploads/{sid}/md5`，随后 merge。未提交 MD5 的合并返回 409，组装文件与声明摘要不符返回错误。旧未完成会话由迁移赋予不可匹配的新指纹，继续按到期规则回收，不适配旧浏览器。

## 前端查询

Dashboard、用户管理、留言及回执改用 TanStack Query 5。查询键包含账号、会话代次和权限范围；请求消费 AbortSignal。退出或权限变化会取消请求并清空内存缓存，普通访问令牌轮换保留同会话缓存。写操作不自动重试，上传的磁盘与合并状态仍使用专用协议。

## 共享文件内容

业务文件记录独立，内容按 SHA-256 存入 `blobs/sha256/`，通过 `files.blob_id` 引用 `file_blobs`。复制项目创建独立文件记录并共享不可变内容，文件名、项目权限及审计不共享。

新上传、复制和回收使用同一 SHA 锁。保留期内的软删除文件仍持有引用；最后一个引用释放后先提交 `GC_PENDING`，再删盘并完成数据库回收，进程中断后可以继续。提交结果未知时保留物理内容。

EF 迁移负责结构；现存非 PURGED 文件由一次性维护命令 `--convert-file-blobs` 转换为内容引用，校验大小及 SHA-256。转换可重试，原物理文件默认保留；确认无误后可加 `--remove-legacy-content` 删除不再被引用的旧文件。普通启动不做转换（避免超过 IIS 启动时限），只校验：仍有未转换文件时拒绝启动并提示运行该命令。转换完成后业务流程不再支持未绑定 blob 的活动文件。首次转换需要临时磁盘空间和维护时间。

新内容首次入库时，调用方已算好暂存文件的 SHA-256，移入规范路径后不再在事务内重读；只有规范路径上原本就存在（无数据库记录的孤儿）内容时才重新校验哈希。

## 静态资源预压缩

`npm run build` 的 postbuild 生成有实际收益的 `.br/.gz` 文件和构建清单。ASP.NET Core 8 按 Accept-Encoding 协商，支持 q 值、HEAD、条件请求和 Vary；Range 使用原始文件。API、健康检查及业务文件不压缩。

发布脚本将清单放在包根，验证每个原文件、压缩文件及解压内容，再生成制品哈希。验包重复执行同一校验；缺失、过期或损坏伴随文件不能通过。IIS 发布目录必须整包替换，不能单独覆盖 JS 后沿用旧压缩文件。

## 升级顺序

停止旧后端，备份数据库与文件目录，依次运行当前版本的 `--migrate-database` 和 `--convert-file-blobs`，然后启动同版本后端，再使用当前前端。不要让旧服务与新服务同时访问升级中的数据库。触发器的账号权限与跨服务器恢复要求见 `server_dotnet/deploy/README.md`。
