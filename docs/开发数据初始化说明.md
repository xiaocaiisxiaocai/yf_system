# 开发数据初始化

新建空库使用现有 `--initialize-database` 命令。初始化后只创建工号 `admin` 和“系统管理员”角色，保留完整权限定义供管理员配置角色；不再预置项目管理员、内部成员和供应商人员角色。初始密码仍由 `YF_BOOTSTRAP_PASSWORD` 提供，首次登录必须改密。

已有数据库的开发数据清理使用独立命令，不会在正常启动或迁移时自动触发。该命令只允许数据库和网站均配置为本机回环地址。

在 `server_dotnet/Yf.Api` 目录先查看准确目标：

```powershell
dotnet .\bin\Debug\net10.0\Yf.Api.dll --inspect-development-data
```

停止当前项目后端后，将检查结果中的数据库名、存储根目录原样传入：

```powershell
dotnet .\bin\Debug\net10.0\Yf.Api.dll --reset-development-data --confirm-database <检查结果中的数据库名> --confirm-storage-root <检查结果中的绝对路径>
```

清理结果：

- 只保留原 admin 用户和系统管理员角色，恢复管理员全部权限。
- admin 原密码和首次改密标志不变；解除锁定，撤销所有已有会话，需重新登录。
- SMTP、系统参数、权限定义、数据库结构和迁移历史保留。
- 清空项目、供应商、其他用户、其他角色、组织、文件、上传会话、留言、回执、通知查看记录、邮件队列和审计记录。
- 删除配置存储根目录中的 `files`、`tmp` 两个业务目录，保留根目录中的其他内容；拒绝符号链接、目录联接及越界路径。

数据库写入采用事务，提交前校验 admin 密码和全部系统配置保持一致。磁盘清理在数据库提交后执行，如失败会明确报告“数据库已清理、文件清理未完成”，不会冒称全部成功；排除文件访问问题后可重跑相同命令。

供应商开户使用管理员手动配置的供应商适用角色。请先创建角色、分配相应项目与文件／留言权限，再在供应商账号表单中选择。清理命令不会自动重新生成其他角色。

自动化测试需要的历史三角色由测试夹具显式创建，且只允许写入 `yf_test_` 前缀的隔离数据库，不影响正常初始化结果。
