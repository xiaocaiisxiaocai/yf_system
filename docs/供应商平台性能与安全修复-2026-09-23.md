# 供应商平台性能与安全修复（2026-09-23）

本次按 26 项问题整改。审计保留期遵照确认维持 **30 天**；刷新令牌仍严格执行旧令牌重放即吊销整个会话，不增加宽限期。此前 Robot 料号及创建人负责制改动保留。

## 改动清单

| 编号 | 最终行为 |
|---|---|
| 1 | 单文件与 ZIP 使用同源原生浏览器下载，Axios 只申请凭证。一次性 HttpOnly 凭证 60 秒，兑换后固定下载会话 15 分钟，单文件支持 Range。每次请求重新检查登录会话、账号、权限及文件范围。 |
| 2 | 项目复制改为持久化后台任务。`POST /projects/{id}/copy` 接收 `name` 与 `idempotencyKey`，持久化排队后返回 `202 Accepted` 和扁平任务对象；前端通过主项目复制任务列表显示排队、复制进度、成功结果或失败原因。worker 在物理复制和哈希期间不长期占用业务事务，提交前重新鉴权并核对源快照。 |

| 4 | 会话记录固定创建时间和绝对截止时间，默认 30 天。轮换继承原截止时间，单个 refresh 到期时间受其约束。清理保留重放检测所需的旧令牌。 |

## 实施边界

- 项目复制仍生成独立物理文件，不使用硬链接或内容去重；执行方式已改为持久化后台任务。提交复制请求成功只表示任务已入队，最终结果以任务状态和结果字段为准。
- 下载管理器接管后的进度、暂停与续传由浏览器处理；下载会话过期后需要重新申请，已开始的响应流不会因 Cookie 到期被强行截断。流式 ZIP 不支持任意字节断点恢复。
- 前端行为测试已完成一次性迁移：30 个 CJS 文件对应的 299 个场景均进入 Vitest/RTL，旧 `react-test-renderer` 依赖和 legacy test script 已删除。
- 下载授权、实时连接和事件队列仍为进程内状态。不能开启 IIS Web Garden 或运行多个 API 副本；sticky session 不解决跨进程事件与授权状态。
- 自动保留期任务清理超过 30 天的审计记录；系统不提供任何手动删除审计的途径。
- refresh 和持久化认证状态不再接管旧客户端响应或旧 schema；升级需与当前前端、API 及契约快照一起发布。

## 数据库升级

新增 `20260923131700_HardenSessionsAndQueryIndexes`，位于 Robot 目录迁移之后。旧会话按同一用户与 session_id 的最早现存令牌创建时间回填，截止时间为该时间加 30 天，并截短超出截止时间的 refresh 到期时间；不会以迁移时间续期。不会删除项目、用户、文件或供应商数据。

随后新增第 9 个 EF 迁移 `20260923141854_AddProjectCopyJobs`。它创建 `project_copy_jobs` 和单行 `project_copy_worker_state`：任务保存请求人、源项目、主项目、幂等键、目标名称、状态、执行 token、worker epoch、文件/字节进度、失败摘要、结果项目和时间；`(requested_by,idempotency_key)` 唯一索引阻止同一用户重复创建同一任务，队列及主项目列表索引支持 worker 领取和前端查询，epoch 用于隔离失去租约的旧 worker。

已有部署需按顺序执行这两个迁移后再启用新版本。`ProjectCopyWorker` 默认开启；进程重启后会把遗留的 `running` 任务恢复为 `pending`，清理其旧 execution token 对应的暂存目录，再由新 token 重新执行。当前代码、数据库迁移、前端和契约快照应一起发布，不能只替换其中一部分。
