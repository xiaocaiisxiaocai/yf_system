# 留言图片

在项目“留言”输入区选择“添加图片”，或截图后在输入框按 Ctrl+V。可以只发图片，也可以配合文字发送；发送前可移除附件。发送失败保留当前草稿，切换项目或账号清空草稿。

支持 PNG、JPEG、GIF、WebP、BMP。每条留言最多 9 张，图片合计最多 50 MiB；单张还受系统参数 `upload.max_file_size` 限制。图片作为留言附件保存，不进入项目文件列表。

发送后显示缩略图，点击打开大图，可缩放、重置和拖动查看；预览不提供下载按钮。留言更新继续通过现有 SignalR 通知同步，历史留言与已读回执保持原有行为。

## 接口与权限

- `POST /api/v1/projects/{id}/messages`：纯文字继续接受 JSON `{content}`；图文使用 multipart/form-data，字段 `content` 和重复的 `images`。创建响应和列表响应增加 `images` 数组，元素为 `{id,name,sizeBytes,mimeType}`。
- `GET /api/v1/messages/{messageId}/images/{imageId}`：使用当前登录认证读取图片，校验项目访问范围和留言状态。图片不使用公开静态 URL，也不要求单独的项目文件预览权限。
- 发送仍要求 `message:create` 和可留言的项目状态。服务器校验图片类型、文件签名及大小。删除留言后，其图片接口不再可访问。

本次不新增依赖：界面沿用 React、Arco Design，图片复用现有图片预览组件，服务端沿用 ASP.NET Core 与私有存储。

## 界面验证（2026-09-15）

前端构建及 236 项自动测试通过。Chrome 138 在 1440×900 和 390×844 两种视口下完成 26 项交互检查，覆盖文件选择、剪贴板图片、普通文本粘贴、发送失败重试、模拟 SignalR 通知更新、刷新回载和大图预览。浏览器接口使用隔离夹具，无真实留言写入；该结果不替代服务端的真实数据库验证。

后端在临时 MySQL 数据库完成 13 项真实 HTTP 检查，包括超过 2 MiB 的图片、图文／纯图片保存与读取、访问权限、签名校验、失败清理、系统大小上限和删除后的访问拒绝。另有 42 项留言图片及数据库结构测试通过，无跳过。迁移 v4 → v5 可重复执行，并保留系统设置。

当前开发环境已执行 v5 迁移并启用新后端。升级前后项目、留言、用户、角色、文件和系统参数记录数不变。部署其他环境时，先按服务端 README 执行 `--migrate-database`，再启动新版；备份应包含私有存储下的 `message-images` 目录。
