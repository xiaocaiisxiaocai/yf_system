# 前后端全量检查与修复报告

检查日期：2026-09-16。范围为当前 `web` React 前端、`server_dotnet` ASP.NET Core 后端及其测试；使用现有主项目／子项目和负责人访问模型。独立检查后由主代理审阅差异并集成验证。

## 已修复的问题

| 问题 | 修复与验证重点 |
| --- | --- |
| 协作摘要或实时连接失败会挡住项目、文件的正常加载 | 核心 HTTP 加载与实时连接状态分开；断同步、失败恢复回归覆盖项目列表、主项目、子项目和文件列表。 |
| 主项目路由切换可能保留上个项目的弹窗、资料和操作目标 | 按路由项目 ID 重建局部状态，防止旧状态进入新项目。 |
| 主项目已删除或失去访问权限后仍展示缓存详情 | 将 403／404 与临时网络失败区分：前者清空详情及编辑／复制状态，后者保留已有数据供重试。 |
| 快速连续操作可能在 React 禁用按钮前重复提交 | 改密、用户、角色、组织、供应商和系统设置增加同步提交锁；校验失败和请求失败均释放锁。 |
| 负责人选项含未设置课别或组织链失效的用户 | 候选查询和保存接口共用有效课别条件；有效权限、用户状态、课别及上级组织均需满足要求。 |
| 组织停用或移动可使在办主项目负责人失去有效课别 | 对本次操作实际导致失效的负责人阻断，要求先转交；正常改名、排序及有效课别间移动保持可用。启用内部用户同时检查组织祖先。 |
| 已完成子项目复制后可能继承旧公共资料 | 新副本继承主项目当前供应商、负责人、课别、工令号等资料；复制源说明和文件，保留引用履历，不复制留言及验收状态。复制提交前同时校验主项目、子项目和文件快照。 |
| 负责人转交的更新时间可能未被更新 | 修复 MySQL UPDATE 赋值顺序影响，保留已验收子项目的负责人同步及更新时间。 |
| 复制提交成功后推送异常可能被当作复制失败 | 隔离提交后的推送异常，避免引导用户重复复制。 |
| 日期未变化也产生审计“变更” | 主项目预计完成日期统一为日期字符串，再比较前后值。 |
| 文件目录校验顺序可先在存储根外创建目录 | 创建前逐级解析并校验目录／链接，覆盖分片、合并、临时 ZIP 和待提交标记路径。 |
| 批量下载可能向越权账号泄露不可用文件名 | 先检查项目可见范围，再返回文件状态。 |
| 刷新令牌到期判断依赖应用机与数据库时钟差 | 在数据库中使用同一 UTC 时钟判断过期。 |
| 未知审计分类返回全部记录，容易误解筛选结果 | 无效分类返回明确的 400 响应。 |
| 邮件取消状态遗漏，未知动作可能显示“已发送” | 增加取消计数、失效事件和原因展示；未知状态保持中性说明。 |
| 主项目资料区长标签紧贴内容 | 主子项目共用标签右侧间距及长内容换行规则。 |

## 测试本身的修复

- 更新仍按旧成员机制、旧组织操作入口、旧通知名称和旧留言目标过滤方式编写的脚本。
- 所有负责人测试使用真实有效课别，并保留“所有候选都应有效”的断言。
- 故障注入持续到明确验证错误界面，再解除并验证真实重试，避免一次性错误被实时刷新覆盖。
- 文件选择的键盘验证针对实际可聚焦按钮，而不是隐藏的原生文件输入。
- 字典、预览和权限专项各自建立独立登录会话，避免跨脚本复用已轮换的刷新令牌相互撤销会话。
- 待验收冻结测试使用服务端确认仍待验收的项目，避免上一操作已将同一夹具驳回。
- 同供应商第二账号真实验证已读隔离，替换无法证明账号隔离的同用户断言。
- 隔离测试不继承外部 App 配置；清理失败正确返回失败。浏览器检查源文件和运行产物哈希，运行中改源不能获得最终通过结果。

## 验收边界

本轮使用本机 Chrome、隔离 MySQL 临时库和独立测试服务，不使用业务数据库进行破坏性测试，不发送真实外部邮件。所有本轮测试进程、临时库和私有登录状态由测试入口清理。

页面模拟窄屏不等同于实体手机及所有浏览器兼容性；文档预览样本通过不代表任意 Office 文件都能与桌面 Office 完全一致。真实 SMTP 投递、目标服务器 IIS 部署、生产容量／压力测试不在本轮本地验收结论内。静态检查仍保留已知第三方源码和 React 建议级告警，不将其描述成零告警。

未触碰 `yf_server` 下用户已有的部署与备份修改。交付保留在当前功能分支，本次未执行合并 main 或远端发布。
