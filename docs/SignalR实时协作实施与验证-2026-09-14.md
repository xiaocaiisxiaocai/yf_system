# SignalR 实时协作实施与验证

## 已实现

新留言、留言删除、已读回执，以及文件和项目活动改为 SignalR 变化通知驱动更新。Hub 地址为 `/api/v1/collaboration/live`，事件 `ProjectChanged` 仅包含 `projectId` 和 `kind`（`messages`、`receipts`、`activity`）。前端收到通知后通过既有授权接口读取最新内容，保留草稿、历史游标和阅读位置。

使用 ASP.NET Core 自带 SignalR 服务端及开源官方客户端 `@microsoft/signalr 10.0.11`。Vite 代理已开启 WebSocket；正式环境保持前后端同源，IIS 配置见部署说明。

- 消息事务提交后只将通知入内存队列；后台派发独立获取连接，避免业务请求持有数据库连接时等待第二个连接。文件/项目活动在成功 HTTP 响应完成后入队。
- 发送前重新校验连接的会话、账号/供应商状态和当前项目访问权限。通知不含正文、用户名或文件名；项目外用户收不到项目提示。
- JWT query token 仅在精确 Hub 路径使用，普通 API 和 negotiate 不接受 query token。WebSocket Origin 限制为配置的前端来源。关闭详细 Hub 错误及客户端连接日志；访问令牌到期时主动关闭连接。
- 首次连接失败持续退避重试，自动重连耗尽后也会继续尝试。首连及重连完成后补查数据；注销或账号切换清理旧连接、事件和定时器。
- 实时连接可用时取消固定 5 秒回执轮询。概览保留 60 秒低频校准；断线时恢复 5 秒轮询兜底。正常更新不等待该轮询周期。
- 当前实现适用于本项目的单实例后端，不引入新数据库表，也未修改用户角色或业务权限。

## 验证结果

| 验证 | 结果 |
|---|---|
| 后端自动测试 | 173/173，无跳过；包含连接池容量为 1 的后台派发验证 |
| 前端自动测试 | 172/172；包含事件路由、重连补查、会话隔离与轮询降级 |
| .NET / TypeScript / Vite 构建 | 通过，.NET 0 警告/0 错误 |
| 真实 SignalR 集成 | 15/15：鉴权、Origin、三类事件、项目隔离、注销连接失效等 |
| 完整 SPA 双浏览器 | 新留言约 408ms 显示，已读回执约 463ms 更新；观察到真实 ProjectChanged 帧 |
| 断线补查 | 主动关闭原生 WebSocket 后重连，接收方完成第二次真实握手，补齐断线留言且保留草稿 |
| 当前开发运行 | API health 正常、前端 200；Vite WebSocket 代理的未授权升级请求返回 401 |
| IIS 脚本 | PowerShell 语法检查通过；新站点日志默认去掉 URI Query，未在本机执行 IIS 安装 |

耗时来自本机隔离环境的一次最终运行，不是对其他网络环境的时延承诺。集成测试创建专用数据库和账号，浏览器使用真实 API 登录、真实 WebSocket 和实际编译后的页面，不使用模拟业务接口。未在真实业务项目发送测试留言。临时库已清理，专用测试 MySQL 已关闭；当前开发项目已启动新版后端。
