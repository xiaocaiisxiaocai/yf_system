# 协作感知优化与验证（2026-09-13）

本轮已实现全局通知、在线更新、完整未读入口、内容精确定位及工作台待办优先。保留公司／供应商的现有确认流程，没有引入个人任务分派、领取或截止时间。

## 用户可见变化

| 场景 | 当前行为 |
|---|---|
| 在任意业务页面收到他人操作 | 顶栏铃铛显示未查看数量，通知抽屉支持未查看／全部、分页和本页标记 |
| 新留言、新文件、开始／提交／确认／驳回／撤回／终止等流程变化 | 来自已持久化的项目动态，按当前账号的项目权限范围查询；本人操作不产生自己的未查看通知 |
| 工作台 | 待我方确认和项目留言放在统计前，默认完整未读分页，可切换全部；统计入口可点击 |
| 项目列表与详情 | 在线检查后自动更新状态、文件列表和未读摘要；待确认标签直接显示公司／供应商 |
| 正在阅读留言或动态 | 显示更新提示，由用户点击获取；不会因后台变化替换正在读的历史或清除草稿 |
| 从通知、工作台、邮件进入 | 链接包含项目和文件／留言目标；目标留言可直接输入，返回全部留言仍保留草稿 |
| 网络中断与恢复 | 通知入口显示中断状态及重试；恢复后重新取页面数据，即使服务端 revision 没有变化；失败时不伪装成空列表 |
| 手机使用 | 通知抽屉适配 390×600，键盘关闭后焦点回到铃铛，小屏顶栏保留标志并缩减文字避免溢出 |

“通知已查看”“留言已读”“项目确认完成”分别保存和处理。标记通知不会直接标记留言或完成项目；留言进入实际可视区域后才按原有机制上报已读。通知不是个人任务列表。

## 更新机制与边界

复用当前 HTTP、认证和项目动态体系，未新增依赖或外部服务。在线、页面可见时每 5 秒检查一次协作概览；请求单飞，10 秒超时，失败退避上限 60 秒。切回页面／网络恢复时立即唤醒；隐藏页面暂停，退出或切换账号取消请求并清空旧账号通知状态。通知列表阅读期间保持稳定，有新增内容时提供刷新入口。

这是周期检查及恢复机制，不是毫秒级实时推送，也不是离线即时送达保证。本轮浏览器用例验证另一参与人发言后，接收者不刷新页面，在 12 秒验收窗口内出现通知。

站内通知独立于 SMTP 的邮件开关。邮件仍沿用现有队列和重试，链接已精确到目标；本轮没有实际发送外部邮件。查看范围按当前权限计算，撤权后不能继续通过通知接口读取内容，删除留言后通知不返回原文。升级后已有的可见历史事件也会作为未查看事项出现，不以任意时间截断历史。

## 数据与接口

新增 `.NET schema version 2` 的 `collaboration_reads` 表，记录用户与项目动态的查看关系；v1 迁移名称和校验和保持不变。支持空库初始化、v1→v2、建表后迁移记录未写入的中断续跑。结构不符、历史被改写或声明已应用却缺表时拒绝启动／迁移。

新增接口：

- `GET /api/v1/collaboration/summary`：未查看数、最新活动 ID、范围内版本指纹。
- `GET /api/v1/collaboration/notifications`：按未查看／全部分页。
- `POST /api/v1/collaboration/reads`：幂等记录指定通知已查看，批次中混入越权 ID 时整批拒绝。
- `GET /api/v1/dashboard/messages`：服务端未读筛选和完整分页。
- 项目摘要新增 `activityRevision`，避免把其他项目的变化显示为当前项目的新动态。

当前开发库已获用户明确同意后，用项目自带 `--migrate-database` 命令成功升级；随后启动新版后端。前端 5173 返回 200，后端 8080 健康为 `ok/db up`，当前已登录工作台显示通知按钮、待确认和未读区域。组合核对／启动命令曾被自动审批拦截，最终使用独立迁移 CLI 与受控执行会话完成；没有声称执行过被拦截命令中的数据全表快照核对。

部署其他环境时仍须先执行显式迁移，再启动新版。旧版程序不能直接按 v1 校验规则启动 v2 数据库；本次未实施逆迁移。原有 8 个 Rust 范围外文件保持原哈希，未包含在本轮修改中。
