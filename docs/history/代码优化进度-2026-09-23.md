## 一、已完成

### 高优先级
1. **读接口不再加排他行锁**：`ProjectService.DetailAsync` / `SummaryAsync` 调 `RequireViewForValidatedActorAsync` 时，`forUpdate` 从 `true` 改为 `false`。
2. **项目类写操作改用共享门控锁**：`LockManagementAsync`（X 锁）改成 `LockBusinessAsync`（S 锁），涉及 `ProjectGroupService`（4 处）、`ProjectService`（编辑、删除）、`ProjectService.Workflow`（SetStatus）、`ProjectCopyService`。
   - `ProjectDictionaryService` 和 Admin/System 模块仍用 X 锁。
   - `AccessService.LockManagementAsync` 上补了注释，说明 X 锁的适用范围。
3. **留言已读去掉写放大**（`MessageService.MarkReadAsync`）：
   - 已读回执先过滤掉已读的，再用一条参数化的批量 `INSERT IGNORE` 写入。
   - 审计改为每个项目、每次请求只写一条：`MESSAGE_READ`，target 为 `project`，detail 为 `{ projectId, messageIds, count }`。
   - `ProjectActivityService` 不再把 `MESSAGE_READ` 转成项目动态（“查看留言回执”）。
   - 前端 `auditLogDetails.ts` 为新格式加了摘要：“标记 N 条留言为已读”。
   - `tests/MessageReceiptTests.cs` 已按新行为更新。
4. **事务内权限缓存**：`AccessService.LockBusinessAsync` 拿到 S 锁后，给这个事务注册一个权限缓存（`ConditionalWeakTable<MySqlTransaction, …>`）。
   - `PermissionCodesAsync` 和新增的 `AccessService.HasPermissionAsync` 走这个缓存；`ProjectAccessService.HasPermissionAsync` 两个重载都改为委托给它。
   - 走 X 锁的管理事务不缓存。
5. **协作通知“标记已读”**（`CollaborationService.MarkReadAsync`）：去掉逐条 `FOR UPDATE` 和项目行锁，改为批量 `INSERT IGNORE`，`read_at` 取 `UTC_TIMESTAMP(3)`。
