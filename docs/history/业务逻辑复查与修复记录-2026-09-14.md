# 业务逻辑复查与修复记录

## 范围与结论

本轮检查公司内部验收、项目范围与内容冻结、通知与待办、角色委派、供应商账号入口及最后管理员保护。先只读审查，再按用户“有问题直接修”的要求修复确认的问题。Rust 归档不在本轮范围内。

## 确认的问题与处理

| 问题 | 原行为与影响 | 修复 |
| --- | --- | --- |
| 旧页面误操作新申请 | 申请 A 撤回、修改材料并提交 B 后，旧页面确认／驳回／撤回仍返回 200，作用于 B | 以最新 SUBMIT 日志 ID 标识申请；请求必须携带所查看版本，锁内不一致返回 409，缺失返回 400。弹窗固定打开时的版本 |
| 无实际验收人仍可提交 | 所有内部用户均无验收权限时，项目仍进入待验收 | 提交前要求至少一名启用内部用户具备项目访问与验收权限；否则 409，状态、审计、通知不变 |
| 通知与可操作范围不一致 | 缺项目访问权限的人可能看到待办；可查看全部项目的非成员验收人没有邮件 | 统一按内部身份、启用角色、project:list、project:confirm 及创建人／成员／view_all 范围判断 |
| 旧邮件过期或迁移后漏通知 | 已完成／撤回申请的旧验收邮件仍可能发送；转交内部后无替代邮件 | 邮件关联申请版本与收件人；工作流取消旧待发项，worker 发送前复核；v4 重建当前有效申请的内部通知 |
| 账号管理隐含依赖供应商修改权限 | 有 supplier:account 仍无法通过供应商页面进入账号管理 | 列表／详情及入口接受 supplier:manage 或 supplier:account；供应商资料写入仍独立校验 supplier:manage |
| 用户角色候选超出委派范围 | 下拉显示无权授予的系统管理员／更高权限角色，保存才失败 | 角色候选按操作者委派上限过滤 |
| 角色管理展示不可执行操作 | 可编辑无权管理的角色，或勾选无法授予的权限 | 返回角色与权限能力；受保护角色只读，不可授予权限禁选，父子联动仅操作可调整项 |
| 已禁用次要管理员被误保护 | 只剩一名启用管理员时，处理另一个已禁用管理员仍被拒绝 | 仅移除启用管理员时参与最后管理员保护；历史引用与不能移除自己管理员角色的限制保留 |

关键缺陷通过真实隔离 HTTP 复现：旧 confirm/reject/withdraw 从错误接受 200 变为 409，申请、状态历史、审计和 outbox 均未改变；无验收人提交从 200 变为 409；删除无历史的已禁用次要管理员从误拒绝 400 变为 200，唯一启用管理员保留。复现脚本与前后结果在 `.runlogs/logic-review-20260914/`。

## 保持的业务规则

- 验收结论仅由公司内部作出；外部账号获得提交权限后可发起申请。
- 不额外增加指定审批层级或强制提交人与验收人不同。
- 待验收阶段文件和项目成员／资料受状态限制；留言作为沟通通道保留。已完成项目仍按原规则只读。
- 通知中心保留可见的历史协作动态；当前待办由项目状态与权限单独判断。
- 不覆盖用户手工角色配置，不重置账号、密码、SMTP 或系统参数。

## 部署与外部副作用

已有数据库需停写并停止邮件 worker、备份后执行 `dotnet Yf.Api.dll --migrate-database` 升级到 v4，再启动新版。前端也须更新，以发送申请版本。

运行中的 `SENDING` 邮件可能已进入 SMTP 外部发送，不会被工作流直接伪标为已取消；worker 保留发送结果记录。取消和过期判断针对尚可控制的排队／重试状态，不能撤回 SMTP 已接收的邮件。迁移只在停 worker 的前提下修复遗留队列，已发送历史不重发。
