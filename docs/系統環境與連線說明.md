# 系統環境與連線說明

**更新日期**：2026-10-13


## 1. 系統功能說明

本系統為「公司與供應商協作平台」，以 Web 方式提供公司內部團隊與外部供應商企業之間的專案資料交換、討論、交付與驗收，並保留完整操作紀錄。另含獨立的 OEM 檔案傳遞業務線。

| 模組 | 主要功能 |
| --- | --- |
| 身分驗證 | 工號＋密碼登入、JWT 存取權杖、刷新工作階段輪替、登入頻率限制、首次登入強制改密碼 |
| 系統管理 | 組織架構（事業部＞部門＞課別）、內部帳號、角色與權限點、供應商企業與供應商帳號管理 |
| 專案協作（核心） | 主專案／子專案管理；子專案流程：草稿 → 進行中 → 供應商提交驗收 → 公司確認／駁回／撤回 → 完成或終止；負責人轉交；Robot 料號與類型字典 |
| 檔案 | 分片上傳與續傳、校驗、下載、批次 ZIP 下載、線上預覽（PDF、Excel、PPTX、圖片）、影片串流（MP4/WebM/OGV）、軟刪除與回收 |
| 留言與通知 | 子專案留言（可附圖）、已讀回執、即時協作通知（SignalR）、未讀計數 |
| 系統功能 | 系統參數、稽核日誌、郵件通知規則與郵件佇列（背景 SMTP 寄送） |
| OEM 平台 | 公司 ↔ OEM 廠商雙向檔案傳遞、審批流程、檔案完整性／格式／壓縮檔結構檢查、刪除策略、OEM 廠商獨立入口（`/oem-portal`） |

權限原則：供應商只能看到所屬供應商企業的專案；內部一般使用者只能看到自己負責或建立的專案；所有寫入操作在伺服器端交易內重新檢查權限。

## 3. 軟體與程式架構

### 3.1 架構概述

採前後端分離開發、同站部署（B/S 架構）：前端 SPA 建置後放在後端 `wwwroot`，由同一個 IIS 站點提供頁面與 API，同源存取，不需反向代理。

```
瀏覽器（內部員工 / 供應商 / OEM 廠商）
        │ HTTP(S)  頁面 + REST API /api/v1 + SignalR /api/v1/collaboration/live
        ▼
IIS 站點（單一應用程式集區，maxProcesses=1）
  └─ ASP.NET Core 8 (Yf.Api, in-process)
       ├─ React SPA 靜態檔（wwwroot）
       ├─ REST API / SignalR 即時通知
       ├─ 背景工作：郵件寄送、檔案回收、專案複製、OEM 檔案檢查
       │
       ├──► MySQL（本機 127.0.0.1:3306）
       ├──► 本機私有磁碟：協作檔案 StorageRoot、OEM 檔案 OemStorageRoot、日誌目錄
       └──► SMTP 郵件伺服器（對外送信，TLS）
```

### 3.2 軟體元件

| 層級 | 技術 / 版本 |
| --- | --- |
| 前端 | React 18、TypeScript 6、Vite 8、Arco Design、@microsoft/signalr |
| 後端 | ASP.NET Core 8（Minimal API）、C# |
| ORM / 資料存取 | Entity Framework Core 9.0.20、Pomelo.EntityFrameworkCore.MySql 9.0.0、MySqlConnector 2.6.2 |
| 驗證與加密 | JWT（System.IdentityModel.Tokens.Jwt 8.23.0）、Argon2 密碼雜湊 |
| 郵件 | MailKit 4.18.0（SMTP over TLS） |
| 壓縮檔檢查 | SharpCompress 0.50.4 |
| 日誌 | Serilog（按日滾動 JSON 日誌，保留 31 份） |
| 資料庫 | MySQL 5.7+，結構由 EF Core Migrations 管理 |

### 3.3 部署特性

- **單一執行個體**：即時連線、下載授權等狀態保存在程序記憶體中，只能有一個 IIS 工作程序與一份部署副本。
- **檔案存放**：上傳檔案存放於網站目錄外的私有磁碟，以內容雜湊（SHA-256）命名，只能透過已驗證的 API 下載／預覽。
- **設定**：資料庫連線、JWT 金鑰等機敏設定放在網站目錄外的外部設定檔（`YF_CONFIG_PATH`），檔案權限僅限系統管理員與應用程式集區身分。
- **用戶端版 Windows 的限制**：Windows 11（含企業版）上的 IIS 同時處理的請求有上限（約 10 個），每位線上使用者的即時通知連線也會佔用名額，使用人數多時可能出現排隊或延遲。長期正式運作或使用人數增加時，建議改用 Windows Server。
- **MySQL 5.7 已停止維護**：MySQL 5.7 系列已於 2023-10 結束官方支援（5.7.44 為最後版本），不再有安全性更新；系統亦支援 MySQL 8，後續可規劃升級。
- **備份／升級／還原**：由 `deploy/maintain-iis.ps1` 執行離線備份（程式、設定、資料庫、協作檔案）。

## 4. 使用者

**使用範圍**：公司研發部、外部供應商及 OEM 合作夥伴。

| 使用者類型 | 所在位置 | 存取範圍與主要操作 |
| --- | --- | --- |
| 系統管理員 | 公司內部 | 組織、帳號、角色權限、供應商、系統參數、郵件設定、稽核日誌 |
| 專案管理員 | 公司內部 | 可檢視全部專案；專案維護、狀態管理、負責人轉交、驗收 |
| 內部負責人／一般員工 | 公司內部 | 自己負責或建立的專案：上傳、留言、狀態操作、驗收 |
| 供應商帳號 | 公司外部（供應商企業） | 所屬供應商企業的全部專案：檢視、上傳、下載、留言、提交驗收 |
| OEM 合作夥伴帳號 | 公司外部（OEM 合作夥伴） | 僅 OEM 入口 `/oem-portal`：接收公司檔案、回傳檔案；不能進入協作平台 |

帳號一律由公司管理員建立，不開放自行註冊。使用人數【待填】。

## 5. 連線方式

### 5.1 目前部署設定

依目前發布包設定，站點位址為 **`http://192.168.7.102:3340`**（公司內網 IP，HTTP，連接埠 **3340/TCP**）。此設定僅適合內網使用。

### 5.2 連線埠一覽

| 方向 | 來源 → 目的 | 協定 / 連接埠 | 用途 | 備註 |
| --- | --- | --- | --- | --- |
| 對內（入站） | 公司內網使用者 → Web 伺服器 | HTTP **3340/TCP**（目前） | 網頁、REST API、SignalR（WebSocket） | 目前設定值 |
| 對外（入站） | 外部供應商 / OEM 廠商 → Web 伺服器 | 建議 HTTPS **443/TCP** | 同上 | 若供應商需由公司外部連線，須設定網域名稱、HTTPS 憑證與防火牆／NAT【待確認是否開放對外】 |
| 本機 | Web 應用 → MySQL | **3306/TCP**，僅 127.0.0.1 | 資料庫 | 不對外開放；若資料庫改放其他主機，強制要求 TLS（`SslMode=VerifyFull`） |
| 出站 | Web 伺服器 → SMTP 伺服器 | **465/TCP**（SSL）或 **587/TCP**（STARTTLS） | 郵件通知 | 實際主機與連接埠在系統「系統參數」頁設定【待填】 |
| 管理 | 系統管理員 → 伺服器 | 遠端桌面 3389/TCP（建議僅內網） | 部署、備份、維護 | 依公司既有管理方式【待填】 |

開發環境使用的 8080（後端）與 5180（前端開發伺服器）僅綁定本機，不屬於正式環境連接埠。

### 5.3 安全說明

- 正式對外使用應改為 HTTPS（443），並將 `CookieSecure` 設為 `true`；目前 HTTP 設定僅在內網、且明確設定 `AllowInsecureCookies=true` 時才允許啟動。
- 前後端同源，SignalR 路徑 `/api/v1/collaboration/live`；IIS 需啟用 WebSocket，若有反向代理須允許 WebSocket Upgrade。
- IIS 日誌移除查詢字串欄位（`cs-uri-query`），避免記錄連線權杖。
- 登入有頻率限制（每 IP 每分鐘 60 次、每 IP＋帳號 10 次），refresh cookie 為 `SameSite=Strict`。
- 安裝腳本不會自動開放防火牆或修改 DNS，需由網管依上表設定。
